**开始之前，请先接受四件事**，后面会一直用到：

1. **先分清"在哪台机器上"。** 本文会在两个地方敲命令：**宿主机**（你的 Windows）和**虚拟机**（里面的 Linux）。它们的提示符长得完全不一样，认错了就会得到"命令不存在"这种看起来像故障的正常现象。有个粗暴但有效的判断法：**看提示符里有没有 `PS C:\`**——有就是 Windows，没有就是 Linux。
2. **虚拟机最大的好处是"坏了可以重来"。** 所以这一篇的基调比上一篇轻松：**放心大胆地搞坏它**。装崩了、配置改乱了、把 `/etc` 删了，都不影响你的 Windows，重装一遍或者回滚快照就行。
3. **报错依然要读最后几行、读第一处 error。** 这条从上一篇继承下来，在 Linux 里只会更重要——Linux 的报错通常比 Windows 的更直白，但也更长。
4. **"一模一样"依然很重要。** 命令里的空格、大小写、连字符（`-`）和下划线（`_`）、路径里的斜杠方向，都是有意义的。Linux **严格区分大小写**，`Rocky` 和 `rocky` 是两个不同的东西。

## 1. 照做就行：从零到一台能 SSH 的 Rocky Linux

这一章是纯操作。跟着做完，你会得到一台装在 Windows 里的 Rocky Linux 10：有图形界面、能上网、能装软件、能从 Windows 直接 SSH 登进去，而且**在动手之前先打好了快照**——搞坏了随时回到这一步。

**这一章预计要花 60～90 分钟。中途不要跳步，尤其是 1.1（确认虚拟化）、1.5（新建虚拟机）和 1.6（安装器里那几个选项）。**

### 1.1 开始前，先确认三件事

**第一件：CPU 虚拟化必须是"已启用"。** 这是唯一的硬门槛，也是新手最大的坑。

怎么看：按 **Ctrl + Shift + Esc** 打开任务管理器 → 选 **"性能"** 选项卡 → 左边点 **"CPU"** → 看右下角的信息块里有没有这一行：

```text
虚拟化:  已启用
```

- 看到 **已启用** → 可以继续。
- 看到 **已禁用** → 需要进 BIOS 把它打开，见下面。
- **看不到这一行** → 说明你的系统认为不需要显示它（部分 Windows 版本会隐藏），可以先去装 VMware，装完它会自己告诉你行不行。

**怎么打开虚拟化（BIOS 里）：**

1. 重启电脑，在刚出现品牌 logo 时**连按**进 BIOS 的键。常见的是 **Del**、**F2**、**F10**、**F12**、**Esc**；笔记本通常是 **F2** 或 **Fn + F2**，联想有些机型是侧面的 **Novo 小孔**。**不确定就一个一个试**，进不去不会坏。
2. 进去之后找这样的字眼（不同主板位置不同，一般在 **Advanced**、**CPU Configuration**、**Security**、**Overclocking** 里）：
   - Intel 平台：**Intel Virtualization Technology**、**Intel VT-x**、**Vanderpool**；
   - AMD 平台：**SVM Mode**、**AMD-V**、**Secure Virtual Machine**。
3. 把它从 **Disabled** 改成 **Enabled**，按 **F10** 保存退出（有的机器是 **Save & Exit**）。
4. 回到 Windows，再按上面的方法看一眼，应该变成"已启用"。

**第二件：内存和硬盘要够，下面是实话实说的账。**

| 宿主机内存 | 能怎么玩 | 建议分给虚拟机 |
| --- | --- | --- |
| 8 GB | 勉强，只能开一台，浏览器要少开几个标签 | 2～3 GB |
| 16 GB | **最舒服的入门配置**，能同时开两台 Linux | 每台 4 GB |
| 32 GB 及以上 | 随便造，可以玩三台以上组成的"小集群" | 每台 4～8 GB |

硬盘：**每台虚拟机先按 40 GB 规划**，加上快照和日志，实际占用会慢慢长到 50～60 GB。**再留 30 GB 余量给宿主机**（Windows 自己也要空间）。所以本文的建议是：**准备 120 GB 以上的空闲空间**，放在 NVMe 固态上最好。

> **一条非常重要的建议：虚拟机文件不要放在 OneDrive、坚果云、iCloud、百度网盘这类同步目录里。** 一个开着的虚拟机每秒都在改磁盘文件，同步客户端会疯狂上传，轻则卡到没法用，重则把虚拟磁盘文件同步坏掉。**放在 `D:\vm\` 这种本地目录里。**

**第三件：知道你的 Windows 有没有开"和 VMware 抢 CPU 虚拟化"的功能。**

Windows 上有些功能（**Hyper-V**、**WSL2**、**Windows 沙盒**、**内核隔离里的"内存完整性"**、企业电脑的 **Credential Guard**）会先一步把 CPU 虚拟化占住。这不代表 VMware 不能用——Workstation 15.5.5 以后会自动改用 Windows Hypervisor Platform 运行，**能跑，但性能差一截，而且不能用嵌套虚拟化**（第 9.5 节）。

本文的建议：**先什么都别关，直接往下做。** 如果后面虚拟机慢得离谱，或者报"VT-x 不可用"，再回来看[第 10.1 节](#101-虚拟化相关的报错)。

### 1.2 第 1 步：下载 VMware Workstation Pro（免费，但要注册账号）

**先给你三个结论，省得被网上的老文章误导：**

1. **VMware Workstation Pro 现在是免费的**：从 2024 年 11 月起，个人、教育、商业用途全部免费，**不需要序列号，也不需要破解**。
2. **但它必须从 Broadcom 官网下载，下载前要注册一个 Broadcom 账号。** 这一步劝退了不少人，本文会一步步走完。
3. **别去"XX软件园""XX下载站"下。** 那些地方的"VMware 安装包"经常被塞进捆绑软件或挖矿程序，而且你根本不知道里面是什么版本。

**下载步骤：**

1. 打开浏览器，访问 Broadcom 的支持门户并登录（没有账号就先注册）：

```text
support.broadcom.com
```

   注册时**邮箱、姓名、地址、国家都填真实的**。Broadcom 有一道"出口合规"筛查，填假信息（比如"张三，地址 123"）会被卡在审核里，下载按钮一直不给你。

2. 登录后，直接在地址栏里粘这个地址（这是"免费下载"入口）：

```text
https://support.broadcom.com/group/ecx/productdownloads?subfamily=VMware%20Workstation%20Pro&freeDownloads=true
```

   也可以自己点：**My Downloads → Free Software Downloads → VMware Workstation Pro**。

3. 页面里选 **版本**（比如 `26H1u1` 或更新的），勾选 **Terms and Conditions** 的同意框，然后下载 **Windows 版**的安装包。
4. 下载到的文件形如：

```text
VMware-workstation-full-26H1u1-25688693.exe
```

   **你要的就是这种 `VMware-workstation-full-...exe`。** 大约几百 MB。

**你应该看到：** 下载列表里出现一个几百 MB 的 `.exe`。（如果页面提示 `Account verification is pending`，说明审核还没过，等邮件；一般几分钟到一天。）

> **下载慢怎么办？** Broadcom 的服务器在国内时快时慢，可以用浏览器自带的下载器挂着，或者换个时间段。**不要用第三方"加速下载"网站**——它们给的文件不可信。

**顺带说清楚其他几个选择**（知道有这么回事就行，本文只用 VMware）：

| 方案 | 是什么 | 为什么本文不选它 |
| --- | --- | --- |
| **VMware Workstation Pro** | 商业公司的桌面虚拟机软件，现在免费 | ——本文的选择 |
| **VirtualBox** | Oracle 的免费开源虚拟机 | 免费好用，但对 Rocky 10 有个坑：**旧版本不给虚拟机暴露 AVX2 指令**，装 Rocky 10 会直接报 CPU 不支持（见 [10.2](#102-装系统阶段的报错)） |
| **Hyper-V** | Windows 专业版自带的虚拟化 | 家庭版没有；和 VMware 抢虚拟化；Linux 桌面体验一般 |
| **WSL2** | Windows 里的"半个 Linux" | 极好用，但它不是完整系统：systemd、内核、分区、网络都不完整，**学不到本文要讲的东西**。当补充可以，当主力不行 |

### 1.3 第 2 步：安装 VMware Workstation

1. **双击**刚下载的 `VMware-workstation-full-...exe`。
2. 如果 Windows 弹"是否允许此应用对你的设备进行更改"，点 **"是"**。
3. 安装向导里可能会问你要不要改安装位置：**默认的 `C:\Program Files (x86)\VMware\VMware Workstation\` 就行**（注意程序本身在 C 盘没关系，占地方的是虚拟机文件，那是在 D 盘）。
4. 中途会看到两个勾选框，**建议都勾上**：
   - **增强型键盘驱动程序（Enhanced Keyboard Driver）**：让虚拟机里的键盘行为更正常，建议装；
   - **将 VMware Workstation 控制台工具添加到系统 PATH**：以后可以在命令行里用 `vmrun`，要玩自动化才用得上，勾着也没坏处。
5. 如果提示"是否检查产品更新"，按你的习惯选。
6. 装完**重启一次电脑**（安装虚拟网卡驱动需要）。
7. 首次打开 VMware Workstation，会看到一个许可界面：**选"用于个人用途/免费版"那一项，然后点 FINISH/完成**。**它不会再问你要序列号**——如果要了，说明你下的是老版本，回 [1.2](#12-第-1-步下载-vmware-workstation-pro免费但要注册账号) 下新的。

**你应该看到：** 一个深灰/黑色的主窗口，左边是"库（Library）"，主区域是"主页（Home）"和"我的计算机（My Computer）"。**现在里面是空的，这是正常的。**

> **旧版本要不要卸载？** 如果你电脑上装过 VMware 的老版本（比如 15.x、16.x），**先卸载再装新版**，否则可能装不上或者虚拟网卡打结。卸载不会删掉你以前的虚拟机文件。
>
> **卸载重装也一样干净：** VMware 不留什么系统级残留，虚拟机文件全都在你自己指定的文件夹里，删文件夹就等于删虚拟机（第 3.5 节有个大坑，务必看）。

### 1.4 第 3 步：下载 Rocky Linux 的 ISO

**先做一个版本选择，这一步选错会直接装不上。**

Rocky Linux 是 RHEL（红帽企业 Linux）的"免费复刻版"，版本号和 RHEL 一一对应。写这篇文章时的两条主线是：

| 版本 | 内核 | 适合谁 | 注意 |
| --- | --- | --- | --- |
| **Rocky Linux 10.x**（最新 10.2） | 6.12 | **本文默认选它**；想学现在企业里在用的东西 | **要求 CPU 支持 x86-64-v3 指令集**，大致是 2013 年以后的 Intel Haswell / AMD Excavator 及更新的 CPU |
| **Rocky Linux 9.x**（最新 9.8） | 5.14 | CPU 比较老（2013 年以前），或者教程/公司环境还在用 9 | 依然在维护，到 2032 年 |

**怎么判断你的 CPU 够不够 Rocky 10？**

- **2015 年以后买的电脑，几乎都够**（Intel 第四代酷睿之后、AMD 锐龙全线）。
- 拿不准就查：按 **Ctrl + Shift + Esc** → 性能 → CPU，看右上角写的型号，搜一下它的发布时间。
- **实在不确定就选 Rocky 9.8**：它一样能学完本文所有内容，只是版本号旧一点。**"装不上"比"版本旧"麻烦得多。**

**下载步骤：**

1. 打开官方下载页：

```text
rockylinux.org/download
```

   页面会按架构和版本列出 ISO。**认准 `x86_64`（就是 64 位 Intel/AMD）。**

2. 你也可以直接去官方镜像站，那里能看到确切的文件名和大小：

```text
https://dl.rockylinux.org/pub/rocky/10.2/isos/x86_64/
```

   国内的话，用清华或中科大的镜像站会快很多，路径是一样的：

```text
https://mirrors.tuna.tsinghua.edu.cn/rocky/10.2/isos/x86_64/
https://mirrors.ustc.edu.cn/rocky/10.2/isos/x86_64/
```

3. **三种 ISO，选哪个？** 看这张表：

| 文件名（示例） | 大小 | 是什么 | 建议 |
| --- | --- | --- | --- |
| `Rocky-10.2-x86_64-boot.iso` | 约 1.0 GB | **联网安装盘**：只带安装器，软件包全部从网上下 | **本文推荐**：体积小、下载快，装的时候需要联网 |
| `Rocky-10.2-x86_64-minimal.iso` | 约 2.0 GB | 最小安装盘：带一套最小系统的包，不联网也能装完 | 网络不稳时选它 |
| `Rocky-10.2-x86_64-dvd1.iso` | 约 **10 GB** | 全量 DVD：几乎所有软件包都在里面 | 除非你要给没网的机器批量装，否则**没必要下这么大** |

   同目录里还有几个名字带 `-latest` 的文件，是"指向当前最新版"的别名，内容一样。

4. **一定要把校验文件一起下下来。** 同一个目录里有：

```text
CHECKSUM              ← 所有 ISO 的哈希都在这个文件里
Rocky-10.2-x86_64-boot.iso.CHECKSUM   ← 单个 ISO 的哈希
```

5. **校验（强烈建议做，只花一分钟）。** 在 Windows 上打开 PowerShell（**Win + X → 终端**），把路径换成你实际的下载位置：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\Rocky-10.2-x86_64-boot.iso" -Algorithm SHA256
```

   把输出的那串哈希，和 `CHECKSUM` 文件里对应那一行**逐字符对比**（对前 8 位和后 8 位也行，中间抄错的可能性很小）。

**你应该看到：** 两串完全一样的十六进制字符串。**不一样就重下**——ISO 有坏字节是"装到一半报错"的头号原因，而且报错信息完全看不出是这个原因。

> **顺手把 Debian 的 ISO 也下了吧**（第 6 章要用，现在下省得再折腾一次）：
>
> ```text
> https://www.debian.org/download
> ```
>
> 选 **`debian-13.7.0-amd64-netinst.iso`**（几百 MB，网络安装版），同目录把 `SHA256SUMS` 一起下来。Debian 的安装细节在[《Debian 13 从裸机到顺手》](/posts/debian-13-sudo-opencode-setup/)那篇里讲得很细，本文只讲"在虚拟机里装"和 Rocky 的差异。

### 1.5 第 4 步：新建虚拟机（向导每一屏）

现在正式开始搭机器。**在 VMware 里点"创建新的虚拟机"**，跟着下面走。

**这一节是全文最需要照抄的一节。** 向导里有些选项一旦定下来就不好改（尤其是固件类型和磁盘控制器），所以第一次别自由发挥。

**第 1 屏：配置类型** → 选 **"自定义（高级）"**。

> 为什么不选"典型"？"典型"会替你把固件、控制器、磁盘类型都决定掉，出错时你根本不知道是哪一项的锅。**自定义多花两分钟，换来的是"我知道我的虚拟机长什么样"。** 这和上一篇里"别用 Dev-C++ 把一切藏起来"是同一个道理。

**第 2 屏：硬件兼容性** → 保持默认（最新的那项，形如 `Workstation 26H1` 或更高）。

**第 3 屏：安装客户机操作系统** → 选 **"稍后安装操作系统（Install the operating system later）"**。

> **别在这一屏选 ISO 文件。** 如果你在这里选了 ISO，VMware 会进入"简易安装"模式，它猜着帮你填用户名密码、自动分区，你什么都学不到，还可能踩坑。**"稍后安装"= 把一台空机器攒好，再自己动手装。**

**第 4 屏：客户机操作系统** → 选 **Linux**，版本里选 **Rocky Linux 64 位**（没有的话选最接近的 `其他 Linux 5.x/6.x 内核 64 位`）。

> 这个选项不是用来"限制"你的，它决定 VMware 给虚拟机预配哪些虚拟硬件（默认网卡型号、磁盘控制器）。**选错了通常也能装，只是虚拟硬件保守一点。**

**第 5 屏：虚拟机名称和位置** → 名字填 `rocky10`，位置点"浏览"选到本地磁盘：

```text
D:\vm\rocky10\
```

**两条硬规矩**（和上一篇里"路径别带中文和空格"是同一条）：

- **路径里不要有中文、空格、特殊符号**；
- **不要放在 OneDrive / 坚果云等同步目录里**。

**第 6 屏：固件类型** → 选 **UEFI**，并把 **"安全引导（Secure Boot）"勾上**。

> 为什么用 UEFI 而不是 BIOS？因为 2015 年以后的电脑全是 UEFI，**你在虚拟机里学的东西要能迁移到真机**。Secure Boot 现代发行版都支持，勾上更接近真实环境。（2026 年 Secure Boot 有个证书换代的坑，见 [10.2](#102-装系统阶段的报错)。）

**第 7 屏：处理器** → 处理器数量 **1**，每个处理器的内核数量 **2**（合计 2 核）。宿主机核多的话给 4 核也行。

- **别把宿主机的核心全给它**：虚拟机的 CPU 是"分时借用"宿主机核心的，给太多反而拖慢宿主机。
- 这一屏下面有个 **"虚拟化 Intel VT-x/EPT 或 AMD-V/RVI"** 的勾选框——**现在不要勾**，第 9.5 节讲嵌套虚拟化时再用。

**第 8 屏：此虚拟机的内存** → 填 **4096 MB**（4 GB）；宿主机只有 8 GB 就填 2048～3072。

**第 9 屏：网络类型** → 选 **"使用网络地址转换（NAT）"**。

> 三种网络的区别先用一句话记住，细节在 [3.4](#34-虚拟网卡和三种网络模式)：
>
> - **NAT**：虚拟机能上网，Windows 也能连上它，但**外部网络里的其他机器看不到它**。**新手选这个，最安全**（默认）。
> - **桥接**：虚拟机会像一台独立电脑一样出现在你的局域网里，能拿到路由器分配的 IP。方便别的设备访问它，但也意味着它暴露在局域网里。
> - **仅主机**：只有宿主机能和它通信，完全离网。适合做隔离实验。

**第 10 屏：I/O 控制器类型** → 默认（`NVMe` 或 `LSI Logic`，保持它推荐的那项）。

**第 11 屏：磁盘类型** → 默认（`NVMe` 或 `SCSI`，保持推荐项）。

**第 12 屏：选择磁盘** → 选 **"创建新虚拟磁盘"**。

**第 13 屏：磁盘容量** →

- 最大磁盘大小：**40 GB**（学 Linux 足够；以后能扩容，见 [9.7](#97-磁盘扩容的完整流程)）；
- **"将虚拟磁盘存储为单个文件"** 和 **"拆分成多个文件"**：两者都行。默认推荐**单个文件**（性能略好）；如果你之后可能把它拷到 FAT32 的 U 盘上，就选**拆分成多个文件**（每个不超过 2 GB）；
- **"立即分配所有磁盘空间"**：**不要勾**。勾了会当场占掉 40 GB 真实空间，虽然性能稍好，但对新手没必要。

**第 14 屏：完成前，点"自定义硬件"再改三处**（这屏是最后的机会）：

1. **新 CD/DVD（SATA）** → 右侧选 **"使用 ISO 映像文件"** → 点"浏览"选中你下载的 `Rocky-10.2-x86_64-boot.iso` → **把"启动时连接"勾上**。
2. **USB 控制器** → **保留**（以后插 U 盘、接串口设备要用）。**声卡**、**打印机** 用不到，可以选中后点"移除"，能省一点资源，减少干扰。
3. **显示** → 把 **"加速 3D 图形"** 的勾**暂时取消**（安装器阶段不需要它，开了偶尔会黑屏；等系统装完、装了显卡驱动再开，见 [9.6](#96-性能优化清单)）。

点 **"关闭"→"完成"**。

**你应该看到：** 左侧"库"里出现了 `rocky10` 这一项，主界面显示它的"设备"清单：内存 4 GB、处理器 2、硬盘 40 GB、CD/DVD 指向那个 ISO、网络适配器 NAT。

**在开机之前，先做一次自查**（这几项错了，后面全乱）：

- [ ] CD/DVD 指向的是 Rocky 的 ISO，且"启动时连接"是勾上的
- [ ] 固件类型是 UEFI（在"虚拟机 → 设置 → 选项 → 高级"里能看到）
- [ ] 内存 4096 MB、处理器 2 核、硬盘 40 GB
- [ ] 网络是 NAT
- [ ] 虚拟机文件夹在本地盘（`D:\vm\rocky10`），路径里没有中文和空格

### 1.6 第 5 步：安装 Rocky Linux（安装器逐屏）

在 VMware 左侧选中 `rocky10`，点绿色三角 **"开启此虚拟机"**（或按 **Ctrl + B**）。**鼠标点进虚拟机窗口后会被"抓"住**，按 **Ctrl + Alt** 可以把它放出来——**这个键请现在记住，它是你在虚拟机和 Windows 之间来回切换的唯一方式。**

**你应该看到：** 黑屏 → 出现 Rocky 的引导菜单，几秒后自动开始加载安装器（会刷一大堆文字，正常）。

> **第一次开机时 VMware 可能弹一句提示**，大意是"此虚拟机可能已被移动或复制"，选 **"我已复制该虚拟机（I Copied It）"**。选"移动"会导致网卡 MAC 变化，进而影响以后配好的网络设置。

**第 1 屏：引导菜单** → 选 **`Install Rocky Linux 10.x`**（默认项，直接等它自动进）。

> 有一个 `Test this media & install Rocky Linux` 选项，它会先校验安装盘再装。**如果你跳过了第 1.4 步的哈希校验，现在给它五分钟做一次**，很值。

**第 2 屏：欢迎界面（WELCOME）** → 左下角选语言，推荐 **中文（中国）**（也可以选 English）。点 **"继续"**。

> **选中文的一个附带好处**：桌面、日历、输入法都是开箱能用的；**选 English 的好处**是报错信息和官方文档字面一致，搜索更准。**两个都想要的话**：这里选中文，然后在下一屏的"语言支持"里把 English 也勾上。

**第 3 屏：安装概要（INSTALLATION SUMMARY）** —— **这一屏是全文最需要注意的一屏**。它分成四块，每一块下面有几项，**带红色感叹号或黄色警告图标的项目必须先点进去设置，右下角的"开始安装"才会亮**。

```text
┌─ 安装概要 ────────────────────────────────────────────────┐
│  本地化                    软件                          │
│   键盘            (默认即可)   安装源        (自动检测)     │
│   语言支持        (勾中文+英)  软件选择  ← 点进去选一套     │
│   时间和日期  ← 点进去选上海                              │
│                                                          │
│  系统                      用户设置                       │
│   安装目的地  ← 必须点！       root 密码   ← 必须设置      │
│   KDUMP          (建议关)      创建用户    ← 必须创建      │
│   网络和主机名 ← 点进去开网卡                             │
│   安全策略        (先跳过)                                │
│                                          [ 开始安装 ]     │
└──────────────────────────────────────────────────────────┘
```

**逐个点进去，按下面填：**

**① 键盘** → 保持 `汉语` 或 `English (US)` 即可。

**② 语言支持** → 勾上 **中文（中国）**，**顺便把 `English (United States)` 也勾上**。多语言不占多少空间，但能让终端里的报错和网上文档对得上。

**③ 时间和日期** → 地区选 **亚洲**，城市选 **上海**；右上角"网络时间"保持**开启**。

**④ 安装源** → 它会显示"自动检测到的安装介质"（因为你挂的是 boot.iso，它会自动去找网络源或者 DVD 源）。**保持自动检测**，如果它显示"需要网络"，确认网络和主机名那一步已经打开网卡并连上网。

**⑤ 软件选择** → 三个选项的含义：

| 选项 | 装出来是什么 | 建议 |
| --- | --- | --- |
| **带 GUI 的服务器（Server with GUI）** | 有 GNOME 桌面、常用命令行工具、firewalld、SELinux | **本文选它**：既能看桌面，又是个"正经服务器" |
| **工作站（Workstation）** | 桌面 + 一堆办公/多媒体软件 | 当日常桌面用可以，学 Linux 没必要装那么多 |
| **最小安装（Minimal Install）** | 只有命令行 | 老手的做法：更干净、更快，但你得会 SSH 才能用——**建议第二轮再这么装** |

**⑥ 安装目的地（Installation Destination）** → **必须点进去一次**。

- 上半部分：**勾选那块 40 GB 的 `VMware Virtual disk`**（它是唯一的一块）；
- 下半部分"存储配置"：选 **"自动（Automatic）"**；
- 点左上角 **"完成"**；
- **然后看"更改摘要"**：它会把自动分区方案列出来（一般是 `/boot/efi`、`/boot`，加上一个 LVM 卷组，里面是 `/`，有的版本还会给一个 swap）。**点进去看一眼，别猜**——这是养成"知道自己机器长什么样"的习惯。

> **"我想自己分区"**：把"存储配置"改成 **"自定义（Custom）"** → 点"完成" → 进入手动分区界面，用 **`+`** 按钮逐条加挂载点。字段含义和推荐值在 [4.4](#44-分区lvmxfsswap-一次讲透) 讲透了，**建议第一次先用自动，第二次重装时再练手动**。
>
> **一个 Anaconda 经典坑**：在"安装目的地"里**什么都没改就直接点"完成"，它会弹一个红框说"没有足够的空间/需要先创建分区"**，然后你莫名其妙回到了概要页。这不是报错，只是提醒你"自动方案还没应用"。**再点进去、确认勾选了磁盘、"完成"、"接受更改"** 就好。

**⑦ KDUMP** → **取消勾选"启用 KDUMP"**。它的作用是"内核崩溃时把内存转储到磁盘"，学习用不上，开着还会固定占用一部分内存。

**⑧ 网络和主机名（Network & Host Name）** → **必须点进去**。

- 右上角把以太网开关拨到 **"打开"**（设备名形如 `ens33`、`ens160`、`eno1`）；
- 左下角"主机名"填一个有意义的名字，比如：

```text
rocky.lab
```

   点 **"应用"**。

> **别用 `xxx.local` 以外还想用的名字？** 规则是这样的：**不要用 `.local` 结尾**（它被 mDNS 协议占用了，容易出现"有时能解析有时不能"的玄学问题）。`rocky.lab`、`rocky.home`、`rocky.internal` 这类随便用，**主机名带域名不是必须的，纯 `rocky` 也行**。

**⑨ 安全策略（Security Profile）** → 第一次**先不选**。（那是给合规环境套 CIS/STIG 基线用的，会把系统改得很难用，不适合第一次学。）

**⑩ root 密码** → 设置一个你记得住的复杂密码，比如 `Rocky#2026Lab`。

- 如果密码太简单（比如 `123456`），会弹"密码太弱"，**要连点两次"完成"才能强制生效**——本文建议直接用复杂密码，别跟它较劲。
- 如果看到 **"锁定 root 账户（Lock root account）"** 的勾，**不要勾**（勾了 root 就登不了；不过我们日常都用普通用户 + sudo，root 只是备用）。
- 如果看到 **"允许 root 用密码进行 SSH 登录"**，**保持不勾**——这是更安全的默认值。

**⑪ 创建用户** → 这一步**必须做**（不做的话很多版本不让开始安装）：

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| 全名 | `Dev User`（随便） | 只是显示用的名字 |
| 用户名 | `dev` | **这是登录名**，用小写字母；以后 SSH 要天天敲它，越短越好 |
| 密码 / 确认密码 | 自己定，别忘了 | |
| **将此用户设为管理员（Make this user administrator）** | **勾上** | 勾上后这个用户能用 `sudo` 提权。**不勾的话你会得到一个"什么都干不了"的账号**（这正是[那篇 Debian 文章](/posts/debian-13-sudo-opencode-setup/)里讲的坑，Rocky 这里是勾选框，别漏） |
| 需要密码才能使用此账户 | 保持勾选 | |

**⑫ 现在"开始安装"应该亮了**，点它。接下来是自动化的拷包过程，视机器性能大约 5～20 分钟。安装过程中屏幕上的"ROOT 密码""创建用户"两个条目如果还带感叹号，**点进去补设**即可。

**你应该看到：** 进度条走完 → 右下角出现 **"重启系统（Reboot System）"** → 点它。

> **重启时如果卡在"黑屏 + 一个光标"**：先等 1～2 分钟；还不动就按 **Ctrl + Alt + Insert**（相当于虚拟机的"重启键"）。**如果它又从 ISO 引导进了安装器**，说明引导顺序没切过来——正常情况下安装器已经改好了硬盘引导，若没有，见 [10.2](#102-装系统阶段的报错) 里"装完还是进安装器"那一条。

**第 4 屏（首次启动）**：会看到 GRUB 引导菜单（默认几秒后自动进入），然后是要你登录的图形界面。

- 先点你的用户 `dev`，输入密码登录；
- 会弹一个"欢迎 / 初始设置"向导：**隐私、在线账号、时区这些能跳就跳**；如果出现 **"许可证信息（License Information）"**，要勾选接受才能继续（Rocky 是开源免费的，这一步只是法律文本确认）；
- 如果弹出"是否把语言改成中文"，按需要选。

**你应该看到：** 一个 GNOME 桌面（顶部有活动栏、左上角"活动"）。**到这里，一台 Rocky Linux 已经装好了。**

### 1.7 第 6 步：装完立刻做的五件事

现在的系统能跑，但还缺"让它好用"的几样东西。**打开终端**（点左上角"活动" → 搜索 `终端` 或 `terminal` → 回车；或者按 **Ctrl + Alt + T**），然后一条一条来。

> **看清楚提示符**：Linux 里你的提示符形如 `[dev@rocky ~]$`，**`$` 表示普通用户，`#` 表示 root**。后面所有命令都在这里敲，**不要跑到 Windows 的 PowerShell 里敲**。

**第 1 件：装 VMware 的"客人工具"（open-vm-tools）。** 它负责分辨率自适应、剪贴板互通、拖拽文件、时间同步、关机时通知宿主机。

```bash
sudo dnf install -y open-vm-tools open-vm-tools-desktop
```

- `sudo` 是"以管理员身份执行"，**第一次会要你输密码**（输的时候屏幕上不显示任何字符，这是正常的，输完回车）；
- `dnf` 是 Rocky 的包管理器（相当于手机上的应用商店，第 5 章细讲）；
- `-y` 表示"别问我了，直接装"；
- 装完**重启一次**让它生效：

```bash
sudo systemctl reboot
```

**第 2 件：全量更新一次系统。**

```bash
sudo dnf upgrade --refresh -y
```

   `--refresh` 的意思是"先刷新一下仓库里的软件清单再更新"。第一次可能更新几百个包，**花 5～20 分钟很正常**。

> **为什么要先更新？** 因为发行版镜像发布之后又修了不少安全和稳定性问题。**新装的系统先更新一次，是一个应该刻进肌肉记忆的习惯。**

**第 3 件：确认时间、时区、主机名。**

```bash
timedatectl
hostnamectl
```

**你应该看到：** `Time zone: Asia/Shanghai (CST, +0800)`、`System clock synchronized: yes`，主机名是你设的 `rocky.lab`。

不对就用这两条改（`sudo` 提权）：

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo hostnamectl set-hostname rocky.lab
```

**第 4 件：打一个"干净基线"快照。**

在 VMware 菜单里：**虚拟机（VM）→ 快照（Snapshot）→ 拍摄快照（Take Snapshot）**，名字写：

```text
干净基线：装完+更新+open-vm-tools
```

**这个快照是你在这一章最大的收获。** 以后不管把系统搞成什么样——删了 `/etc`、装崩了驱动、网卡配错上不了网——都能右键这个快照选 **"恢复到快照"**，几十秒回到现在这个状态。**快照的具体玩法和它的大坑见 [2.5](#25-快照不是备份先说结论) 和 [9.1](#91-快照树怎么管理)。**

**第 5 件：开启 SSH，让自己能从 Windows 敲命令。**

```bash
sudo systemctl enable --now sshd
systemctl status sshd
```

- `systemctl enable --now 服务名` = **开机自启 + 现在就启动**（这两个动作是分开的，`enable` 管开机，`start` 管现在，`--now` 把两件事一起做了）；
- `status` 应该显示绿色的 `active (running)`。

   **按 `q` 退出那个状态页面**（它会占住整个终端，很多人第一次以为卡死了）。

再看看自己这台机器的 IP 地址：

```bash
ip -4 addr show
```

**你应该看到：** 某个网卡（`ens33` 之类）下面有一行 `inet 192.168.x.x/24`。**把这个地址记下来**，下一步要用。

> **IP 会变吗？** NAT 网络里由 VMware 的虚拟 DHCP 分配，一般会一直给你同一个地址，但重启后可能变。**想知道"现在是多少"就再敲一次 `ip -4 addr show`。** 想彻底固定，见 [9.4](#94-网络进阶端口转发桥接仅主机)。

### 1.8 第 7 步：从 Windows 用 SSH 连进虚拟机

**这是本文一个重要的心态转变**：从这一刻起，你不必再对着虚拟机的窗口敲命令了。**在 Windows 的终端里 SSH 进去，体验几乎和连一台真服务器一样**——而且虚拟机窗口可以最小化，省资源。

1. 在 **Windows** 上打开 PowerShell（**Win + X → 终端**）。
2. 输入（把 IP 换成你刚才记下的）：

```powershell
ssh dev@192.168.80.128
```

3. 第一次连接会问：

```text
The authenticity of host '192.168.80.128' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

   输入 **`yes`** 回车。（这是在问"你信任这台机器的身份吗"——第一次见当然没见过，输 `yes` 是正常的；以后它会记在 `C:\Users\你\.ssh\known_hosts` 里。**如果某天它突然说"主机密钥变了"，那才是要警惕的事**。）

4. 然后输入用户 `dev` 的密码。

**你应该看到：** 提示符变成 `[dev@rocky ~]$`，**但这次是在 Windows 的窗口里**。敲 `ls`、`df -h`、`hostname` 试试，一切正常。

> **Windows 说"无法将 ssh 项识别为..."？** 说明没装 OpenSSH 客户端：**设置 → 系统 → 可选功能 → 添加可选功能 → 搜索 `OpenSSH 客户端` → 安装**。Windows 10/11 一般自带。
>
> **连不上？** 按顺序查：① 虚拟机里 `systemctl status sshd` 是不是 running；② 两边 IP 是不是同一个网段（Windows 上敲 `ipconfig`，看 `VMnet8` 那块网卡的地址，应该是 `192.168.80.1` 这种）；③ 是不是把 IP 抄错了。详见 [10.4](#104-网络相关的报错)。

**现在，回到虚拟机窗口，做最后一件事：关机。**

```bash
sudo systemctl poweroff
```

或者直接在 GNOME 右上角菜单里选"关机"。**别用 VMware 的"关闭虚拟机"来硬断电**——那相当于拔电源。

关机后，在 VMware 里把 **CD/DVD 的"启动时连接"取消掉**（虚拟机 → 设置 → CD/DVD → 取消勾选）。这样以后开机不会再去找 ISO，启动更快，也能避免"意外又进了安装器"。

**恭喜，第 1 章的操作部分结束。** 你现在拥有的是一台随时能回到起点的 Rocky Linux。

> **如果你打算接着装 Debian（第 6 章）**，先别急着做——**建议先把 Rocky 玩两天**，把第 2 章原理和第 5 章的命令过一遍，再来装第二台。两台空系统摆在那儿并不会让你学得更快，**一台玩熟了再装第二台，对照才有意义。**

## 2. 一分钟原理：虚拟机到底在跑什么

如果你只想知道"为什么这么配"，看完这一章就够了。想深挖再往后面翻。

### 2.1 一台虚拟机其实是"一堆文件 + 一个进程"

你在 VMware 里看到的那台"电脑"，真身是：**宿主机上的一个普通进程**（Windows 上叫 `vmware-vmx.exe`）**加上一个文件夹**。

| 你看到的 | 实际是什么 |
| --- | --- |
| 虚拟机的"屏幕" | 宿主机上一个窗口，内容是那个进程画出来的 |
| 虚拟机的"内存 4 GB" | **宿主机内存里划出来的 4 GB**（开机时分配，不是一开始就吃掉全部） |
| 虚拟机的"硬盘 40 GB" | 宿主机上的一个/一堆 `.vmdk` 文件 |
| 虚拟机的"网卡" | 宿主机上的虚拟网卡 + VMware 装的虚拟交换机驱动 |
| 虚拟机的"BIOS/UEFI" | 一个 `.nvram` 文件 + VMware 内置的固件模拟 |
| 虚拟机的"CPU 2 核" | **宿主机的物理核心按时间片借给它用** |

一句话：**虚拟机不是"模拟一台电脑的软件"，而是"用一个真实进程去假装一台电脑"。**

### 2.2 为什么需要 VT-x / AMD-V

CPU 的指令分两种：普通指令（加减乘除、读写内存）和**特权指令**（改页表、关中断、直接操作设备）。后者只有操作系统内核能执行。

问题是：**虚拟机里也有一套操作系统内核**，它也想执行特权指令。如果让它直接执行，它就会真的改到宿主机的页表和设备——那就穿帮了。

有三种历史方案：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **纯模拟** | 一条条翻译虚拟机里的指令（QEMU 不带 KVM 就是这样） | 慢几十倍，但能跨架构（在 x86 上模拟 ARM） |
| **二进制翻译 / 半虚拟化** | 扫描并改写特权指令，遇到就"陷入"到虚拟机软件里模拟（VMware 早期的做法） | 兼容性好但仍有开销 |
| **硬件虚拟化（VT-x / AMD-V）** | CPU 本身多出一个"客户机模式"：内核代码可以**直接跑在物理 CPU 上**，只有真正碰特权资源时才"退出"到虚拟机软件处理 | 快得多，**这就是必须开 VT-x 的原因** |

打个比方：**没有 VT-x，虚拟机软件像个同声传译，每句话都要它转一道；有 VT-x，相当于给 CPU 加了一个"双人房"，客人自己在里面说话，只有要动房间里的公共设施时才叫管理员。**

术语上：

- **Type-1（裸机型）**：hypervisor 直接装在硬件上，比如 VMware ESXi、KVM、Xen、Hyper-V。服务器上用的就是这类。
- **Type-2（宿主型）**：hypervisor 装在 Windows/Linux 之上，比如 VMware Workstation、VirtualBox。**你用的就是这类。**
- 现在两者的界线已经很模糊（Workstation 也能借 Windows 的 Hyper-V 跑），但这个分类仍然是理解"虚拟化在哪一层"的最好入口。

### 2.3 你点"开启此虚拟机"之后发生了什么

按时间顺序，大致是这样一串：

```text
你点"开机"
  ↓
VMware 启动 vmware-vmx.exe 进程，读 rocky10.vmx 里的配置
  ↓
按配置"造"出虚拟硬件：虚拟主板、2 个 vCPU、4 GB 内存、NVMe 磁盘、e1000e/vmxnet3 网卡、USB 控制器…
  ↓
把虚拟机的"内存"映射到宿主机进程的内存里（宿主机此时开始真的占用）
  ↓
运行虚拟机内置的 UEFI 固件（相当于真机主板上的那套程序）
  ↓
UEFI 按启动顺序找到光驱 → 从 ISO 里的 EFI 引导程序启动
  ↓
GRUB 加载安装器的内核和 initramfs → Anaconda 安装器跑起来
  ↓
（装好之后）UEFI 从硬盘的 EFI 分区启动 → GRUB → Linux 内核 → systemd → 图形界面
```

**有两个推论值得记住：**

1. **虚拟机开机时宿主机开始吃内存**，关机才还回来。所以"同时开三台 4 GB 的虚拟机"意味着宿主机至少要腾出 12 GB。
2. **虚拟机的"开机自检"是假的**（没有真硬件要检测），所以它启动比真机快。但**它走的引导链和真机是一样的**：UEFI → EFI 分区 → GRUB → 内核 → initramfs → systemd。**你在虚拟机里学到的引导知识，在真机上 100% 适用。**

### 2.4 NAT 网络是怎么通的

第 1.5 步选了 NAT，它是这样工作的：

```text
      你的 Windows（宿主机）
      ├── 物理网卡 ──────────→ 路由器 ──→ 互联网
      └── VMnet8（虚拟网卡，地址通常是 192.168.x.1）
             │
             └── 虚拟交换机（VMware 装的一个系统服务在管）
                    ├── 虚拟 DHCP：给虚拟机发地址（192.168.x.128 起）
                    ├── 虚拟 NAT：把虚拟机的流量"伪装"成宿主机的流量发出去
                    └── 你的虚拟机（192.168.x.128/24）

      VMnet1（仅主机模式的虚拟网卡，另一套网段）
```

于是：

- **虚拟机能上网**：它的包先给虚拟 NAT，NAT 换成宿主机的地址发出去，回来的包再换回去。和家里路由器给手机做 NAT 是一回事。
- **宿主机能连虚拟机**：因为 Windows 上有一块 `VMnet8` 网卡，地址就在同一网段，`ssh dev@192.168.x.128` 自然通。
- **局域网里的其他设备（手机、另一台电脑）连不上虚拟机**：因为在它们看来，流量全是"你的 Windows 发出来的"，虚拟机藏在后面。**想让别人能连，要改桥接或者做端口转发**（[9.4](#94-网络进阶端口转发桥接仅主机)）。

**怎么在 Windows 上确认这些？** 在 PowerShell 里：

```powershell
ipconfig /all
```

**你应该看到** `VMware Network Adapter VMnet8` 和 `VMnet1` 两块虚拟网卡，以及它们的 IPv4 地址。**这就是"虚拟网络真的存在"的证据。**

### 2.5 快照不是备份（先说结论）

**快照 = 给虚拟机拍一张"当前状态"的照片，以后可以回到那一刻。** 它非常好用，但有三件事必须知道：

1. **快照不是备份。** 快照文件**和虚拟机本体放在同一个文件夹、同一块硬盘上**。硬盘坏了、文件夹被误删了，快照和虚拟机一起没。**备份是"复制到另一个地方"，快照是"在这台机器上留个存档点"。**
2. **快照会拖慢虚拟机，并且越拍越大。** 原理是"写时复制"：拍下快照后，**所有新的写入都进一个增量文件**，原来的磁盘文件保持不变。所以：

```text
拍快照前：   [基础磁盘 vmdk]  ← 直接读写
拍快照后：   [基础磁盘 vmdk]（只读） + [增量 delta]（所有新写入）
跑得越久  →  增量文件越大 → 读一个旧文件可能要先穿过好几层增量 → 越慢
```

3. **不能用快照代替"长期存档"。** 正确用法是：**做危险操作前拍一张，做完确认没问题就删掉，只留少数几个关键节点（比如"干净基线"）。** 需要长期保留的状态，用**克隆**（[9.2](#92-克隆与模板)）或者把整个文件夹复制到另一块硬盘上。

| 我想做的事 | 该用哪个 |
| --- | --- |
| 试一个可能把系统搞坏的配置 | **快照**，改坏了就回滚 |
| 保留一个"装好就不动"的环境 | **克隆**成一台新虚拟机 |
| 防止硬盘坏、误删、勒索软件 | **备份**：把文件夹复制到另一块盘/移动硬盘/NAS |
| 把环境给同学 | **导出 OVF/OVA**（[9.8](#98-导出导入与迁移)） |

## 3. 电脑基础补课（虚拟机视角）

这一章补的是"虚拟机里的东西到底对应现实中的什么"。**遇到不懂的步骤回来查就行。**

### 3.1 一台电脑的四件套，在虚拟机里分别是什么

| 真机上的东西 | 虚拟机里的对应物 | 你要知道的关键点 |
| --- | --- | --- |
| CPU 核心 | **vCPU**（虚拟 CPU），数量由你在向导里指定 | vCPU 是"借用"宿主机的物理核心；**给的核数超过宿主机物理核数只会互相拖累** |
| 内存条 | 宿主机进程里的一块内存 | 开机时占用、关机时归还；宿主机内存不够时 VMware 会去用页面文件（卡到没法用） |
| 硬盘 | `.vmdk` 文件 | 可以扩容、可以加第二块（第 9.7 节），**但缩不回去** |
| 网卡 | 虚拟网卡（常见型号 `e1000e`、`vmxnet3`） | 配错型号装完可能没网；NAT/桥接/仅主机是"这根网线插在哪台交换机上" |
| 光驱 | ISO 文件挂载 | 装系统、进救援模式都要用它 |
| 显卡 | VMware 的虚拟显卡（`vmwgfx` 驱动） | 3D 加速是可选项，Linux 桌面卡顿/黑屏时先关它 |
| BIOS/UEFI | `.nvram` 文件 + VMware 固件模拟 | 固件类型（BIOS/UEFI）**建虚拟机时定，之后能改但很麻烦** |
| 电源键 | 虚拟机窗口里的开关机按钮 | **优先在系统里正常关机**，别用"关闭虚拟机"硬断电 |

### 3.2 虚拟磁盘：`.vmdk` 是怎么回事

**它不是一个"假硬盘"，而是宿主机文件系统上的一个普通文件**，里面按虚拟硬盘的扇区顺序存数据。

| 名词 | 意思 | 对你的影响 |
| --- | --- | --- |
| **单个文件 / 拆分成多个文件** | 一个 `.vmdk`，还是切成 `s001.vmdk`、`s002.vmdk`… | 拆分的方便拷到 FAT32 移动盘；单文件的 I/O 略好 |
| **精简置备（thin）/ 立即分配** | 用多少占多少 vs 一开始就占满 40 GB | 默认精简：**文件夹看起来只有几 GB，用久了会长到几十 GB** |
| **快照增量（delta）** | 拍快照后的所有新写入 | 见 [2.5](#25-快照不是备份先说结论) |
| **虚拟磁盘扩容** | 改"最大磁盘大小" | **只能变大**；改完还要在系统里扩分区和文件系统（[9.7](#97-磁盘扩容的完整流程)） |

**为什么"我明明只用了 10 GB，文件夹却占了 25 GB"？** 因为精简置备是**只增不减**的：文件删了，块已经分配出去就不会自动还给宿主机。想瘦身要用 VMware 的"压缩（Compact）"功能，而且得先在系统里把空闲块标记出来（[9.6](#96-性能优化清单)）。

### 3.3 UEFI、GPT、Secure Boot 是什么

这三个词经常一起出现，其实管的是三件不同的事：

| 名字 | 是什么 | 一句话理解 |
| --- | --- | --- |
| **BIOS / UEFI** | 主板上固件的两种世代 | 老的是 BIOS（1980 年代那套），新的是 UEFI。**UEFI 支持大硬盘、图形界面、安全启动** |
| **MBR / GPT** | 硬盘分区表的两种格式 | MBR 最多 4 个主分区、最大 2 TB；**GPT 是现代格式，分区数量几乎不受限** |
| **Secure Boot** | UEFI 的一个安全功能 | 开机时只允许"有可信签名"的引导程序运行，防止引导区病毒 |

它们的搭配关系：

```text
UEFI 固件 + GPT 分区表 + EFI 系统分区（/boot/efi） + 可选 Secure Boot   ← 现代组合（本文的选择）
BIOS 固件 + MBR 分区表 + 一个 1 MiB 的 biosboot 分区（GPT 时）        ← 老组合（只有老机器才需要）
```

**为什么这件事对你重要？**

- 你在安装器里选"自动分区"时，它**根据固件类型决定要不要建 EFI 分区**。选错固件 → 装完起不来。
- 手动分区时，**UEFI 必须有一个"EFI 系统分区"，挂载点是 `/boot/efi`，类型是 `EFI System Partition`**。没有它，引导程序没地方放。
- **Secure Boot 在 2026 年有个时代性的坑**：微软 2011 年签发的 Secure Boot 证书从 2026 年 6 月起陆续到期，虚拟机里的固件密钥库（PK/KEK/db）如果还是老一套，可能出现"装完起不来""引导校验失败"。VMware 26H1u1 已经带了自动修复 PK 的能力。**遇到相关问题，最快的两个办法是：把 Workstation 更新到最新版，或者在虚拟机设置里临时关掉 Secure Boot。**（微软的说明见 [Windows Secure Boot certificate expiration](https://support.microsoft.com/en-us/servicing/os/secure-boot/2025/06/windows-secure-boot-certificate-expiration-and-ca-updates)。）

### 3.4 虚拟网卡和三种网络模式

| 模式 | 虚拟机能不能上网 | 宿主机能不能连它 | 局域网别的设备能不能连它 | 什么时候用 |
| --- | --- | --- | --- | --- |
| **NAT** | ✅ | ✅ | ❌ | **默认**，学习、开发 |
| **桥接（Bridged）** | ✅ | ✅ | ✅（像一台独立电脑） | 要给别人访问（比如手机打开你搭的网页） |
| **仅主机（Host-only）** | ❌ | ✅ | ❌ | 断网做实验、模拟内网 |
| **自定义（Custom）** | 看你选哪个 vmnet | 看配置 | 看配置 | 想搭多台机器组成"内网"时 |

**还有两个经常被忽略的点：**

- **虚拟网卡型号**：Linux 里常见的是 `e1000e`（模拟 Intel 网卡，兼容性最好）和 `vmxnet3`（VMware 的半虚拟化网卡，性能更好，但**需要系统里有驱动**）。现代发行版两者都认，**默认值别动**。
- **MAC 地址**：每台虚拟网卡都有一个虚拟 MAC。**复制虚拟机文件夹时，两台机器的 MAC 会一样，同一个网络里就会打架**（见下一节）。

### 3.5 为什么虚拟机不能直接拷给别人用

"虚拟机就是一个文件夹"这句话对，但**直接拷文件夹有两个坑**：

1. **MAC 地址和 UUID 冲突**：复制出来的机器和原机器有同样的网卡 MAC、同样的虚拟机 UUID。如果在同一个网络里同时开机，会出现 IP 冲突、网络时通时断。**VMware 在你打开一个"看起来是复制品"的虚拟机时会弹窗问你是"移动"还是"复制"——选"我已复制该虚拟机"，它会重新生成 MAC/UUID。**
2. **路径和硬件兼容性**：`.vmx` 里可能写着绝对路径；新机器的 CPU 如果比创建时缺特性，虚拟机可能起不来（尤其是开了嵌套虚拟化或某些 CPU 特性时）。

**正确的"给别人/换电脑"姿势**：用 **文件 → 导出为 OVF** 生成一个 `.ova`（单个文件，包含配置 + 磁盘），对方用"打开 OVF"导入即可。见 [9.8](#98-导出导入与迁移)。

## 4. ISO、开机与安装器：从镜像到系统

这一章解释第 1.4～1.6 步背后的东西。**它的价值在于：以后你要装任何 Linux（包括真机），走的都是同一条路。**

### 4.1 ISO 是什么，校验和为什么必须做

**ISO 文件是"一张光盘的完整复印件"**：它把光盘上的目录结构、文件、以及最关键的**引导信息**一起打包成一个文件。安装盘能开机，就是靠里面那套引导信息（历史上叫 El Torito，现代 UEFI 系统靠里面的 EFI 引导分区）。

所以 ISO **不是压缩包**——你不能只解压出几个文件就装系统。**它必须被"当作光盘"用**：虚拟机里挂载它，真机上写进 U 盘。

**校验和（checksum）是"文件的指纹"**：下载过程中如果丢了几个字节（网络抖动、被下载工具截断、镜像站同步不全），算出来的哈希就和官方公布的不一样。**这种损坏最坑的地方是：它能通过，但会在安装到一半时以完全无关的报错形式炸掉**，让人怀疑硬盘、怀疑内存、怀疑人生。

所以务实规则是：**大文件（ISO、安装包）下载后花一分钟校验一次**。Linux 上更省事：

```bash
# 在 ISO 所在的目录里（需要同目录有 SHA256SUMS 或 CHECKSUM 文件）
sha256sum -c --ignore-missing CHECKSUM
```

输出里每个文件后面跟一个 `OK` 才算过。

### 4.2 从开机到安装器：五步引导链

你在虚拟机里看到的是"黑屏刷字然后进了安装器"，中间其实有这么几步：

```text
① UEFI 固件初始化（虚拟主板 + .nvram 里的设置）
      ↓ 按启动顺序找到光驱
② 读取 ISO 里的 EFI 引导程序
      ├─ 开了 Secure Boot：先跑 shim（有微软签名的小程序），由它验证并启动下一环
      └─ 没开：直接跑 GRUB
      ↓
③ GRUB 显示引导菜单（Install / Test this media / Troubleshooting）
      ↓ 你选了 Install
④ GRUB 把内核（vmlinuz）和 initramfs 加载进内存，交给内核
      ↓
⑤ 内核跑起一个"临时小系统"（initramfs 里的 dracut），
   它找到光盘、加载安装器需要的驱动，最后启动 Anaconda 安装器
```

**四个名词，看懂这张图就够了：**

| 名词 | 一句话 |
| --- | --- |
| **shim** | 被微软签名的"引导链第一环"，专为 Secure Boot 而生；Linux 发行版靠它才能在开了安全启动的机器上引导 |
| **GRUB** | 引导加载器：显示菜单、加载内核和 initramfs |
| **initramfs** | 一个内存里的小系统，负责"在内核还没法访问真正的根文件系统之前"把驱动和挂载准备好 |
| **Anaconda** | Fedora/RHEL/Rocky 系共用的安装器程序（就是你刚才点的那个图形界面） |

> **这个链条在你装完系统后依然在跑**，只是第 ② 步从"光驱里的 EFI 程序"变成"硬盘 EFI 分区里的 `/boot/efi/EFI/rocky/shimx64.efi`"，第 ⑤ 步从"安装器"变成"真正的系统"。**理解了它，以后"装完起不来"这类问题你就知道该从哪一环查。**

### 4.3 Anaconda 在装什么

安装器看着在"拷文件"，实际做了这些事（顺序大致如此）：

1. **探测硬件**：CPU、内存、磁盘、网卡、显卡——**你在虚拟机里，它探测到的就是 VMware 假装的那些设备**；
2. **按你的选择分区**：写 GPT 分区表、建 EFI 分区、建 LVM 卷组和逻辑卷、格式化成 XFS/ext4；
3. **解包 RPM 包**到目标分区（这就是为什么装系统要几十分钟：不是"复制一个镜像"，而是"装几千个软件包并逐条执行它们的安装脚本"）；
4. **给每个文件打上 SELinux 标签**（这一步很关键，漏了系统会起不来，见 [5.4](#54-selinux先学会看不要关)）；
5. **生成配置文件**：`/etc/fstab`（谁挂在哪儿）、`/etc/default/grub`、网络配置、用户和密码（密码是哈希后写进 `/etc/shadow` 的）；
6. **生成 initramfs**（`dracut`）——给新系统做一份"启动时用的小系统"，里面装着你这块硬盘、这个文件系统需要的驱动；
7. **安装引导程序**到 EFI 分区（`grub2-install` + `grub2-mkconfig`）；
8. **把你所有的安装选项存成一份"配方"**：

```bash
sudo cat /root/anaconda-ks.cfg
```

**这份文件是安装器的"录音"。** 你当时选了什么语言、什么分区、什么软件组，全在里面。它的实际用途是**无人值守安装**（Kickstart）：给 100 台机器装系统时，把这份文件改一改，安装器就能全自动跑完。**顺便说：看完它，你就再也不会觉得"安装过程是个黑盒"了。**

### 4.4 分区、LVM、XFS、swap 一次讲透

**先把四个概念分清**（新手最容易糊在一起）：

| 概念 | 是什么 | 类比 |
| --- | --- | --- |
| **分区表** | 描述"这块盘被切成几块"的表（GPT / MBR） | 一本书的目录 |
| **分区（partition）** | 盘上的一段连续空间，如 `/dev/nvme0n1p1` | 书的一章 |
| **文件系统（filesystem）** | 分区里"文件和目录怎么组织"的规则（XFS / ext4） | 章节里的排版规则 |
| **挂载点（mount point）** | 这个文件系统接到目录树的哪个位置（`/`、`/boot`） | 把这一章插入全书的位置 |

**Linux 和 Windows 最不一样的一点：Linux 没有"盘符"。** 所有东西都挂在**一棵树**上，树根是 `/`。你插一块新硬盘，不是得到"E 盘"，而是要把它的文件系统**挂到树的某个目录上**（比如 `/data`）。

**本文推荐的布局**（40 GB 单盘、UEFI）：

| 挂载点 | 大小 | 类型 | 说明 |
| --- | --- | --- | --- |
| `/boot/efi` | 600 MiB | EFI System Partition | **UEFI 必须有**，引导程序住这儿。别用 ext4，它的类型必须是 EFI System Partition |
| `/boot` | 1 GiB | ext4 | 放内核和 initramfs。**有人喜欢把 `/boot` 放进 LVM，但 GRUB 读 LVM 有时会出问题，独立分区最省心** |
| `swap` | 2～4 GiB | swap | 见下面 |
| `/` | 剩下的全部 | XFS，放在 LVM 上 | 根目录，所有东西都在这儿 |

**LVM 是什么？** 它是硬盘和文件系统之间的"中间层"，把物理磁盘抽象成可以随时伸缩的池子：

```text
物理卷 PV            卷组 VG              逻辑卷 LV            文件系统
/dev/nvme0n1p3  →   vg: rl         →    lv: root  (30G)  →  XFS，挂在 /
（一整块分区）      （一个资源池）         lv: swap  ( 4G)  →  swap
                                         lv: home  (10G)  →  XFS，挂在 /home
```

它的好处非常实际：

- **能在线扩容**：以后加一块虚拟硬盘 → 加入卷组 → 逻辑卷就变大了（[9.7](#97-磁盘扩容的完整流程) 有完整实操）；
- **能给逻辑卷起名字**，不用记"哪个分区是哪个"；
- **能做快照**（LVM snapshot，和虚拟机快照是两种不同的东西，但思路一样）。

**代价是多一层抽象**，出问题时排查链更长（分区 → PV → VG → LV → 文件系统，五层全要看）。**学习阶段建议：跟着默认走（Rocky 默认就用 LVM），知道有这几层就行。**

**XFS 还是 ext4？** 这是"RHEL 系 vs Debian 系"最直观的差异之一：

| | **XFS** | **ext4** |
| --- | --- | --- |
| 谁默认用 | RHEL / Rocky / Alma / Fedora 的 `/` | Debian / Ubuntu 的 `/` |
| 扩容 | ✅ 能在线扩 | ✅ 能在线扩 |
| **缩小** | ❌ **不支持缩小**（这是最容易踩的坑） | ✅ 支持（要先卸载） |
| 大文件/大容量表现 | 更好（设计目标就是大文件和高并发） | 够用 |
| 修复工具 | `xfs_repair`（**必须先卸载**） | `fsck.ext4` |
| 备份 | `xfsdump`（按文件系统，不能按目录） | 通用工具即可 |

**结论：安装器默认给什么就用什么。** 你唯一要记住的是：**如果你选了 XFS，根分区就只能变大不能变小。**

**swap 到底还要不要？**

- **它是什么**：一块"内存不够时拿来垫"的磁盘空间。物理内存紧张时，内核把不常用的内存页写到 swap，腾出物理内存。
- **现代机器还需要吗**：需要，但不像以前那么重要（内存大了、还有 zram 这种"压缩内存"技术）。**虚拟机里给 2～4 GB 就够了。**
- **唯一需要"swap ≥ 内存"的场景是"休眠（hibernate）"**——休眠要把整个内存写进 swap。**虚拟机里几乎不用休眠（挂起是另一回事，由 VMware 负责），所以别为它浪费 16 GB 磁盘。**
- **查它在不在用**：`swapon --show`、`free -h` 里的 Swap 那一行。

**手动分区的操作步骤**（Anaconda 里，想练的时候照着做）：

1. 安装目的地 → 存储配置选 **"自定义"** → 点"完成"（会弹出"点击这里自动创建"的提示，**别点**）；
2. 在新界面里选中那块盘 → 点 **`+`** 号，按下表逐条加：

| 点 `+` 后填的挂载点 | 大小 | 设备类型 | 文件系统 |
| --- | --- | --- | --- |
| `/boot/efi` | `600 MiB` | 标准分区 | `EFI System Partition` |
| `/boot` | `1 GiB` | 标准分区 | `ext4` |
| `swap` | `4 GiB` | 标准分区（或 LVM） | `swap` |
| `/` | 空着不填 = 剩余全部 | **LVM** | `xfs` |

3. 点 **"完成"** → 它会列出"将要进行的更改"，逐条看一遍 → 点 **"接受更改"**。

> **新手手动分区的三个经典错误**：① 忘了 `/boot/efi`（UEFI 机器装完起不来）；② 把 `/` 只给了 10 GB（装两个大软件就满了，根分区满 = 系统各种诡异故障）；③ 在 BIOS 固件下用 GPT 却忘了 1 MiB 的 `biosboot` 分区。**所以第一次用自动方案完全没错。**

### 4.5 软件选择里的几套系统有什么区别

"软件选择"这一屏背后是**软件组（group）**机制：发行版把几百个包预先组合成几个"环境（Environment）"，每个环境再挂一批可选组件。

| 你选的 | 大致包含 | 装完占用 | 适合 |
| --- | --- | --- | --- |
| **最小安装** | 内核、systemd、dnf、firewalld、SELinux 工具、基本命令 | 约 1.5～2 GB | 学服务、当服务器、追求干净 |
| **带 GUI 的服务器** | 上面这些 + GNOME + 浏览器 + 常用工具 | 约 5～7 GB | **本文默认**：能看桌面，也是正经服务器 |
| **工作站** | 桌面 + 办公/多媒体/打印等一堆东西 | 约 8～10 GB | 当日常桌面用 |

**装完之后还能补装或删掉吗？** 能：

```bash
# 看有哪些环境组、哪些已安装
dnf group list

# 补装一个图形界面（最小安装后悔了就用这条）
sudo dnf group install -y "Server with GUI"
sudo systemctl set-default graphical.target
sudo systemctl reboot
```

> **"最小安装"的人怎么用？** 全程靠 SSH：装完在虚拟机窗口里用命令行登录，`ip -4 addr show` 查 IP，然后从 Windows SSH 进去（第 1.8 节）。**这是最接近真实服务器运维的路径，也是本文推荐的"第二台机器"装法。**

## 5. Rocky 装完之后：RHEL 家族的规矩

这一章把 Rocky（以及 RHEL、AlmaLinux、Fedora、CentOS Stream）的"家规"讲清楚。**这些规矩和 Debian 系有明显差别，第 6 章会做正面对照。**

### 5.1 rpm、dnf5 和仓库：软件是怎么来的

**软件包（package）**是"一堆文件 + 安装脚本 + 元数据（版本、依赖、签名）"打成的单个文件。Rocky 用的是 **RPM** 格式（`.rpm`），Debian 系用的是 **DEB**（`.deb`）。

**为什么不能自己下载 `.rpm` 一个个装？** 因为依赖。A 依赖 B，B 依赖 C 的某个版本……手工解决会疯。所以有了包管理器：

```text
你在终端敲：   sudo dnf install nginx
                        │
        ① 读配置：/etc/yum.repos.d/*.repo  ← 里面写着"去哪些网址找包"
                        │
        ② 下载元数据（仓库里所有包的清单、版本、依赖、校验和）
                        │
        ③ 算依赖：nginx 需要 pcre2、openssl、zlib…全都够吗？
                        │
        ④ 下载 .rpm 到 /var/cache/dnf/  →  校验 GPG 签名（防止被人掉包）
                        │
        ⑤ rpm 逐个安装，把"我装了什么"记进本地的 RPM 数据库
                        │
        ⑥ 跑包的安装脚本（建用户、装 systemd 服务、生成配置）
```

**几个术语：**

| 词 | 意思 |
| --- | --- |
| **仓库（repository / repo）** | 一个放着几千个 RPM 和一份清单的网址（或本地目录） |
| **元数据（metadata）** | 那份清单：包名、版本、依赖、校验和。`dnf makecache` 就是在下它 |
| **依赖（dependency）** | "我要跑，必须先有谁" |
| **GPG 签名** | 包的防伪标记。`dnf` 默认会验；验不过就拒绝安装 |
| **dnf5** | Rocky 10 / RHEL 10 里的新版 dnf（用 C++ 重写），`dnf` 命令现在就是它 |
| **yum** | 老名字，现在基本只是 dnf 的别名，老教程里的 `yum install` 大多还能跑 |

**看一眼你的仓库配置：**

```bash
dnf repolist          # 现在启用了哪些仓库
ls /etc/yum.repos.d/  # 仓库配置文件都在这里
cat /etc/yum.repos.d/rocky.repo
```

`.repo` 文件长这样（字段比你想的少）：

```ini
[baseos]
name=Rocky Linux $releasever - BaseOS
mirrorlist=https://mirrors.rockylinux.org/mirrorlist?arch=$basearch&repo=BaseOS-$releasever
#baseurl=http://dl.rockylinux.org/pub/rocky/$releasever/BaseOS/$basearch/os/
gpgcheck=1
enabled=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-10
```

| 字段 | 意思 |
| --- | --- |
| `[baseos]` | 仓库的 ID，命令里用它（`dnf --repo=baseos ...`） |
| `mirrorlist` | "去这个网址问有哪些镜像可用"，比写死 `baseurl` 更抗故障 |
| `gpgcheck=1` | 校验签名，**不要改成 0** |
| `enabled=1` | 启用 |

> **换国内镜像源**（下载慢的时候做）：把 `mirrorlist` 那行注释掉，把 `baseurl` 换成清华/中科大的地址。**改之前先备份原文件**，因为改错了会影响所有安装：
>
> ```bash
> sudo cp /etc/yum.repos.d/rocky.repo /etc/yum.repos.d/rocky.repo.bak
> sudo sed -i 's|^mirrorlist=|#mirrorlist=|; s|^#baseurl=http://dl.rockylinux.org|baseurl=https://mirrors.tuna.tsinghua.edu.cn/rocky|' /etc/yum.repos.d/rocky*.repo
> sudo dnf clean all && sudo dnf makecache
> ```
>
> **`$releasever` 和 `$basearch` 不用你替换**，dnf 会自动展开成 `10` 和 `x86_64`。

### 5.2 dnf 常用命令表

| 我想干嘛 | 命令 | 备注 |
| --- | --- | --- |
| 刷新元数据 | `sudo dnf makecache` | 装东西报"找不到包"时先来一条 |
| 查有没有这个包 | `dnf search 关键字` | |
| 看包的信息 | `dnf info 包名` | 版本、来源、大小、说明 |
| **这个文件/命令属于哪个包** | `dnf provides */nginx.conf` | **排错神器**：报"命令不存在"时用它找该装哪个包 |
| 装 | `sudo dnf install 包名` | 一次可以写多个 |
| 装本地 rpm 并自动解决依赖 | `sudo dnf install ./xxx.rpm` | 比 `rpm -ivh` 好用，因为会联网补依赖 |
| 删 | `sudo dnf remove 包名` | 会连带删掉不再被需要的依赖（看清楚它列的清单再按 y） |
| 升级全部 | `sudo dnf upgrade --refresh` | 日常维护 |
| 只检查不装 | `sudo dnf check-update` | |
| 看已装/可装 | `dnf list --installed`、`dnf list --available` | |
| 看某个包装了哪些文件 | `rpm -ql 包名` | |
| 看某个文件属于哪个已装的包 | `rpm -qf /usr/bin/ls` | |
| 看安全更新 | `sudo dnf updateinfo list security` | |
| **看历史、回滚** | `sudo dnf history` → `sudo dnf history undo 12` | **误删软件后的救命命令**：把第 12 次事务整体撤销 |
| 清缓存 | `sudo dnf clean all` | 仓库换源、报"元数据损坏"时用 |
| 装软件组 | `sudo dnf group install "Server with GUI"` | |
| 图形式管理（RHEL 系特色） | `sudo dnf install cockpit` → 浏览器开 `https://IP:9090` | 可以在网页上管服务、看日志、装软件、开终端 |

> **dnf5 的一个变化**：`config-manager` 子命令的写法改了。老教程里的 `dnf config-manager --set-enabled crb` 在 dnf5 上不一定认，**新写法**是：
>
> ```bash
> sudo dnf config-manager setopt crb.enabled=1
> ```
>
> 两条都试试，哪条能跑就用哪条。**这类"老教程失配"是学 Linux 最常见的摩擦，判断方法只有一个：看报错，然后用 `dnf config-manager --help` 查当前版本支持什么。**

### 5.3 EPEL、CRB 和"Rocky 的软件为什么这么旧"

**先说为什么会旧。** RHEL 系的核心承诺是 **ABI/API 稳定**：你今天为 Rocky 10 编译的程序，到 2035 年还能跑。为了这个承诺，它**不允许在同一个大版本里升级主要软件的大版本**——Python 3.12 就是 3.12，不会变成 3.13。

| 你想要 | RHEL 系的做法 |
| --- | --- |
| 系统稳定、十年不用重装 | ✅ 这正是它的强项（Rocky 10 支持到 2035 年） |
| 用最新版的某软件 | ❌ 换 Flatpak / 容器 / 官方 SCL / 自己编译 |
| 装一些"额外但常用"的工具 | **EPEL** |

**EPEL（Extra Packages for Enterprise Linux）**是 Fedora 社区维护的"附加仓库"，专门给 RHEL 系补那些因为授权或政策进不了官方仓库的软件：

```bash
sudo dnf install -y epel-release
sudo dnf makecache
dnf repolist | grep epel
```

**CRB（CodeReady Builder）**是"开发用仓库"，很多开发库（`-devel` 包）在里面，默认不开：

```bash
# dnf5 的写法
sudo dnf config-manager setopt crb.enabled=1
# 老版本的写法（跑不通就用上面那条）
sudo dnf config-manager --set-enabled crb
```

> **第三方仓库要谨慎。** 网上教程常让你加 `remi`、`rpmfusion`、各种 `copr`。它们确实能给你新版本软件，但也可能**替换掉系统自带的库**，导致依赖地狱。规则：**能用官方仓库 + EPEL 解决的，就不要加第三方仓库。** 需要新版 PHP/Node 这类，优先用容器（第 8.7 节）。

### 5.4 SELinux：先学会看，不要关

**SELinux 是"强制访问控制"**：传统的 Linux 权限是"这个文件的属主是谁、其他人能不能读写"（第 7.2 节），SELinux 在这之上再加一层——**"这个进程有没有资格碰这类东西"**，而且规则由系统策略说了算，root 也不能随便违反。

**为什么你会遇到它？** 因为它是 RHEL 系默认开启且 Enforcing 的。典型场景：你把网页文件放到 `/var/www/html`，权限全开、防火墙也放了，浏览器还是 `403`——**因为 SELinux 不允许 httpd 读这个目录**。

**先看，别关：**

```bash
getenforce              # Enforcing / Permissive / Disabled
sestatus                # 完整状态：策略名、当前模式、配置文件位置
ls -Z /var/www/html     # 看文件的安全上下文（那一串 user:role:type:level 里的 type 最关键）
ps -Z -C httpd          # 看进程的上下文
id -Z                   # 看自己的上下文
```

**遇到拒绝时的处理流程：**

```bash
# ① 先看有没有被拒的记录（这是 SELinux 的"报错日志"）
sudo ausearch -m avc -ts recent
# 或者实时看
sudo tail -f /var/log/audit/audit.log

# ② 判断是"标签错了"还是"策略不允许"
#    如果只是你把文件搬到了新位置，标签不对 —— 用 restorecon 修回来：
sudo restorecon -Rv /var/www/html

# ③ 如果是"某功能被策略挡住了"，用布尔开关放行（而不是关掉 SELinux）：
getsebool -a | grep httpd          # 看有哪些开关
sudo setsebool -P httpd_can_network_connect on   # -P = 永久生效
```

**关于"关掉它"**：很多网上教程第一步就是 `setenforce 0` 或者改 `/etc/selinux/config` 把 `SELINUX=disabled`。**建议不要**：

1. **学会看 SELinux 的报错是 RHEL 系运维的基本功**，也是"我懂 Linux"和"我会抄命令"的分界线；
2. **关掉它会在系统里留下半残状态**：文件在 Enforcing 下打的标签，和 Disabled 时创建的文件标签不一致，以后想开回来会发现一堆服务起不来（**要开回来必须做一次全盘 relabel，很慢**）；
3. 临时排查可以用 `sudo setenforce 0`（重启后恢复），**但请把它当成"确认问题是不是 SELinux 造成的"的临时手段，而不是解决方案**。

**和 Debian 系的对照**：Debian/Ubuntu 默认用的是 **AppArmor**——同样是强制访问控制，但思路是"给每个程序写一份允许清单（路径级）"，比 SELinux 的"全局标签体系"简单得多，默认也更宽松。**这也是"两个发行版对照着学"能带给你的收获：同一个问题，两种哲学。**

### 5.5 firewalld：端口不通先看它

Rocky 默认开着防火墙（`firewalld`），**默认策略是"拒绝进来的连接，只放行少数几个服务"**。

```bash
firewall-cmd --list-all                 # 看当前区域放行了什么
sudo firewall-cmd --get-active-zones    # 看网卡在哪个区域
sudo firewall-cmd --add-service=http     # 临时放行 http（重启后失效）
sudo firewall-cmd --add-service=http --permanent   # 持久放行
sudo firewall-cmd --reload               # 让 permanent 的改动生效
sudo firewall-cmd --add-port=8080/tcp --permanent  # 放行一个端口
sudo firewall-cmd --remove-service=http --permanent && sudo firewall-cmd --reload
```

**规则（记这两条就够）：**

1. **`--permanent` 只写配置，不改当前状态；不加 `--permanent` 只改当前状态，不写配置。** 想"立刻就生效并且以后也在"，要**两条一起用**：先加 `--permanent`，再 `--reload`。
2. **`--reload` 会重载配置**，短暂断掉现有连接。远程改防火墙时**先想清楚别把自己关在外面**（这也是为什么建议在虚拟机里练手，而不是在真服务器上）。

> **排错顺序永远是这条链**：
>
> ```text
> 服务本身起了吗 → 监听在哪个地址/端口 → 防火墙放行了吗 → SELinux 允许吗 → 网络能通吗
> systemctl status  → ss -tlnp        → firewall-cmd --list-all → ausearch -m avc → ping/curl
> ```
>
> **"网页打不开"的九成原因在这四步里，而且顺序不能乱。** 先查服务再查防火墙，能省一半时间。

### 5.6 systemd 的基本功

**systemd 是 1 号进程**（PID 1），它负责启动系统上的一切，并管理"服务"。

```bash
systemctl status sshd        # 状态：active (running) / failed / inactive (dead)
sudo systemctl start sshd    # 现在启动
sudo systemctl stop sshd     # 现在停止
sudo systemctl enable sshd   # 设为开机自启（下次开机生效）
sudo systemctl disable sshd  # 取消开机自启（不影响当前）
sudo systemctl enable --now sshd   # 两步一起做
sudo systemctl restart sshd  # 改完配置重启服务
systemctl list-units --type=service --state=running   # 现在跑着哪些服务
systemctl list-unit-files --state=enabled             # 哪些是开机自启的
```

**最容易混淆的一点**：`start` 和 `enable` 是两件独立的事。

| 命令 | 影响"现在" | 影响"下次开机" |
| --- | --- | --- |
| `systemctl start X` | ✅ 立即启动 | ❌ |
| `systemctl enable X` | ❌ | ✅ |
| `systemctl enable --now X` | ✅ | ✅ |

**"我明明 start 了，重启就没了"**——因为忘了 enable。这句话在 Linux 新手群体里出现的频率极高。

### 5.7 sudo、wheel 组和 root

**root 是"超级用户"**，能做任何事，包括把系统删掉。所以现代做法是：**用普通用户登录，需要提权时临时用 `sudo`。**

```bash
sudo 命令              # 以 root 身份执行这一条命令（会问你的密码）
sudo -i                # 开一个 root 的交互式 shell（相当于"我不出去了"）
sudo -l                # 看"我被允许执行哪些命令"（排查权限问题的第一步）
whoami                 # 我现在是谁
id                     # 我的 UID、GID、属于哪些组
```

**为什么你能用 sudo？** 因为安装时勾了"将此用户设为管理员"，安装器把你的用户加进了 **`wheel` 组**：

```bash
id dev                          # 输出里应该有 wheel
grep wheel /etc/sudoers         # 会看到 %wheel ALL=(ALL) ALL 这一行
```

`/etc/sudoers` 里的 `%wheel ALL=(ALL) ALL` 意思是：**wheel 组的所有人，在任何主机上，可以以任何用户身份，执行任何命令**。想改这个文件**必须用 `visudo`**（它会检查语法，写错了不让保存，避免你把自己锁在外面）：

```bash
sudo visudo
```

**`su`、`su -`、`sudo -i` 的区别**（这三个经常被混用）：

| 命令 | 变成谁 | 环境变量 | 需要谁的密码 |
| --- | --- | --- | --- |
| `su dev` | dev | 保留当前的环境 | **目标用户的密码**（切 root 就是 root 密码） |
| `su - dev` | dev | 重新加载目标用户的登录环境（更干净，`-` 很重要） | 同上 |
| `sudo -i` | root | 加载 root 的登录环境 | **你自己的密码**（前提是你在 wheel 里） |

**最佳实践**：日常用 `sudo 单条命令`，别一直开着 root 的 shell——你在 root shell 里敲错一条命令，代价可能是整台机器。

贴墙上的那种。**别背，用的时候来查。**

## 6. 第二台虚拟机：装上 Debian，用对照法学 Linux

到这一步，你已经有一台能用的 Rocky。**为什么还要装一台 Debian？** 因为在 Linux 世界里，"Linux"其实是一大家子，而**看懂它们的差异，比多背一百条命令有用得多**。

### 6.1 为什么值得再装一台（不是重复劳动）

**"学一个发行版"和"学 Linux"是两件事。** 只用一个发行版，你会把它的"家规"当成 Linux 的真理：

- 你会以为"装软件当然是用 `dnf`"、"防火墙当然是 firewalld"、"必须管 SELinux"；
- 换个发行版（工作中、服务器上、别人的机器上）就抓瞎。

**两台机器摆在一起，你会立刻看清哪些是"Linux 的共性"，哪些只是"这个发行版的习惯"：**

| 同一个问题 | Rocky（RHEL 系）的答案 | Debian 的答案 |
| --- | --- | --- |
| 装软件 | `dnf` + `.rpm` | `apt` + `.deb` |
| 软件源配置 | `/etc/yum.repos.d/*.repo` | `/etc/apt/sources.list` 或 `*.sources`（deb822） |
| 默认根文件系统 | XFS | ext4 |
| 强制访问控制 | **SELinux**（默认 Enforcing） | **AppArmor**（默认按 profile 生效，宽松得多） |
| 防火墙 | firewalld（默认开） | 默认**没有防火墙服务**（只有 nftables 内核框架，规则为空） |
| 默认桌面 | GNOME | GNOME（可换 KDE/XFCE…） |
| 软件新旧 | 保守，十年一个大版本 | 版本较新，两年一版 |
| 特点 | 企业级、长相守 | 社区驱动、哲学清晰（社会契约、DFSG） |

**换句话说：装第二台的成本是 30 分钟，收益是"从此不再把某个发行版的习惯当成 Linux 本身"。**

### 6.2 复用第 1 章：只改三处

**新建虚拟机的流程和 [1.5](#15-第-4-步新建虚拟机向导每一屏) 完全一样**，照着做，只改这三个地方：

| 向导里的位置 | Rocky 时选的 | **Debian 时改成** |
| --- | --- | --- |
| 客户机操作系统 | Rocky Linux 64 位 | **Debian 13.x 64 位**（没有就选"其他 Linux 6.x 内核 64 位"） |
| 名称和位置 | `D:\vm\rocky10` | **`D:\vm\debian13`** |
| 磁盘大小 | 40 GB | **20 GB** 就够（Debian 基础系统很小），想多装点东西就 30 GB |

其他保持一样：**UEFI + Secure Boot、2 核、2048～4096 MB 内存、NAT、单个文件磁盘、自定义硬件里挂 Debian 的 ISO**。

- **内存**：Debian 不装桌面的话 1 GB 都能跑，给 2048 MB 很宽裕。想学"内存吃紧时会发生什么"，**故意给它 1024 MB 也有教学价值**（你会亲眼看到 OOM killer 出手，见 [8.4](#84-虚拟内存页表和-oom)）。
- **CD/DVD**：挂你之前下载的 `debian-13.7.0-amd64-netinst.iso`（[1.4](#14-第-3-步下载-rocky-linux-的-iso) 末尾让你顺手下的那个）。

### 6.3 Debian 安装器的差异清单

开机、选择 **`Graphical install`**（图形安装，操作最直观），然后按下面走。**和 Rocky 不同的地方都标出来了：**

| 步骤 | Rocky 的 Anaconda | **Debian 的安装器** |
| --- | --- | --- |
| 整体风格 | 一个"安装概要"页，逐项配置后统一点"开始安装" | **一步一屏的问答式**：语言 → 位置 → 键盘 → 网络 → 用户 → 分区 → 软件 → 装 |
| 语言/位置/键盘 | 一屏里三处 | 分三屏问你 |
| 网络 | 安装器里点开关打开网卡 | 自动用 DHCP 配置，**直接问你主机名和域名**（域名可以留空） |
| **root 密码** | 必须设 root 密码 | **可以留空！留空 = 不启用 root 密码登录，第一个用户自动获得 sudo** |
| 创建用户 | 单独的"创建用户"屏，要勾"设为管理员" | 紧接着 root 那屏问全名和用户名，**留空了 root 密码的话这个用户天然能用 sudo** |
| 分区 | "安装目的地"里选自动/自定义，界面是图形化的 | 问"分区方式"，选 **"使用整个磁盘"** → **"将所有文件放在一个分区中"**（新手最省事） |
| 时钟 | 选时区（上海） | 选时区（上海），**注意它用 UTC 存硬件时钟**（虚拟机里建议选"否"让硬件时钟用 UTC，见 [8.8](#88-时间utc时区和虚拟机时钟)） |
| 软件选择 | 环境组：最小安装 / 带 GUI 的服务器 / 工作站 | **tasksel 的勾选框清单**：只勾 **`SSH server`** 和 **`standard system utilities`**（要桌面就再勾 `Debian desktop environment` + `GNOME`） |
| 镜像源 | 安装源自动检测 | **会让你选镜像站**（选 `deb.debian.org` 或中国的镜像站如 `mirrors.tuna.tsinghua.edu.cn`，后者快很多） |
| 引导程序 | 自动装到 EFI 分区 | 会问"是否把 GRUB 装到主引导记录"，**UEFI 机器选是**（它自己会放进 EFI 分区） |
| 装完 | 重启进 GNOME | 重启进一个**文本登录界面**（如果你没勾桌面） |

**几分钟后你应该看到**：一个黑底白字的登录提示 `debian13 login:`，或者（勾了桌面的话）图形登录界面。

**这一步就是本文和[那篇 Debian 文章](/posts/debian-13-sudo-opencode-setup/)的分工**：那边把 Debian 安装器、sudo 的坑、把自己锁在外面怎么救、以及用 opencode 配整机讲得很透；**本文只讲"在虚拟机里装"和"两个发行版怎么对照"**。装 Debian 时遇到 `sudo: command not found`、`用户不在 sudoers 文件中` 这类问题，**直接去看那篇的第 3～4 章**，这里不重复。

**登录进去后，第一件事是确认自己在哪台机器上：**

```bash
hostname          # debian13
cat /etc/os-release
ip -4 addr show
```

### 6.4 装完之后的差别：apt、dpkg、deb822

**先用三条命令认路：**

```bash
cat /etc/debian_version          # 13.7
cat /etc/apt/sources.list        # 传统单行格式（可能只有几行注释）
ls /etc/apt/sources.list.d/      # 新版 deb822 格式的 .sources 文件常在这里
```

**Debian 13 的两种源格式**（这是新手最容易看懵的地方）：

```text
# 传统单行格式：/etc/apt/sources.list
deb http://deb.debian.org/debian trixie main contrib non-free-firmware

# deb822 格式：/etc/apt/sources.list.d/debian.sources
Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie
Components: main contrib non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
```

**两种格式二选一，别同时存在两套重复的源**（会出现"同一个包有两个来源"的警告）。**看到哪个就用哪个改。**

**apt / dpkg 命令表（和 dnf 正面对照）：**

| 我想干嘛 | Debian（apt/dpkg） | Rocky（dnf/rpm） |
| --- | --- | --- |
| 刷新软件清单 | `sudo apt update` | `sudo dnf makecache` |
| 升级全部（不删包） | `sudo apt upgrade` | `sudo dnf upgrade` |
| 升级全部（允许为依赖删包） | `sudo apt full-upgrade` | `sudo dnf upgrade` |
| 装 | `sudo apt install 包名` | `sudo dnf install 包名` |
| 删（保留配置） | `sudo apt remove 包名` | `sudo dnf remove 包名` |
| 删（连配置一起删） | `sudo apt purge 包名` | （删包时配置一般一并处理，另有 `dnf remove --noautoremove` 等细节） |
| 清理不再需要的依赖 | `sudo apt autoremove` | `sudo dnf autoremove` |
| 搜索 | `apt search 关键字` | `dnf search 关键字` |
| 看包信息 | `apt show 包名` | `dnf info 包名` |
| **这个文件属于哪个包** | `dpkg -S /usr/bin/ls` | `rpm -qf /usr/bin/ls` |
| **哪个包提供这个命令** | `apt-file search bin/命令`（要先 `apt install apt-file`） | `dnf provides */命令` |
| 看某个包装了哪些文件 | `dpkg -L 包名` | `rpm -ql 包名` |
| 我装了什么 | `apt list --installed` | `dnf list --installed` |
| 历史/回滚 | `less /var/log/apt/history.log`（**没有 dnf 那样的 undo**） | `dnf history` + `dnf history undo N` |
| 装本地包 | `sudo apt install ./xxx.deb` | `sudo dnf install ./xxx.rpm` |

**几个 Debian 特有的点：**

- **`apt update` 和 `apt upgrade` 是两件事。** 前者只刷新"有哪些包可装"，后者才真正动手。**"我明明 apt install 了却说找不到包"——十有八九是忘了 `apt update`。**
- **`non-free-firmware` 组件**：Debian 12 起把非自由固件单独列出来了。**装完发现没网卡/没无线**，先检查源里有没有 `non-free-firmware`，再 `sudo apt install firmware-iwlwifi` 之类。
- **Debian 没有 firewalld。** 想配防火墙用 `nftables` 或 `ufw`（`sudo apt install ufw` 更友好）。**这不是"Debian 不安全"，而是"Debian 默认不替你决定"**——它的哲学是：默认装最少的东西，需要什么自己加。
- **AppArmor 默认是"有内核支持、按 profile 生效"**：`sudo aa-status` 能看到已加载的 profile 数量。它比 SELinux 安静得多，多数人一辈子不会遇到它拦人。
- **桌面用户注意**：Debian 稳定版的 GNOME 版本比 Fedora 新，但比 Arch 旧。想尝鲜可以用 `backports` 源（**只装个别包，别整体升级**）。

### 6.5 两个家族的历史（为什么会有 rpm 和 deb）

知道这段历史，很多"为什么两个发行版这么不一样"就顺了：

```text
1991  Linus 发布 Linux 内核
1993  ├── Debian 诞生（社区驱动，先有"社会契约"再有发行版）
      └── Red Hat 诞生（1994 正式发布，商业公司主导）
1994  Debian 用 dpkg / .deb
1997  Red Hat 推出 RPM（Red Hat Package Manager）
2002  Red Hat 拆分出 RHEL（企业版，收费订阅）
2003  Fedora 成为 Red Hat 的"社区试验田"（新东西先在 Fedora 试）
2004  CentOS 出现：把 RHEL 的源代码重新编译成免费版，"和 RHEL 二进制兼容"
2020  Red Hat 宣布 CentOS 转向 CentOS Stream（滚动预览版），社区炸锅
2021  Rocky Linux 诞生（由 CentOS 创始人 Gregory Kurtzer 发起），继续做"RHEL 复刻"
```

**结论：Rocky 和 Debian 是两条完全不同血脉的传承**——一个是"企业级稳定性"路线，一个是"社区自治 + 严格自由软件定义"路线。**学了这两个，再看 AlmaLinux、Fedora、Ubuntu、openSUSE、Arch，你会发现它们都能在这张谱系图上找到位置。**

**顺便说一个趋势**：现在 Flatpak、Snap、容器（Docker/Podman）正在让"发行版差异"变小——**同一个容器镜像在 Rocky 和 Debian 上跑起来一模一样。** 所以本文的态度是：**发行版差异要懂，但别把它当信仰；哪天要换，你不会从零开始。**

### 6.6 两台机器怎么分工

**别让第二台闲着。** 一个很好用的分工：

| 机器 | 角色 | 干什么 |
| --- | --- | --- |
| `rocky10` | **服务端** | 练服务：Nginx、数据库、Podman、systemd 服务、防火墙、SELinux |
| `debian13` | **客户端/对照组** | 用 `curl`、`ssh`、`rsync` 去访问 Rocky；同时用它体会 apt/AppArmor 的差异 |

**在 Windows 上给两台机器配别名**（第 7.9 节会详细讲 `~/.ssh/config`）：

```text
# C:\Users\你的名字\.ssh\config
Host rocky
    HostName 192.168.80.128
    User dev

Host debian
    HostName 192.168.80.130
    User dev
```

以后 `ssh rocky`、`ssh debian` 就够了。**两台机器互相 `ssh`、互相 `curl`，你就有了一个最小的"网络实验室"**——这比在任何模拟器里学网络都真实。

## 7. 拿这两台机器学 Linux（动手练习课）

这一章是**练习清单**：每一节都是"在虚拟机里怎么做 + 为什么"。**虚拟机在这里的最大价值是：你可以放心地把它搞坏。**

**做练习前先打快照**（[9.1](#91-快照树怎么管理)）。以后你会养成一个习惯：**动手之前先拍快照，搞完确认没问题再删掉它。**

### 7.1 目录树：为什么配置文件几乎都在 `/etc`

Linux 的目录结构有一个标准，叫 **FHS（Filesystem Hierarchy Standard）**。**不要求背，但要认得这张表**：

| 目录 | 放什么 | 记忆点 |
| --- | --- | --- |
| `/` | 根，一切从这里开始 | 没有"盘符"这个概念 |
| `/bin`、`/sbin` | 基本命令（现在通常是指向 `/usr/bin`、`/usr/sbin` 的软链接） | `/usr` 合并后它们成了链接 |
| `/usr` | 系统自带的程序、库、文档 | **只读性质**，别往里手工塞东西 |
| `/usr/local` | **你手工编译安装的**软件 | 想自己编软件，装这儿 |
| `/etc` | **配置文件** | 你要改的东西 90% 在这 |
| `/var` | 会不断变大的东西：日志、缓存、数据库、网站文件 | **"磁盘满了"十有八九是它** |
| `/var/log` | 日志 | 排错第一站 |
| `/home` | 普通用户的家目录 | `~` 就是 `/home/dev` |
| `/root` | root 的家目录 | 不是 `/home/root` |
| `/tmp` | 临时文件，重启可能被清 | 谁都能写，所以有"粘滞位"（[7.2](#72-权限与用户)） |
| `/opt` | 第三方商业软件 | 少用 |
| `/proc`、`/sys` | **不是真文件**，是内核暴露出来的"窗口" | `cat /proc/cpuinfo` 就是在问内核 |
| `/dev` | 设备文件 | `/dev/nvme0n1` 是磁盘，`/dev/null` 是黑洞 |
| `/mnt`、`/media` | 临时挂载点、可移动介质 | 挂 U 盘常用 |

**两个能立刻用上的推论：**

```bash
# ① 磁盘满了，先看 /var 里是谁
sudo du -sh /var/* | sort -h

# ② 想改某个服务的行为，先找它的配置文件在 /etc 里叫什么
rpm -ql nginx | grep etc        # Rocky
dpkg -L nginx | grep etc        # Debian
```

### 7.2 权限与用户

**权限是 Linux 最基本的安全模型**，`ls -l` 的每一列都有意义：

```text
-rw-r--r--  1 dev  dev   1234 Nov  6 10:00 note.txt
│└┬┘└┬┘└┬┘  │ │    │      │
│ │  │  │   │ │    │      └── 大小、时间
│ │  │  │   │ │    └───────── 所属组
│ │  │  │   │ └────────────── 属主
│ │  │  │   └──────────────── 硬链接数（目录的链接数 = 子目录数 + 2）
│ │  │  └──────────────────── 其他人：r-- 只读
│ │  └─────────────────────── 所属组：r-- 只读
│ └────────────────────────── 属主：rw- 读写
└──────────────────────────── 文件类型：- 普通文件、d 目录、l 软链接
```

**数字表示法**（`chmod` 用得多）：`r=4`、`w=2`、`x=1`，三位相加：

| 权限 | 数字 | 常见于 |
| --- | --- | --- |
| `rwxr-xr-x` | `755` | 可执行文件、目录 |
| `rw-r--r--` | `644` | 普通文件 |
| `rw-------` | `600` | **私钥、密码文件** |
| `rwx------` | `700` | 私人目录（比如 `~/.ssh`） |

```bash
chmod 644 note.txt          # 属主可读写，其他人只读
chmod +x script.sh          # 给所有人加执行权限（脚本要用）
chmod 700 ~/.ssh            # 只允许自己进这个目录
chown dev:dev file          # 改属主和属组（需要 sudo）
umask                       # 看"新建文件默认去掉哪些权限"，一般是 022
```

**几条容易踩的点：**

- **目录上的 `x` 表示"能进去"**（`cd`），`r` 表示"能列出里面有什么"（`ls`）。**只有 `r` 没有 `x` 的目录，你能看到文件名但打不开文件**——这种半吊子状态很迷惑人。
- **`/tmp` 上的 `t`（粘滞位）**：谁都能建文件，但**只有文件属主能删自己的**。没有它就意味着"任何人都能删别人放在 /tmp 的东西"。
- **`setuid`（`s` 出现在属主执行位）**：任何用户执行它时，会以**文件属主**的身份运行。`/usr/bin/passwd` 就是这样：普通用户需要改 `/etc/shadow`（只有 root 能写），于是让 passwd 带着 root 身份去改。**这也是很多提权漏洞的来源，看到 setuid 文件值得多看一眼。**
- **`~/.ssh` 的权限必须是 700，私钥必须 600**，否则 ssh 会拒绝使用："Permissions 0644 for 'id_ed25519' are too open"。**这是 ssh 在保护你。**

### 7.3 进程与信号

```bash
ps aux                # 看所有进程（a=所有用户的，u=用户友好格式，x=包括没终端的）
ps -ef --forest       # 用树形看父子关系
pgrep -a sshd         # 按名字找进程
top / htop            # 实时看（htop 更好看：sudo dnf install htop）
```

**`ps aux` 里最该看的三列**：`PID`（进程号）、`%CPU`/`%MEM`（吃多少）、`STAT`（状态，`R` 运行、`S` 睡眠、`Z` 僵尸、`D` 不可中断的 IO 等待）。

**信号（signal）是"给进程发消息"**：

```bash
kill -15 PID      # SIGTERM：请你自己收拾收拾退出（默认，**优先用它**）
kill -9 PID       # SIGKILL：立刻弄死你，不给你收拾的机会（最后手段）
kill -1 PID       # SIGHUP：很多服务用它代表"重新读配置"
pkill -f "python.*server"   # 按命令行匹配批量杀
```

**为什么"先 -15 再 -9"？** 因为数据库、日志服务需要**把缓存刷盘、把事务收尾**。直接 `-9` 可能丢数据或者留下半截文件。**`kill -9` 是"实在不听话"才用的。**

**前后台与"关掉终端就死"**：

```bash
sleep 300 &        # 放后台跑
jobs               # 看后台任务
fg %1              # 把 1 号任务拉回前台
# Ctrl + Z        暂停当前前台任务（它还在，只是不动了）
bg %1              # 让暂停的任务在后台继续跑
nohup ./long.sh > out.log 2>&1 &   # 让它在关掉终端后还能活下去
```

> **经典误区**：直接在 SSH 里跑一个长任务然后关掉窗口 = 进程收到 SIGHUP = 任务死掉。**这就是 `nohup`、`tmux`、`screen` 存在的原因。** 现代做法：`tmux`（`sudo dnf install tmux`，断开重连还在）。

**看 `/proc` 认识进程的本质**：

```bash
ls /proc/1/                    # 1 号进程（systemd）的"内脏"
sudo cat /proc/1/cmdline | tr '\0' ' '   # 它的启动命令
cat /proc/meminfo | head        # 内存信息
cat /proc/cpuinfo | grep "model name" | head -2
ls -l /proc/self/exe            # "我自己"这个进程对应的可执行文件
```

**`/proc` 里没有真实文件**——它是内核在你读的时候**现场生成**的。**理解这一点，你就理解了"Linux 里一切皆文件"这句话的含义：连内核状态都能用读文件的方式访问。**

### 7.4 自己写一个 systemd 服务

**这是"从用户变成管理员"的一步。** 目标：写一个开机自动运行的小服务，并学会看它的日志。

**第一步：准备一个"服务本体"。** 用最简单的 Python 起个 HTTP 服务：

```bash
# 确认有 python3，没有就装
python3 --version || sudo dnf install -y python3

mkdir -p ~/myservice && cd ~/myservice
```

```bash
cat > ~/myservice/server.py <<'EOF'
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        body = b"hello from systemd\n"
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

HTTPServer(("0.0.0.0", 8080), Handler).serve_forever()
EOF
```

**第二步：写 unit 文件。** 系统级服务放在 `/etc/systemd/system/`：

```ini
# /etc/systemd/system/hello.service
[Unit]
Description=Hello HTTP service (learning)
After=network.target

[Service]
Type=simple
User=dev
WorkingDirectory=/home/dev/myservice
ExecStart=/usr/bin/python3 /home/dev/myservice/server.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

**逐字段解释**（这张表值得看懂）：

| 段/字段 | 意思 |
| --- | --- |
| `[Unit]` | 描述和依赖关系 |
| `Description` | 给人看的说明，`systemctl status` 里显示 |
| `After=network.target` | "等网络就绪之后再启动我" |
| `[Service]` | 怎么跑这个服务 |
| `Type=simple` | 默认类型：`ExecStart` 一执行，systemd 就认为服务起来了 |
| `User=dev` | **用哪个用户跑**（安全要点：别用 root 跑你自己的小程序） |
| `WorkingDirectory` | 工作目录（相对路径的基准） |
| `ExecStart` | **启动命令，必须写绝对路径**（systemd 不走你的 PATH） |
| `Restart=on-failure` | 崩了自动重启 |
| `[Install]` | `systemctl enable` 时用哪一段 |
| `WantedBy=multi-user.target` | 挂到"多用户模式"这个启动目标上（相当于"正常开机"） |

**第三步：让它跑起来。**

```bash
sudo systemctl daemon-reload        # 改了 unit 文件必须先来这一条！
sudo systemctl enable --now hello
systemctl status hello
```

**你应该看到** `active (running)`，然后从另一台机器（或宿主机）验证：

```bash
curl http://localhost:8080
curl http://192.168.x.x:8080          # 从 Debian / Windows 上试
```

**第四步：故意让它崩，练习看日志。**

```bash
sudo systemctl stop hello
# 把 ExecStart 里的 python3 改成一个不存在的路径，然后：
sudo systemctl daemon-reload && sudo systemctl start hello
systemctl status hello          # 会看到 failed 和 "No such file or directory"
journalctl -u hello -n 20       # 看这个服务的日志
```

**改回来，`daemon-reload` + `restart`，它就回来了。** 这一整套流程（写 unit → daemon-reload → enable → 看 journalctl）就是 Linux 上"部署一个后台服务"的标准动作，**以后换成 Nginx、数据库、你自己的程序，做的事情一模一样。**

> **两个必须记住的坑**：
>
> 1. **改了 unit 文件一定要 `systemctl daemon-reload`**，否则 systemd 用的还是老定义（这是"我明明改了配置怎么没用"的头号原因）。
> 2. **`ExecStart` 里不能写 `~/`、也不能靠 PATH**。systemd 不经过 shell，你得写 `/usr/bin/python3` 这种绝对路径。**"手动能跑，做成服务就不行"九成是这个原因。**

### 7.5 日志：出问题先看这里

**systemd 把所有服务的输出统一收进了 journal**：

```bash
journalctl -xe                    # 最近的问题（排错第一站）
journalctl -u hello               # 只看某个服务
journalctl -u hello -f            # 实时跟踪（= tail -f）
journalctl -u hello --since "10 min ago"
journalctl --since today --until "1 hour ago"
journalctl -b                     # 本次开机以来的全部
journalctl -b -1                  # 上一次开机的（重启后回看崩溃原因！）
journalctl -p err -b              # 只看 error 级别
journalctl --disk-usage           # journal 占了多大
sudo journalctl --vacuum-size=200M  # 限制它的大小
```

**`journalctl -b -1` 是排查"重启前的崩溃"的关键命令**——机器已经重启了，但上次开机的日志还在。

**传统日志文件也还在**（`/var/log/`）：

| 文件 | 内容 |
| --- | --- |
| `/var/log/messages` | 一般系统消息（Rocky/Debian 都有类似文件） |
| `/var/log/secure`（Rocky）/ `/var/log/auth.log`（Debian） | **登录、sudo、SSH 认证记录**（查"谁在爆破我的机器"看它） |
| `/var/log/dnf.log`、`/var/log/apt/history.log` | 软件安装历史 |
| `/var/log/boot.log` | 开机过程 |
| `/var/log/audit/audit.log` | **SELinux 的拒绝记录**（[5.4](#54-selinux先学会看不要关)） |

**日志会被"轮转"（logrotate）**：不然它会把磁盘写满。规则在 `/etc/logrotate.conf` 和 `/etc/logrotate.d/` 里。**看到 `messages-20261001` 这种带日期的文件，就是轮转的结果。**

### 7.6 磁盘与 LVM 扩容（虚拟机最爽的练习）

**这个练习只有虚拟机做得到**：真机上给硬盘扩容要先关机、插盘、进 RAID 卡界面……**虚拟机里点几下就行。**

**先说三个命令的区别（经常被混用）：**

| 命令 | 回答什么问题 | 数据来源 |
| --- | --- | --- |
| `lsblk` | **机器上有哪些块设备，怎么挂的** | 内核 |
| `df -h` | **文件系统层面用了多少空间** | 已挂载的文件系统 |
| `du -sh 目录` | **这个目录里的文件加起来多大** | 实际扫目录 |

> **`df` 说满了但 `du` 加起来对不上？** 最常见的原因是**有进程还占着一个已删除的文件**（你 `rm` 了，但进程没关，空间不释放）。用 `sudo lsof +L1` 找出来，重启那个服务就好了。**这是生产环境里的经典事故。**

**完整扩容流程（以 Rocky 为例，从 40 GB 扩到 60 GB）：**

```bash
# ① 记录现状
lsblk
df -h /
sudo vgs            # 卷组还剩多少空闲
```

```text
# ② 关掉虚拟机（sudo systemctl poweroff），在 VMware 里：
#    虚拟机 → 设置 → 硬盘 → 扩展 → 填 60 GB → 确定
#    （只能变大，不能变小！）
```

```bash
# ③ 开机，确认内核看到的新容量
lsblk                    # 磁盘 60G，但分区可能还是 40G —— 这是正常的，继续
sudo growpart /dev/nvme0n1 3      # 把第 3 个分区撑满磁盘（Rocky 需要先装 cloud-utils-growpart）
sudo pvresize /dev/nvme0n1p3      # 让 LVM 知道物理卷变大了
sudo vgs                          # 现在 VFree 应该多了 20G
sudo lvextend -l +100%FREE /dev/rl/root   # 把空闲全给根逻辑卷
sudo xfs_growfs /                 # XFS 在线扩容（ext4 用 resize2fs）
df -h /                           # 完成
```

**五个名词的对应关系，看这张图就懂了：**

```text
物理磁盘 60G
└── nvme0n1p3 分区 60G        ← growpart 处理这一层
    └── PV（物理卷）60G       ← pvresize 处理这一层
        └── VG rl（卷组）     ← vgs 看这一层的空闲
            └── LV root 60G   ← lvextend 处理这一层
                └── XFS 文件系统 60G  ← xfs_growfs 处理这一层
```

**为什么要分这么多层？** 因为每一层各管一件事：分区表管"盘怎么切"、LVM 管"空间怎么分配"、文件系统管"文件怎么放"。**多一层抽象，多一层灵活（可以随时把空间从一个逻辑卷挪到另一个），也多一层排查的活。**

> **一个真实的坑**：如果你扩容时先 `lvextend` 后 `pvresize`，会发现 `vgs` 里没有新空间可用，`lvextend` 报"insufficient free space"。**顺序是：先让内核看到分区变大（growpart）→ 再让 LVM 看到 PV 变大（pvresize）→ 再扩 LV → 最后扩文件系统。**

### 7.7 网络排查的一条链

**排错的正确顺序是"从近到远、从下到上"**，不要一上来就怀疑路由器：

```bash
# ① 我自己有没有地址、网卡起来了吗
ip -4 addr show
ip route                 # 默认网关是谁（default via ...）

# ② 本机服务在听吗、听在哪个地址上
ss -tlnp                 # -t TCP -l 监听 -n 数字端口 -p 进程
curl -I http://localhost:8080

# ③ 网关能通吗（用 IP，不用域名）
ping -c3 192.168.80.1

# ④ 外网 IP 能通吗
ping -c3 1.1.1.1

# ⑤ 域名能解析吗
dig www.rockylinux.org +short
cat /etc/resolv.conf

# ⑥ 应用层到底返回了什么
curl -v http://example.com
```

**这套顺序能立刻定位问题在哪一层：**

| 现象 | 结论 |
| --- | --- |
| `ip addr` 没地址 | 网卡没启用/DHCP 没拿到 → `nmcli device status`、`nmcli connection up 名字` |
| 有地址但 `ping 网关` 不通 | 虚拟机网络模式/虚拟交换机问题 → 查 VMware 的 VMnet 服务 |
| `ping 1.1.1.1` 通、`ping 网址` 不通 | **DNS 问题**（不是网络问题！） |
| IP 能通、端口不通 | 服务没起 / 防火墙 / SELinux → [5.5](#55-firewalld端口不通先看它) 那条链 |
| `curl` 有响应但内容不对 | 到应用层了，去看程序日志 |

> **"能 ping 通 IP 但 ping 不通域名"是最经典的一道分水岭**，它把"网络问题"和"DNS 问题"一刀切开。**记住这个分水岭，你能省下大量搜索时间。**

**DNS 解析在 Linux 上的链路**（和 Windows 不太一样）：

```text
程序调用 getaddrinfo
   ↓
/etc/nsswitch.conf 里写着 hosts: files dns   ← 先查 files，再查 dns
   ↓
files = /etc/hosts（本地手工映射）  →  没有？
   ↓
dns = /etc/resolv.conf 里的 nameserver  →  去问它
   ↓
（有 systemd-resolved 的系统上还会多一层 127.0.0.53 的本地缓存解析器）
```

**所以"我改了 /etc/resolv.conf 怎么没用"的答案常常是：它被 NetworkManager 或 systemd-resolved 接管了，你的改动会被覆盖。** 正确做法是改网卡配置（`nmcli`）或 `/etc/systemd/resolved.conf`。**这也顺便解释了 Linux 的一条通用规律：直接改"生成出来的文件"往往没用，要改"生成它的那个配置"。**

### 7.8 文本三剑客与管道

**Linux 的看家本领：把一堆小工具用管道串起来。**

```bash
# grep：找内容（-r 递归、-n 显示行号、-i 忽略大小写、-v 反选）
grep -rn "Listen" /etc/httpd/
journalctl -u sshd | grep -i "failed password"

# sed：按行替换/删除（-i 直接改文件，改前先备份！）
sed -n '1,20p' /etc/ssh/sshd_config          # 只看前 20 行
sudo sed -i.bak 's/^#PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
grep -v '^#' /etc/ssh/sshd_config | grep -v '^$'   # 去掉注释和空行看有效配置

# awk：按列处理（$1 第一列、$NF 最后一列、NR 行号）
awk '{print $1, $NF}' access.log
awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd     # UID ≥ 1000 的普通用户

# 管道 + 排序 + 计数：一条命令回答"谁在刷我的站"
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

# 重定向
命令 > file        # 覆盖写入
命令 >> file       # 追加
命令 2> err.log    # 只重定向错误输出
命令 > all.log 2>&1  # 标准输出和错误都进同一个文件

# xargs：把上一步的输出变成下一步的参数
find /var/log -name "*.log" -size +10M | xargs -r ls -lh
```

**一个真实例子**：统计 SSH 登录失败的来源 IP 前十名（**公网机器上天天用**）：

```bash
sudo grep "Failed password" /var/log/secure \
  | awk '{print $(NF-3)}' \
  | sort | uniq -c | sort -rn | head
```

**这个例子的价值不在命令本身，而在思路**：`grep 挑行 → awk 取列 → sort 排序 → uniq -c 计数 → sort -rn 按数量倒序 → head 取前十`。**几乎所有"日志分析"都是这个套路的变体。**

### 7.9 SSH 密钥、scp、rsync

**密码登录能省则省，密钥登录又快又安全。** 在 **Windows** 上生成密钥：

```powershell
ssh-keygen -t ed25519 -C "windows-to-vm"
# 一路回车（默认路径 C:\Users\你\.ssh\id_ed25519；密码短语可以留空，也可以设）
```

**把公钥装到两台虚拟机上**（Windows 上没有 `ssh-copy-id`，用这个写法）：

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh dev@192.168.80.128 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**从 Linux 到 Linux**（比如 Debian 连 Rocky）就简单了：

```bash
ssh-keygen -t ed25519
ssh-copy-id dev@192.168.80.128
```

**然后配 `~/.ssh/config`**（Windows 上也在 `C:\Users\你\.ssh\config`）：

```text
Host rocky
    HostName 192.168.80.128
    User dev
    IdentityFile ~/.ssh/id_ed25519

Host debian
    HostName 192.168.80.130
    User dev
```

以后 `ssh rocky` 一条命令直达，`scp 文件 rocky:/tmp/` 也一样。

**传文件：`scp` 还是 `rsync`？**

| | `scp` | `rsync` |
| --- | --- | --- |
| 简单程度 | 最简单：`scp a.txt rocky:/tmp/` | `rsync -avz a.txt rocky:/tmp/` |
| 增量传输 | ❌ 每次都全传 | ✅ **只传变化的部分** |
| 断点续传 | ❌ | ✅（`--partial --progress`） |
| 排除文件 | 麻烦 | ✅（`--exclude '*.log'`） |
| 删除目标端多余文件 | ❌ | ✅（`--delete`，**危险，先 `-n` 干跑一遍**） |

**结论：传一两个小文件用 `scp`，传目录、传大文件、要定期同步用 `rsync`。**

```bash
rsync -avz --progress ~/project/ rocky:/home/dev/project/
rsync -avzn --delete ~/project/ rocky:/home/dev/project/   # -n 只演练不落地，看看它会删什么
```

> **`rsync` 的路径结尾斜杠是个经典坑**：`rsync -a src/ dst/`（带斜杠）是"把 src 里的**内容**同步到 dst"，`rsync -a src dst/`（不带）是"把 src **这个目录**放进 dst"。**差一个字符，结果完全不同。**

### 7.10 定时任务

**经典方案：cron。**

```bash
crontab -e        # 编辑当前用户的定时任务
crontab -l        # 列出
```

**五个星号的含义**（记住顺序：分 时 日 月 周）：

```text
*  *  *  *  *  要执行的命令
│  │  │  │  └── 星期几（0-7，0 和 7 都是周日）
│  │  │  └───── 月（1-12）
│  │  └──────── 日（1-31）
│  └─────────── 小时（0-23）
└────────────── 分钟（0-59）

*/5 * * * *   每 5 分钟
0 3 * * *     每天凌晨 3 点
0 3 * * 0     每周日凌晨 3 点
@reboot       每次开机时
```

**两个必须有心理准备的点：**

1. **cron 的环境和你登录时的环境不一样**（PATH 极简、没有你 `~/.bashrc` 里的设置）。**脚本里要用绝对路径**，命令要写全路径，否则"手动跑没问题，cron 跑就失败"。
2. **cron 的输出会以邮件形式尝试发给你**（机器上没邮件系统就丢进日志）。**最好显式重定向**：

```bash
0 3 * * * /usr/bin/rsync -avz /data/ /backup/ >> /var/log/mybackup.log 2>&1
```

**现代方案：systemd timer**（更适合"服务化"的定时任务，能看日志、能依赖其它服务）：

```ini
# /etc/systemd/system/backup.timer
[Unit]
Description=Daily backup

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable --now backup.timer
systemctl list-timers              # 看所有定时器下次什么时候跑
journalctl -u backup.service       # 看它跑得怎么样
```

**选哪个？** 学习、临时脚本用 `cron`（到处都有）；正式服务用 `timer`（和 systemd 生态一致，日志统一）。

### 7.11 用快照养成"敢做实验"的习惯

**这是本文最想让你形成的一个工作流**：

```text
① 拍快照（名字写清楚：改 nginx 之前的基线）
   ↓
② 大胆改、大胆删、大胆装 —— 允许自己犯错
   ↓
③ 记录：改了什么、报了什么错、怎么解决的（这一步最容易被跳过，但收益最大）
   ↓
④ 成功了 → 删掉快照（保持虚拟机轻快）
   失败了 → 恢复快照，回到 ②，用你刚学到的信息再试一次
```

**给你三个"故意搞坏"的练习**（每个都在快照保护下做）：

1. **把自己锁在 SSH 外面**：`sudo systemctl stop sshd` 然后从 Windows 连——连不上。**回到虚拟机窗口（你有"物理接触"！）把它启回来。** 这个练习的价值是理解"为什么服务器要留一个带外管理通道（IPMI、串口、救援模式）"。
2. **让磁盘满掉**：`dd if=/dev/zero of=~/bigfile bs=1M count=8000`（先看清楚根分区还剩多少！），然后观察系统各种诡异行为（写日志失败、GUI 卡、装软件报错）。**用 `df`/`du` 找出来、删掉、恢复。**
3. **让一个进程吃满内存**：用 `stress-ng`（`sudo dnf install stress-ng`）或者自己写个吃内存的循环，观察 `free -h`、`top`，以及内核什么时候出动 OOM killer（`dmesg | tail` 里会看到 `Out of memory: Killed process ...`）。**这就是 [8.4](#84-虚拟内存页表和-oom) 讲的东西在眼前发生。**

**这三个练习做完，你对 Linux 的"怕"会少一大半。** 因为你知道：**最坏的情况无非是回滚快照。**

## 8. 再往下走一层：程序、内核、硬件

**这一章是给"想知道为什么"的人准备的。** 它把上一篇（C 语言、编译过程）和这一篇（Linux、虚拟机）接起来：**你写的 `.c` 是怎么变成 CPU 上跑的东西的？中间那几层是什么？**

### 8.1 从 `.c` 到进程：ELF、动态链接、strace

**先在 Rocky 里把上一篇的程序跑一遍**（证明 Linux 上的编译器和 Windows 上是同一套世界观）：

```bash
sudo dnf install -y gcc make
mkdir -p ~/code && cd ~/code
cat > hello.c <<'EOF'
#include <stdio.h>
int main(void) {
    printf("Hello from Linux!\n");
    return 0;
}
EOF
gcc -Wall -g -o hello hello.c
./hello
```

**Linux 上可执行文件不叫 `.exe`，叫 ELF。** 但"编译四阶段"（预处理 → 编译 → 汇编 → 链接）和 `-Wall`、`-g`、`-o` 的含义**完全一样**——这正是上一篇推荐 MinGW 而不是 MSVC 的理由。

**看清这几个工具在问什么：**

```bash
file hello          # 它是什么文件（ELF 64-bit LSB executable, x86-64 ... dynamically linked）
ldd hello           # 它依赖哪些动态库（libc.so.6 ...）
readelf -h hello    # 看 ELF 头：入口地址、架构、类型
objdump -d hello | head -30   # 反汇编，看到真正的机器指令
strings hello | head          # 看看二进制里有哪些可读字符串
```

**"动态链接"是什么意思？** `hello` 自己**不包含** `printf` 的实现，它只记着"我需要 libc.so.6"。真正把两边接上的是**动态链接器**（`/lib64/ld-linux-x86-64.so.2`），在程序启动那一刻才去找库、填地址。

**这解释了一个经典怪现象**：

```bash
./hello
# bash: ./hello: No such file or directory
# —— 但文件明明在！
```

**原因是：它找不到动态链接器或某个 `.so`，而错误信息含糊地报成了"文件不存在"。** 常见于"把一个 32 位程序拷到没有 32 位库的系统上""编译时链接了某个容器里的库"。排查方法：

```bash
file hello                          # 看架构对不对（x86-64 还是 32-bit）
ldd hello                           # 看哪个库 "not found"
./hello; echo $?                    # 看退出码
```

> **这也是"解释器缺失"的通用套路**：一个脚本开头写着 `#!/usr/bin/python3`，如果系统里没有 python3，报错也是 `bad interpreter: No such file or directory`。**报错说的是"我在找的那个东西不存在"，不是"你敲的文件不存在"。**

**`strace`：把"程序在跟内核说什么"全部打印出来。**

```bash
sudo dnf install -y strace
strace -f ./hello
```

**你会看到几百行，抓住这几行就够了**：

```text
execve("./hello", ["./hello"], 0x7ffd...) = 0        ← 内核装载了这个程序
openat(AT_FDCWD, "/etc/ld.so.cache", O_RDONLY) = 3   ← 打开动态链接器缓存
openat(AT_FDCWD, "/lib64/libc.so.6", O_RDONLY) = 3   ← 打开 libc
...
write(1, "Hello from Linux!\n", 18) = 18             ← 真正"打印"的动作
exit_group(0) = ?                                    ← 退出
```

**这几行把前面所有抽象都落地了：** 程序不是"凭空打印"，它是**通过系统调用（`write`）请求内核**，替它把字节送出去。**"用户程序只能请求、不能直接操作硬件"——这就是下一节的主题。**

### 8.2 用户态、内核态和系统调用

CPU 有两种（实际上是四种，但常用两种）运行级别：

| 级别 | 叫什么 | 能干什么 |
| --- | --- | --- |
| Ring 0 | **内核态** | 执行所有指令：改页表、关中断、直接读写设备 |
| Ring 3 | **用户态** | 只能执行普通指令，碰特权资源就触发异常 |

**你的程序（包括 `bash`、`nginx`、`python`）永远跑在 Ring 3。** 想读写文件、发网络包、申请内存，都必须**通过系统调用（syscall）"请求"内核**：

```text
用户程序                          内核
   │                              │
   │  write(1, "hi", 2)           │
   ├─────── 系统调用（陷入） ─────→│
   │                         ① 检查参数合法吗
   │                         ② 找到 fd 1 对应的文件/终端
   │                         ③ 把数据交给驱动
   │  ←────── 返回值 2 ───────────┤
   │                              │
```

**这就是为什么"用户态/内核态"值得知道**：

- **安全**：程序不能直接碰硬件，乱来最多自己被杀死。
- **稳定**：内核崩了整机就崩；用户程序崩了只死一个进程。
- **性能**：每次系统调用都要"陷入—返回"，有固定开销。**所以高性能程序会尽量减少系统调用次数**（批量读写、`io_uring`、零拷贝这些技术都是为这个目标服务的）。

**"Linux 里一切皆文件"的真相**：内核给每个打开的东西分配一个**文件描述符（fd）**——一个整数。文件、目录、管道、socket、设备、`/proc` 里的伪文件，都统一成"可以 `read`/`write`/`close` 的对象：

```bash
ls -l /proc/$$/fd       # 看当前 shell 打开了哪些 fd（0=标准输入 1=标准输出 2=标准错误）
```

**这就是"一切皆文件"的实际含义：不是"它们真的是文件"，而是"它们都提供了同一套接口"。** 于是 `cat /proc/cpuinfo`、`echo 1 > /proc/sys/net/ipv4/ip_forward`、`nc` 收发网络数据，都能用同一套工具操作。

### 8.3 中断、时钟和上下文切换

**中断（interrupt）是"硬件叫醒 CPU"的机制**：网卡收到包、磁盘读完数据、键盘按下按键，都会发一个中断，CPU 暂停手头的活，跳去执行对应的处理程序。

**时钟中断**尤其重要：内核靠它**定期拿回控制权**——检查"这个进程的时间片用完了吗、该换谁跑了"。这就是**抢占式多任务**的基础。

```bash
vmstat 1            # 每秒刷新：r 可运行进程、b 不可中断、cs 上下文切换、in 中断次数
pidstat -w 1        # 看每个进程的上下文切换（需要 sysstat 包）
uptime              # 负载（load average）——注意它统计的是"可运行 + 不可中断"的进程
```

**一个非常实用的知识点**：**load average 高但 CPU 空闲？** 说明进程卡在**不可中断状态（D）**——典型原因是磁盘 IO 慢（在虚拟机里，就是宿主机磁盘被别的虚拟机或同步软件拖住了）。**"看负载高不高"从来不够，还要看它高在哪一类进程上。**

### 8.4 虚拟内存、页表和 OOM

**内存管理的核心思想**：每个进程都以为自己独占一大片连续内存（**虚拟地址空间**），实际物理内存由内核按"页"（常见 4 KiB）分配，中间靠**页表**翻译。

```text
进程 A 看到的虚拟地址         物理内存（真实的条子）
0x0000... 代码         ──┐
0x4000... 数据         ──┼──→  页表 ──→  物理页框（4 KiB 一块）
0x7fff... 栈           ──┘              （可能根本不在内存里，而在 swap）
```

**这套机制带来四个好处**（每一个都对应你会在 Linux 上遇到的现象）：

| 好处 | 现象/命令 |
| --- | --- |
| 进程之间互相看不见对方的内存 | 一个程序崩溃不会串改别人的数据 |
| 内存可以"超额承诺"（overcommit） | 申请 1 GB 不等于立刻占用 1 GB；`malloc` 成功不代表真有内存 |
| 不常用的页可以换到 swap | `free -h` 里 Swap 那行；性能陷阱：换出去再换回来会很慢 |
| 内存可以映射文件（mmap） | 程序加载、大文件读写、共享库都靠它 |

**必须看懂 `free -h`**：

```text
               total        used        free      shared  buff/cache   available
Mem:           3.6Gi       1.2Gi       0.3Gi        20Mi       2.1Gi       2.2Gi
Swap:          4.0Gi          0B       4.0Gi
```

- **`free` 很小不代表内存不够**——`buff/cache` 是**内核拿空闲内存做的缓存**（读过的文件、写过的块），需要时会立刻让出来；
- **真正该看的是 `available`**：它才是"新程序还能拿多少"；
- **`swap used` 不为 0 也不一定有问题**，但如果它在持续增长且 `si/so`（`vmstat` 里的换入换出）一直非零，说明内存确实紧张。

**OOM killer**：当系统内存真的耗尽、连回收都救不回来时，内核会**挑一个进程杀掉**（按"占用大 + 重要性低"评分）：

```bash
dmesg | tail -30 | grep -i -A5 "out of memory"
# 你会看到：Out of memory: Killed process 1234 (python3) total-vm:..., anon-rss:...
journalctl -k | grep -i "killed process"
```

**这就是 [7.11](#711-用快照养成敢做实验的习惯) 里那个练习要你亲眼看到的东西。** 在虚拟机里给 1 GB 内存、故意跑个吃内存的程序，你就能看到：先卡、然后 swap 狂转、最后某个进程被杀。**生产环境里"服务莫名其妙挂了"，第一件事就是查它是不是被 OOM 杀了。**

### 8.5 从文件系统到磁盘

**一次 `write` 到磁盘，中间要穿过很多层**：

```text
你的程序 write()
   ↓  系统调用
VFS（虚拟文件系统层，统一接口）
   ↓
具体的文件系统（XFS / ext4 / …）——决定"文件放在哪些块上"
   ↓
页缓存（page cache）——内核先把数据放内存里，标成"脏页"
   ↓  （稍后由内核线程回写）           ← 注意：这里就"返回成功"了
块设备层 —— 决定 IO 怎么排、怎么合并
   ↓
设备驱动（nvme / virtio / vmw_pvscsi…）
   ↓
虚拟磁盘（vmdk 文件）
   ↓
宿主机文件系统 → 宿主机驱动 → 你的真实 SSD
```

**三个由此而来的重要结论：**

1. **`write` 返回成功 ≠ 数据已经在磁盘上。** 它只保证"内核收到了"。想强制落盘要用 `fsync()`（命令层面是 `sync`、`fsync` 工具）。**这也解释了"断电后文件损坏"和"数据库为什么需要 WAL/事务日志"。**
2. **文件系统需要日志（journal）。** XFS/ext4 都是日志文件系统：先记"我要做这些改动"，再真正改数据。断电后靠日志回放保持一致性（**这就是开机时偶尔看到"recovering journal"的原因**）。
3. **`iostat -x 1` 里的 `%util` 和 `await` 是虚拟机性能的关键指标**——如果 `await`（平均等待时间）在几十毫秒甚至几百毫秒，说明宿主机磁盘在排队，**加 CPU 和内存都没用**。

```bash
sudo dnf install -y sysstat
iostat -x 1 3          # 看磁盘：%util 接近 100 就是瓶颈
iotop                  # 看是哪个进程在读写（需要装 iotop）
```

### 8.6 网络栈：socket 和三次握手

**socket 是"网络版的 fd"**：程序不直接操作网卡，它让内核建一个 socket，然后像读写文件一样收发数据。

```bash
# 在 Debian 上起一个"监听"（用 nc 模拟服务端）
nc -l 9000

# 在 Rocky 上连过去
nc 192.168.80.130 9000      # 然后互相对着打字，两边都能看到 —— 这是最原始的"聊天"
```

**用 `ss` 看连接的全貌：**

```bash
ss -tlnp        # 谁在监听（LISTEN）
ss -tnp         # 已建立的连接（ESTAB）以及属于哪个进程
ss -s           # 汇总统计
```

**抓一次三次握手（最直观的网络教学）**：

```bash
# 一台机器上抓包（先装 tcpdump）
sudo dnf install -y tcpdump
sudo tcpdump -n -i any port 9000
# 另一台机器上发起连接：nc 192.168.80.130 9000
```

```text
IP 192.168.80.128.54321 > 192.168.80.130.9000: Flags [S]      ← ① SYN：我想连你
IP 192.168.80.130.9000  > 192.168.80.128.54321: Flags [S.]    ← ② SYN-ACK：收到，我也想连你
IP 192.168.80.128.54321 > 192.168.80.130.9000: Flags [.]      ← ③ ACK：好，开始
```

**从此"三次握手"不再是背书，而是你亲眼见过的东西。** 顺带你会看到 **NAT 的痕迹**：如果是从宿主机访问虚拟机，抓到的源地址是 `VMnet8` 那个地址——**这就是 [2.4](#24-nat-网络是怎么通的) 说的"NAT 会改写地址"。**

### 8.7 从虚拟机到容器：cgroups 与 namespace

**你已经会造虚拟机了，再理解容器只需要一句话**：

> **容器 = 用 namespace 让进程"看不见"外面的世界 + 用 cgroups 让它"用不了"太多资源 + 用一个镜像给它一套文件系统。**

| | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离的是什么 | **整台"硬件"**（各自有内核） | **进程的视野和配额**（共用宿主内核） |
| 启动速度 | 几十秒 | 零点几秒 |
| 资源开销 | 每个都带一套完整系统（GB 级） | 只多几个进程（MB 级） |
| 隔离强度 | 强（硬件级） | 较弱（内核漏洞会影响所有容器） |
| 能跑不同内核吗 | ✅ 能 | ❌ 不能（都用宿主内核） |
| 典型用途 | 完整系统、异构环境、强隔离 | 部署应用、微服务、CI |

**在 Rocky 上亲手验证一下（Podman 是 RHEL 系的默认容器工具，比 Docker 更适合单机）**：

```bash
sudo dnf install -y podman
podman run --rm hello-world                 # 跑一个容器，跑完自动删
podman run -it --rm alpine sh               # 进一个 Alpine 的 shell
# 在里面看看：它有自己的主机名、自己的进程树、自己的网络
hostname; ps aux; ip a; cat /etc/os-release; exit
```

**看"隔离"到底隔离了什么**：

```bash
lsns                        # 列出当前所有 namespace 及其里的进程
unshare --pid --fork --mount-proc bash   # 手工造一个"看不见外面进程"的环境
sudo systemd-cgtop          # 看 cgroup 里的资源占用（systemd 就是在用 cgroup 管服务）
cat /sys/fs/cgroup/system.slice/sshd.service/memory.max   # 服务的资源限制就在这
```

**为什么这件事对你重要？** 因为第 5.3 节讲的"Rocky 的软件太旧"在这里有了解法：**想要新版 Node、Python、数据库，用容器跑，不动系统本身。** 这也是近几年 Linux 使用方式最大的变化——**系统只负责跑容器，软件环境由镜像定义。**

### 8.8 时间：UTC、时区和虚拟机时钟

**时间的两个概念**：硬件时钟（主板上的小电池，RTC）和系统时钟（内核维护的）。

| 系统 | 硬件时钟默认存什么 | 结果 |
| --- | --- | --- |
| Windows | **本地时间**（东八区就直接存 +8） | 装双系统时容易和 Linux 打架 |
| Linux | **UTC** | 显示时按 时区 换算成本地时间 |

**这就是"装了双系统之后 Windows 时间差 8 小时"的原因**——两边对 RTC 的理解不一样。解决办法（虚拟机里不常遇到，真机双系统会遇到）：要么让 Linux 也用本地时间（`timedatectl set-local-rtc 1`，**不推荐**），要么改 Windows 注册表让它用 UTC（**推荐**）。

**虚拟机特有的时间问题**：

```bash
timedatectl                 # 看时区和是否同步
timedatectl list-timezones | grep Shanghai
sudo timedatectl set-timezone Asia/Shanghai
chronyc sources -v          # 看时间同步源（Rocky 用 chrony）
```

- **虚拟机被"挂起"后恢复，时间可能跳变**：因为挂起期间虚拟机没在跑，而宿主机的时间在走。恢复时靠 VMware Tools 和 chrony 校正。
- **VMware 的"与宿主机同步时间"**：在虚拟机设置 → 选项 → VMware Tools 里。**它对"偶尔开一次的桌面虚拟机"很方便，但如果你在虚拟机里跑数据库或做时间敏感的实验，最好关掉它，只依赖 chrony**——因为它可能让时间"往回跳"。
- **验证同步是否真的在工作**：`timedatectl` 里的 `System clock synchronized: yes`，以及 `chronyc tracking` 里的 `Leap status: Normal`。

## 9. 虚拟机进阶技巧

**这一章是"把虚拟机用出花来"的部分。** 每节都能独立看。

### 9.1 快照树怎么管理

**操作位置**：菜单 **虚拟机 → 快照**。

| 操作 | 说明 |
| --- | --- |
| 拍摄快照（Take Snapshot） | 建议**关机状态**拍（干净、体积小、恢复快）；运行中也能拍（会连内存状态一起存，**文件大很多**） |
| 恢复到快照（Revert） | **当前状态会被丢弃**，先确认没有你要留的东西 |
| 快照管理器（Snapshot Manager） | 看快照树、清理、克隆"某个快照的状态"为新虚拟机 |
| 删除快照（Delete） | **不是"删掉那台机器"**，而是"删掉存档点、把增量合并回主磁盘"——**合并大快照可能要几分钟，会占额外磁盘空间** |

**命名规范**（很重要，一周后你就忘了哪个是哪个）：

```text
01-干净基线：装完+更新+工具
02-装完 nginx 之前
03-改 SELinux 之前的实验
```

**什么时候拍**：动 `/etc` 里的关键配置前、装大软件前、做危险实验前。
**什么时候删**：实验成功并且稳定运行几天后。
**别做的事**：把快照当长期存档（[2.5](#25-快照不是备份先说结论)）。

> **一个容易忽略的坑**：虚拟机磁盘如果被设成"独立（Independent）"模式，或者磁盘在快照后被扩容过，**某些操作会不允许拍快照**，或者回滚后出现"磁盘大小不匹配"的警告。**遇到就先合并/删除旧快照，再做新操作。**

### 9.2 克隆与模板

**克隆（Clone）** = 复制出一台新虚拟机：

| 类型 | 占空间 | 特点 |
| --- | --- | --- |
| **完整克隆（Full）** | 和原机器一样大 | 完全独立，可以随便改；**推荐** |
| **链接克隆（Linked）** | 很小 | 依赖原机器的磁盘（原机器不能删！），适合"临时开几台做测试" |

**操作**：虚拟机 → 管理 → 克隆。

**"用虚拟机搭模板"的完整流程**（这是本文最实用的工作流之一）：

```text
① 装一台"母机"：最小安装 + 更新 + open-vm-tools + 你常用的工具
② 关机，克隆成"模板"（这台以后不再开机使用）
③ 需要新机器时：从模板克隆 → 开机 → 做下面这四件"去重"的事：

   sudo hostnamectl set-hostname newbox.lab     # 改主机名
   sudo rm -f /etc/machine-id && sudo systemd-machine-id-setup   # 重新生成机器 ID
   sudo rm -f /etc/ssh/ssh_host_*               # 删掉旧的 SSH 主机密钥
   sudo ssh-keygen -A                           # 重新生成（否则所有克隆机的指纹都一样）
```

**为什么必须做"去重"？**

- **`/etc/machine-id` 一样**会导致 DHCP 拿到同一个 IP、systemd 日志混在一起、某些许可证/监控工具认错机器；
- **SSH 主机密钥一样**意味着"所有机器的身份相同"——不仅不安全，你从宿主机连第二台时还会被 `known_hosts` 冲突挡住（`WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`），得手工删旧记录。

### 9.3 共享文件夹、剪贴板、分辨率

**先装工具**（两台机器分别做，Rocky 用 dnf、Debian 用 apt）：

```bash
# Rocky
sudo dnf install -y open-vm-tools open-vm-tools-desktop
# Debian
sudo apt update && sudo apt install -y open-vm-tools open-vm-tools-desktop
sudo systemctl reboot
```

**装完你会得到**：窗口缩放时分辨率自动跟随、宿主机和虚拟机之间复制粘贴、拖拽文件、时间同步。

**共享文件夹（让宿主机的一个目录出现在 Linux 里）**：

1. **虚拟机设置 → 选项 → 共享文件夹 → 总是启用** → 添加一个宿主机目录（比如 `D:\share`），名字叫 `share`；
2. 在 Linux 里挂载（**Rocky 和 Debian 命令一样**）：

```bash
mkdir -p ~/hostshare
sudo vmhgfs-fuse .host:/ /home/dev/hostshare -o allow_other -o uid=$(id -u dev) -o gid=$(id -g dev)
ls ~/hostshare          # 应该能看到 share 目录
```

3. **想看有哪些共享**：`vmware-hgfsclient`（列出共享名）。
4. **想开机自动挂载**，写进 `/etc/fstab`：

```text
.host:/    /home/dev/hostshare    fuse.vmhgfs-fuse    defaults,allow_other,uid=1000,gid=1000,nofail    0 0
```

   **`nofail` 很重要**：万一共享服务没起来，机器还能正常启动（否则可能卡在启动阶段）。

> **共享文件夹不好用怎么办？** 说实话，**在"要学 Linux"的前提下，SSH + rsync 是更好的方式**（[7.9](#79-ssh-密钥scprsync)）：更快、更可靠、更接近真实工作流。**共享文件夹只适合"偶尔从 Windows 拖个文件进去"这种场景。**

### 9.4 网络进阶：端口转发、桥接、仅主机

**场景一：只想让宿主机用固定端口连虚拟机的 SSH。**

虚拟机设置 → 网络适配器 → **NAT 设置 → 添加**：

```text
主机端口：2222        虚拟机 IP：192.168.x.128（或留空，用 DHCP 分配的）
类型：TCP             虚拟机端口：22
```

然后从宿主机连：

```bash
ssh -p 2222 dev@127.0.0.1
```

**好处**：**虚拟机 IP 变了也不影响**，你永远连 `127.0.0.1:2222`。

**场景二：让局域网里的手机/另一台电脑访问虚拟机的服务。**

虚拟机设置 → 网络适配器 → **桥接（Bridged）** → 勾选"复制物理网络连接状态" → 选对**物理网卡**（有线还是无线，选错就没网）。

- 虚拟机此时会从**你家路由器**拿 IP（和宿主机同网段）；
- 手机连同一个 WiFi 就能访问 `http://虚拟机IP:8080`；
- **注意**：虚拟机现在暴露在局域网里了，**别在上面跑有漏洞的服务**。

**场景三：搭一个完全隔离的"内网"，做网络实验。**

- 用**仅主机（Host-only）**模式，或者用**虚拟网络编辑器**新建一个自定义 VMnet（比如 VMnet2，关掉 DHCP）；
- 给几台虚拟机都接上去，手动配 IP（`nmcli` 或 `nmcli connection modify`），就得到一个"随便折腾"的网段；
- 想让它上网，就在其中一台机器上开转发 + NAT（**学 iptables/nftables、路由、DNS 的最好沙盘**）。

**查看和修改虚拟网络**：菜单 **编辑 → 虚拟网络编辑器**（需要点"更改设置"提权）。这里能看到 VMnet0（桥接）、VMnet1（仅主机）、VMnet8（NAT）的子网、DHCP 范围，也能改。

> **`VMnet8` 的网段是可以改的**，但如果和你公司的真实网段撞了（比如公司就是 `192.168.80.0/24`），会出现"有时通有时不通"的诡异现象。**遇到就先看 `ipconfig` 里 VMnet8 的网段，和真实网络冲突就改掉。**

### 9.5 嵌套虚拟化（在 Rocky 里跑 KVM/Podman）

**"嵌套虚拟化"= 在虚拟机里再开虚拟机。** 有两个需求会用到它：

1. 想在 Rocky 里装 **KVM/libvirt** 玩真·虚拟化；
2. 想在里面跑需要 KVM 加速的容器/模拟器（Android 模拟器、某些 CI）。

**开启方法**：虚拟机设置 → 处理器 → 勾选 **"虚拟化 Intel VT-x/EPT 或 AMD-V/RVI"** → 确定 → 重启虚拟机。

验证：

```bash
grep -o -m1 -E 'vmx|svm' /proc/cpuinfo | head -1     # 有输出就说明 CPU 虚拟化暴露给虚拟机了
ls /dev/kvm                                          # 存在就能用 KVM
sudo dnf install -y libvirt virt-install             # 想玩 libvirt 就装
```

**限制（很重要）**：

- **宿主机如果因为 Hyper-V/WSL2 处于"Host VBS 模式"，嵌套虚拟化不可用**（[10.1](#101-虚拟化相关的报错)）；
- 嵌套会带来明显性能损失（一次内存访问可能要过两层页表）；
- 宿主机和客户机 CPU 特性不匹配时，虚拟机可能起不来（换台机器打开同一个虚拟机常见）。

### 9.6 性能优化清单

**按"性价比"从高到低排：**

| 做法 | 效果 | 说明 |
| --- | --- | --- |
| **虚拟机磁盘放在 NVMe/SSD 上** | ⭐⭐⭐⭐⭐ | 磁盘 IO 是虚拟机最大的瓶颈。**别放机械盘、别放同步网盘目录** |
| **给宿主机留够内存** | ⭐⭐⭐⭐⭐ | 让宿主机去用页面文件（swap）= 一切都会变慢 |
| **CPU 不超过宿主物理核数** | ⭐⭐⭐⭐ | 2～4 核通常最好；给 8 核不会更快，只会让两边抢 |
| **把杀毒软件的实时扫描排除虚拟机目录** | ⭐⭐⭐⭐ | Windows Defender：设置 → 病毒和威胁防护 → 排除项 → 添加 `D:\vm` |
| **关掉用不到的设备**（声卡、打印机、摄像头） | ⭐⭐ | 减少中断和驱动开销 |
| **磁盘预分配（立即分配所有空间）** | ⭐⭐⭐ | 快，代价是当场占满 40 GB |
| **慎开 3D 加速** | ⭐⭐ | 桌面流畅靠它；但驱动/版本不匹配时会黑屏、花屏 |
| **虚拟机里关掉不需要的服务** | ⭐⭐ | 例如 KDUMP、不需要的数据库 |
| **定期"压缩"虚拟磁盘** | ⭐⭐ | 回收已删除文件占的空间（见下） |

**"磁盘占用只增不减"怎么救？** 先在 Linux 里把空闲块标记出来，再在 VMware 里压缩：

```bash
# Linux 里（需要 open-vm-tools）
sudo vmware-toolbox-cmd disk list
sudo vmware-toolbox-cmd disk shrink /        # 需要足够空闲空间，过程较慢
# Debian 也可以先 fstrim：
sudo fstrim -av
```

然后 **虚拟机 → 设置 → 硬盘 → 压缩（Compact）**。

> **反过来，有个"看起来像故障"的正常现象**：虚拟机里 `df -h` 显示只用了 8 GB，宿主机上文件夹却有 25 GB。**这就是精简置备的代价**（[3.2](#32-虚拟磁盘vmdk-是怎么回事)）。**想回收就按上面的流程做，不做也不影响使用。**

### 9.7 磁盘扩容的完整流程

**扩容分两处，两处都要做，少一处都不生效：**

```text
① 虚拟机层面：把 vmdk 变大（VMware 界面里操作）
② 客户机层面：让分区 + LVM + 文件系统认识到变大了（Linux 里操作）
```

**① 在 VMware 里**：关机 → 虚拟机设置 → 硬盘 → **扩展** → 填新容量 → 确定。**只能变大，不能变小。**

**② 在 Linux 里**：完整命令在 [7.6](#76-磁盘与-lvm-扩容虚拟机最爽的练习)，这里补两个要点：

- **如果分区表是"整块盘一个分区"且用了 LVM**：`growpart` → `pvresize` → `lvextend` → `xfs_growfs`（顺序不能乱）；
- **如果没开 LVM（直接一个 XFS/ext4 分区）**：`growpart` → `xfs_growfs /`（ext4 用 `resize2fs /dev/nvme0n1p2`）。

**想缩小怎么办？** 文件系统层面 XFS 直接不支持；ext4 能缩但要求先卸载。**实际做法是"曲线救国"**：

```text
新建一块小一点的虚拟磁盘 → 格式化和挂载 → rsync -a 把数据搬过去 →
改 /etc/fstab → 重启验证 → 删掉旧磁盘
```

**在虚拟机的世界，"重做一遍"通常比"缩回去"更省事。**

### 9.8 导出、导入与迁移

| 需求 | 用什么 | 说明 |
| --- | --- | --- |
| 拷给别人（对方也用 VMware） | **导出 OVF（`.ova` 单文件）** | 文件 → 导出为 OVF。它把配置 + 磁盘打成一个包，换电脑不折腾 |
| 备份到移动硬盘 | **直接复制整个文件夹** | 关机后复制；**目标盘要放得下（可能是几十 GB）** |
| 换到 VirtualBox / 云 | **导出 OVF 再导入** | 通用格式；但 VMware Tools 要换成对方那套（VirtualBox 用 Guest Additions） |
| 变成真机 | 复杂，不建议 | 驱动、引导、授权都是问题；**真机装机有[专门的教程](/posts/debian-13-sudo-opencode-setup/)** |
| 自动化管理 | `vmrun` / `vmcli` | 25H2 之后还新增了 `vmcli` 和 REST API。例：`vmrun start "D:\vm\rocky10\rocky10.vmx" nogui` |

**导出的 OVA 有多大？** 约等于"实际占用 + 一点开销"。**导出前先清理**（删日志、`dnf clean all`、`vmware-toolbox-cmd disk shrink`），能小很多。

**一个务实的三层备份策略**（虚拟机玩家的版本）：

```text
第一层：快照        ← 动手前的存档点（同盘，快，但不防硬件故障）
第二层：克隆/复制文件夹到另一块盘   ← 防误删、防文件夹损坏
第三层：导出 OVA 放到移动硬盘/NAS    ← 防硬盘坏、防勒索软件（离线副本）
```

## 10. 报错排查手册（按现象找答案）

**按现象查，别按"你觉得的原因"查。** 这一章的每一条都是"现象 → 原因 → 怎么办"。

> **查之前先做两件事**：
>
> 1. **确认你在哪台机器上**（[开头的第 1 条](#先看这张地图你现在该去哪一节)）。在 Windows 的 PowerShell 里敲 `systemctl`，得到的必然是"无法将 systemctl 项识别为..."——那不是故障。
> 2. **读报错本身。** 尤其是 Linux 的报错：它常常直接把答案写在里面（`Permission denied`、`No space left on device`、`Connection refused`、`command not found`）。**先把报错读三遍，再来查表。**

### 10.1 虚拟化相关的报错

**① 开虚拟机时提示"VMware Workstation 与 Hyper-V 不兼容"，或者虚拟机慢得离谱**

原因：Windows 的 Hyper-V / WSL2 / 沙盒 / 内核隔离（内存完整性）正在占用 CPU 虚拟化，Workstation 只能退到 **Host VBS 模式**（借 Windows Hypervisor Platform 跑）。

怎么办（按推荐顺序）：

1. **就这样用**：能跑，只是慢一些，而且**不能用嵌套虚拟化**。只是学 Linux 的话完全够用。
2. **想让它跑得快**：关掉那些功能再重启（**注意：关掉 WSL2 后你的 WSL 就用不了了**）：
   - `Win + R` → `optionalfeatures` → 取消 **Hyper-V**、**虚拟机平台**、**Windows 沙盒**；
   - **Windows 安全中心 → 设备安全性 → 内核隔离 → 内存完整性 → 关**；
   - 企业电脑可能还有 Credential Guard/Device Guard，由 IT 策略控制，你自己关不掉。
3. 关完重启，再开虚拟机，Workstation 会用 VMware 自己的 hypervisor（**最快**）。

**② 提示 "VMware Workstation 在此主机上不支持嵌套虚拟化" 或 "VT-x 已禁用"**

```text
此主机支持 Intel VT-x，但 Intel VT-x 处于禁用状态。
```

- **你 BIOS 里没开虚拟化** → 回 [1.1](#11-开始前先确认三件事) 打开；
- **你开了虚拟机，但宿主机的虚拟化还没生效** → 关机、**彻底断电重启**（不是重启，是关机再开，有些主板要这样才应用设置）；
- **你正处在 Host VBS 模式还想开嵌套虚拟化** → 不支持，二选一。

**③ 装完 VMware 之后，Windows 里没有 `VMnet1` / `VMnet8` 网卡**

在 PowerShell（**管理员**）里修复：

```powershell
# 让 VMware 重置虚拟网络
& "C:\Program Files (x86)\VMware\VMware Workstation\vnetlib64.exe" -- stop
& "C:\Program Files (x86)\VMware\VMware Workstation\vnetlib64.exe" -- uninstall
& "C:\Program Files (x86)\VMware\VMware Workstation\vnetlib64.exe" -- install
& "C:\Program Files (x86)\VMware\VMware Workstation\vnetlib64.exe" -- start
```

或者直接用菜单 **编辑 → 虚拟网络编辑器 → 更改设置 → 还原默认设置**（最省事，会重建所有虚拟网卡）。

**④ "无法打开虚拟机：该文件已被锁定" / "虚拟机似乎正在使用中"**

- 上次 VMware 崩了，进程还在：打开**任务管理器**，结束所有 `vmware-vmx.exe`、`vmware.exe`；
- 还存在 `.lck` 目录：**确认虚拟机没在跑**之后，删掉虚拟机文件夹里的 `*.lck` 文件夹和目录；
- 提示"我已移动/我已复制"时选 **"我已复制该虚拟机"**（见 [3.5](#35-为什么虚拟机不能直接拷给别人用)）。

### 10.2 装系统阶段的报错

**① 一开机就报 `Fatal glibc error: CPU does not support x86-64-v3`**

**原因**：你装的是 Rocky 10 / RHEL 10 / AlmaLinux 10 这一代，它们要求 x86-64-v3 指令集（AVX2 那一代），而**虚拟机看到的 CPU 没有暴露这些指令**——要么宿主 CPU 太老（2013 年以前），要么虚拟机软件版本太旧（老版本的 VirtualBox 就有这个毛病，升级到最新版即可）。

**怎么办**：

1. 宿主 CPU 是 2013 年以后的：**升级 VMware 到最新版**（本文用的版本没这个问题）；用 VirtualBox 的话升级到最新；
2. 宿主 CPU 确实老：**改装 Rocky Linux 9.8**（[1.4](#14-第-3-步下载-rocky-linux-的-iso) 的那张选择表）；
3. 顺手记一个通用判断法：**"装得上"和"装最新"是两回事，先保证能跑起来。**

**② 安装器里"安装目的地"是空的 / 提示 "No disks found"**

- 虚拟机确实没硬盘 → 回 [1.5](#15-第-4-步新建虚拟机向导每一屏) 检查第 12～13 屏；
- **控制器类型不兼容**（少见）：编辑虚拟机设置，把磁盘控制器换成 `SATA` 或 `LSI Logic SAS` 再试；
- **磁盘被快照/独立模式搞乱了**：把磁盘设为"独立-持久"或删掉快照再试。

**③ 装完重启进不去，或者直接又进了安装器**

按顺序查：

1. **引导顺序**：虚拟机设置 → 选项 → 高级 → 固件类型对不对（你按 UEFI 装的，就不能选 BIOS）；BIOS/UEFI 里的启动顺序是否把硬盘排在第一；
2. **ISO 还挂着**：把 CD/DVD 的"启动时连接"取消（[1.8](#18-第-7-步从-windows-用-ssh-连进虚拟机) 结尾）；
3. **Secure Boot 导致的引导校验失败**（2026 年常见，见 [3.3](#33-uefigptsecure-boot-是什么)）：先在虚拟机设置里**临时关掉 Secure Boot** 验证；确认是它，就把 Workstation 更新到 26H1u1 或更高（它带 PK 自动修复）；
4. **手动分区时漏了 `/boot/efi`**（UEFI 机器）：启动安装器进救援模式补一个，或者干脆重装（**有快照/重装只要二十分钟，别在这里耗两小时**）。

**④ 安装过程中报错 "There was a problem reading data from the CD-ROM / ISO"**

**几乎 100% 是 ISO 下载坏了。** 回 [4.1](#41-iso-是什么校验和为什么必须做) 校验哈希、重下。**别怀疑硬盘、别怀疑内存，先校验。**

**⑤ 安装器界面黑屏 / 花屏 / 分辨率奇怪**

- 虚拟机设置 → 显示 → **取消"加速 3D 图形"**；
- 显存调到 8 MB 以上（4K 屏幕给 16～32 MB）；
- 还不行就在引导菜单里选 `Troubleshooting → Install in basic graphics mode`。

**⑥ 键盘鼠标在安装器里没反应**

- 鼠标：点一下虚拟机窗口内部让它"抓住"鼠标；**Ctrl + Alt** 放出来；
- 键盘完全无反应：虚拟机设置 → 选项 → 高级 → 检查"增强型键盘驱动"是否安装；或先把 VMware 更新到最新版。

### 10.3 登录与系统阶段的报错

**① 忘记密码（root 或普通用户）**

**这是虚拟机最不用担心的问题**（真机上要拆硬盘），因为你有"控制台"。在 GRUB 菜单上操作：

```text
① 开机，在 GRUB 菜单出现的瞬间按 ↑/↓ 让它停下来（默认几秒就过去了）
② 选中要启动的内核，按 e 进入编辑
③ 找到以 linux 开头的那一行（可能显示成 linux /vmlinuz-...）
④ 在这一行末尾加一个空格，然后写：   rd.break
⑤ 按 Ctrl + X 启动
⑥ 进入紧急 shell 后，依次执行：

   mount -o remount,rw /sysroot
   chroot /sysroot
   passwd root          # 改 root 密码；改普通用户就写 passwd dev
   touch /.autorelabel  # 让 SELinux 重新打标签（不改这一条可能登录不进去）
   exit
   exit                 # 再 exit 就会继续启动

⑦ 用新密码登录
```

**注意**：这个方法能做到，意味着"**任何能物理接触机器的人都能重置你的密码**"。所以服务器的物理安全很重要——**这也是磁盘加密（LUKS）存在的意义。**

**② 开机卡在 `emergency mode` / `You are in emergency mode`**

**九成是你改坏了 `/etc/fstab`**（比如加了块不存在的磁盘、UUID 抄错）。

```text
① 在提示处输入 root 密码进入紧急 shell
② mount -o remount,rw /
③ vi /etc/fstab      # 把可疑的那一行前面加 # 注释掉
④ 以后要安全地测试 fstab，记住这条命令：sudo mount -a   ← 它会把 fstab 里的条目全挂一遍
   报错就说明 fstab 有问题，修完再重启
⑤ systemctl reboot
```

**③ 图形界面起不来，只有黑屏或文本登录**

```bash
# 在文本界面登录后：
systemctl get-default                 # 看默认目标是 graphical 还是 multi-user
sudo systemctl set-default graphical.target
sudo systemctl start gdm              # 手动起图形登录管理器

# 看它为什么起不来：
systemctl status gdm
journalctl -b -u gdm -n 50
journalctl -b -p err                  # 本次开机的所有错误
```

最常见的原因：装驱动（尤其是 NVIDIA）之后没配好、显存/3D 加速不兼容（[10.2 ⑤](#102-装系统阶段的报错)）、磁盘满了。

**④ 中文显示成方块、输入法打不出中文**

- 方块 = **缺字体**：`sudo dnf install -y wqy-zenhei-fonts wqy-microhei-fonts`（Rocky）/ `sudo apt install -y fonts-wqy-zenhei`（Debian）；
- 打不出中文 = **没装输入法**：GNOME 用 `ibus-libpinyin`：

```bash
sudo dnf install -y ibus ibus-libpinyin
# 装完注销重新登录，然后在 设置 → 键盘 → 输入源 里添加"中文（智能拼音）"
```

**⑤ 系统里时间和宿主机差 8 小时**

回 [8.8](#88-时间utc时区和虚拟机时钟)：检查时区（`timedatectl`）、检查 VMware 的时间同步选项、`sudo timedatectl set-timezone Asia/Shanghai`。

### 10.4 网络相关的报错

**① 虚拟机里 `ip -4 addr show` 没有地址**

```bash
nmcli device status            # 看网卡状态：connected / disconnected
nmcli device connect ens33     # 手动连
nmcli connection show          # 看有哪些连接配置
sudo nmcli connection up "有线连接 1"
```

如果 `nmcli` 显示网卡是 `unmanaged`，说明 NetworkManager 没接管它——检查是不是手工改过 `/etc/NetworkManager/conf.d/` 或 `/etc/sysconfig/network-scripts/`。

**② Windows 上 `ssh dev@IP` 连不上（Connection timed out / refused）**

**按这条链查，顺序别乱：**

```text
① 虚拟机里服务在吗      systemctl status sshd        → 不是 running 就 enable --now
② 虚拟机里在听哪个地址  ss -tlnp | grep :22          → 应该听 0.0.0.0:22 或 *:22
③ 虚拟机的 IP 变了吗    ip -4 addr show              → 变了就用新地址（或做端口转发，见 9.4）
④ 虚拟机防火墙放行了吗  sudo firewall-cmd --list-all → services 里应有 ssh
⑤ 宿主机这边网卡通吗    ipconfig                 → VMnet8 应该是 192.168.x.1
⑥ 宿主机能 ping 通吗    ping 192.168.x.128
⑦ ping 通但 22 端口不通 → 回到 ④；ping 不通 → 虚拟网络问题（编辑 → 虚拟网络编辑器 → 还原默认设置）
```

**③ 能 `ping 1.1.1.1`，但 `ping www.baidu.com` 报"未知的名称或服务"**

**这是 DNS 问题，不是网络问题**（[7.7](#77-网络排查的一条链)）。对虚拟机来说最常见的原因是：**宿主机在 NAT 模式下把 DNS 转发给了虚拟网络，但宿主机的 DNS 本身有问题**（比如挂了 VPN、改了 hosts、公司 DNS 需要认证）。

```bash
cat /etc/resolv.conf
# 临时验证：直接指定一个公共 DNS
sudo sh -c 'echo "nameserver 223.5.5.5" > /etc/resolv.conf'
# 想持久：用 nmcli 改连接的 DNS
sudo nmcli connection modify "有线连接 1" ipv4.dns "223.5.5.5,1.1.1.1"
sudo nmcli connection up "有线连接 1"
```

**④ 改成桥接后虚拟机彻底没网**

- **选错了物理网卡**：你走 WiFi，却选了有线网卡。虚拟机设置 → 网络适配器 → 桥接 → **配置适配器** → 选当前正在用的那张；
- **公司/校园网限制**：很多企业网络**只允许一个 MAC 上网**（802.1X 认证），桥接的虚拟机拿不到 IP。**换回 NAT。**

**⑤ 克隆出来的机器和原机器抢 IP、SSH 指纹报错**

见 [9.2](#92-克隆与模板)：改主机名、重建 `machine-id`、重建 SSH 主机密钥。已经冲突的，先在 VMware 里把冲突的那台断网（网络适配器改成"仅主机"），修好再切回来。

**⑥ `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`**

你重装过那台虚拟机（或克隆冲突），主机指纹变了。**如果确认是你自己干的**，删掉旧记录：

```powershell
# Windows
ssh-keygen -R 192.168.80.128
```

```bash
# Linux
ssh-keygen -R 192.168.80.128
```

**⑦ `Permission denied (publickey)`**

- 公钥没装进 `~/.ssh/authorized_keys`（[7.9](#79-ssh-密钥scprsync)）；
- 权限不对：`~/.ssh` 必须 700、`authorized_keys` 必须 600、家目录不能是 777；
- 服务器端配置禁止了密码登录，而你的密钥又不对：去虚拟机控制台看 `/var/log/secure`（Rocky）或 `/var/log/auth.log`（Debian）。

### 10.5 磁盘与空间相关的报错

**① 宿主机 C 盘/虚拟机所在盘满了**

```powershell
# 看看是谁占的
Get-ChildItem D:\vm -Recurse -File | Sort-Object Length -Descending | Select-Object -First 20 FullName, @{n='GB';e={[math]::Round($_.Length/1GB,2)}}
```

常见原因：**虚拟机磁盘自然增长**、**快照积累**、**`.vmem` 挂起文件**（挂起状态下的内存镜像，有几个 G）、**日志**。处理：删掉不要的快照、压缩磁盘（[9.6](#96-性能优化清单)）、把挂起改成关机。

**② 虚拟机里 `df -h` 显示满，但 `du` 加起来没那么多**

**有进程还占着已删除的文件**（[7.6](#76-磁盘与-lvm-扩容虚拟机最爽的练习)）：

```bash
sudo lsof +L1 | head            # 找出"已删除但仍被打开"的文件
sudo systemctl restart 那个服务   # 让它释放
```

**③ `No space left on device`，但 `df` 显示还有空间**

**inode 用尽了**（小文件太多）：

```bash
df -i                            # 看 IUse% 那一列
```

处理：找出海量小文件的目录（常见于 `/var/spool`、缓存目录、日志目录）清理掉。

**④ 扩容后 `df` 还是老的大小**

**层次漏了**（[7.6](#76-磁盘与-lvm-扩容虚拟机最爽的练习) 那五层）。按顺序重新走一遍：`lsblk`（分区变大了吗）→ `pvs`/`vgs`（LVM 知道吗）→ `lvs`（逻辑卷扩了吗）→ `df`（文件系统扩了吗）。**哪一层数字没变，就是卡在哪一层。**

**⑤ 删快照时报"空间不足"或一直卡着**

删除快照 = **把增量合并回主磁盘**，合并过程需要额外空间。腾出空间（删别的快照、清理宿主机磁盘）再删；**合并期间千万不要强制关机。**

### 10.6 性能与卡顿

| 现象 | 先查什么 | 常见原因 |
| --- | --- | --- |
| 整个虚拟机都慢 | 宿主机任务管理器：CPU/内存/磁盘 | 宿主内存不足、宿主机磁盘 100% 占用（杀软扫描、Windows 更新） |
| 桌面卡、窗口拖动掉帧 | 虚拟机设置 → 显示 | 3D 加速没开或驱动不匹配；显存太小；宿主 GPU 驱动老 |
| 打开文件/编译慢 | `iostat -x 1` 的 `await`、`%util` | 磁盘 IO 瓶颈（虚拟机盘在机械盘/网盘同步目录里） |
| 网络慢 | `ping` 延迟、`iperf3` | 桥接走了错误的网卡；宿主 WiFi 不稳 |
| 挂起恢复后异常 | 时间、网络、剪贴板 | 恢复后时间跳变；网卡需要 `nmcli connection up` |
| 越用越慢 | 快照数量、磁盘占用 | 快照链太长（每次读都要穿透多层）→ 删快照 |

**一条万能的性能判断法**：**在宿主机上打开任务管理器，看资源监视器。**

- 宿主 **CPU 满** → 虚拟机核给多了，或者有程序在跑满；
- 宿主 **内存接近满** → 减少虚拟机内存或关掉别的程序（**这一条最常见**）；
- 宿主 **磁盘活动时间 100%** → 磁盘是真瓶颈，换到 SSD、减少同时运行的虚拟机。

### 10.7 提问与自救的正确姿势

**先分清"我到哪一步了"**，然后按这三步走：

**第一步：确定是哪一层的问题。**

```text
① 是 VMware 本身的问题吗？      → 看 vmware.log、看宿主机事件
② 是虚拟机硬件/固件的问题吗？    → 能不能进 GRUB？能不能进救援模式？
③ 是 Linux 系统的问题吗？        → 能不能进系统？journalctl / systemctl status 说什么？
④ 是某个服务/应用的问题吗？      → 服务日志、配置文件、防火墙、SELinux
```

**第二步：搜索时用"报错原文的关键句"，不要抄整个屏幕。**

- ✅ 搜 `Fatal glibc error: CPU does not support x86-64-v3`
- ✅ 搜 `firewalld add port permanent not working`
- ❌ 搜 `虚拟机装不上怎么办 我的是联想的电脑`

**第三步：提问时给全下面六样。**

1. **你在哪台机器上**（Windows 宿主机 / Rocky 虚拟机 / Debian 虚拟机）；
2. **你执行了什么命令**（原样复制）；
3. **完整的报错**（别只截一小块）；
4. **关键配置**（`vmware.log` 末尾、`/etc/fstab`、网卡配置、`systemctl status` 输出）；
5. **你做过的变更**（"我刚改过 fstab"这种信息价值极高）；
6. **你已经试过什么、结果如何**。

**最后一条经验还是那句：一次只改一个地方。** 同时改防火墙、SELinux、网络配置，出问题时你根本不知道是谁的锅——**这也是为什么要在动手前拍快照。**

## 11. 名词小词典

| 词 | 一句话解释 |
| --- | --- |
| **宿主机（host）** | 跑虚拟机的这台真电脑（你的 Windows） |
| **客户机 / 虚拟机（guest / VM）** | 被跑起来的那个"假电脑" |
| **Hypervisor** | 管理虚拟机的软件层（Type-1 装在硬件上，Type-2 装在系统上） |
| **VT-x / AMD-V** | CPU 提供的硬件虚拟化功能，虚拟机性能的关键 |
| **嵌套虚拟化** | 在虚拟机里再跑虚拟机（要开 VT-x/EPT 透传） |
| **vCPU** | 分配给虚拟机的虚拟 CPU 核心 |
| **vmdk / vmx / nvram** | 虚拟硬盘 / 虚拟机配置 / 虚拟固件设置，都是文件 |
| **快照（Snapshot）** | 某个时刻的状态存档点，靠"写时复制"实现；**不是备份** |
| **克隆 / 链接克隆** | 复制虚拟机；链接克隆共享原磁盘，省空间但依赖原机 |
| **OVF / OVA** | 虚拟机的通用交换格式（OVA 是单文件打包），跨软件迁移用它 |
| **VMware Tools / open-vm-tools** | 客户机里的增强驱动：分辨率、剪贴板、时间同步、共享文件夹 |
| **vmnet0 / vmnet1 / vmnet8** | 桥接 / 仅主机 / NAT 用的虚拟交换机 |
| **NAT / 桥接 / 仅主机** | 三种虚拟网络模式：能上网但隐身 / 像独立电脑 / 只和宿主通 |
| **ISO** | 光盘的镜像文件，装系统用；**不是压缩包** |
| **校验和（hash）** | 文件的指纹，用来确认下载没坏 |
| **UEFI / BIOS** | 主板固件的两代；UEFI 配 GPT + EFI 分区 |
| **Secure Boot** | UEFI 的安全启动：只允许有签名的引导程序 |
| **GPT / MBR** | 两种分区表格式；GPT 是现代格式 |
| **分区 / 文件系统 / 挂载点** | 盘上的一段空间 / 里面怎么组织文件 / 接到目录树的哪个位置 |
| **LVM（PV/VG/LV）** | 硬盘与文件系统之间的抽象层，能在线扩容 |
| **XFS / ext4** | 两种文件系统；XFS 不能缩小，ext4 能 |
| **swap** | 内存不够时的"溢出区"，也是休眠用的地方 |
| **fstab** | `/etc/fstab`，写"开机时自动挂载什么"的文件 |
| **inode** | 文件系统里描述一个文件的元数据结构；**inode 用尽也会"写不进去"** |
| **页缓存（page cache）** | 内核拿空闲内存缓存文件内容，需要时让出 |
| **runlevel / target** | 系统的运行级别；现代 systemd 用 `multi-user.target`（文本）、`graphical.target`（图形） |
| **systemd** | 1 号进程，负责启动和管理所有服务 |
| **unit** | systemd 的配置单位（`.service`、`.timer`、`.target`…） |
| **journalctl** | 看 systemd 统一日志的命令 |
| **SELinux / AppArmor** | 两种强制访问控制：RHEL 系用 SELinux（标签），Debian 系用 AppArmor（profile） |
| **firewalld / nftables / ufw** | 防火墙的几种管理方式：Rocky 默认 firewalld，Debian 默认空规则，ufw 是友好的前端 |
| **rpm / deb** | 两种软件包格式 |
| **dnf / apt** | 两种包管理器（还有 `yum` 这个老名字，现在是 dnf 的别名） |
| **仓库（repo）** | 存放软件包的服务器 |
| **EPEL** | 给 RHEL 系补充常用软件的社区仓库 |
| **ELF** | Linux 上的可执行文件格式（对应 Windows 的 PE/`.exe`） |
| **动态链接 / `.so`** | 程序启动时才去加载共享库（对应 Windows 的 `.dll`） |
| **系统调用（syscall）** | 用户程序请求内核服务的唯一入口 |
| **用户态 / 内核态** | CPU 的两种特权级别（Ring 3 / Ring 0） |
| **fd（文件描述符）** | 内核给"打开的东西"发的编号，"一切皆文件"的接口 |
| **/proc、/sys** | 内核暴露出来的"伪文件系统"，读它们就是在问内核 |
| **OOM killer** | 内存耗尽时内核挑一个进程杀掉 |
| **OOM / RSS / VSZ** | 实际占用物理内存 / 申请的虚拟内存（VSZ 很大不代表真占内存） |
| **socket / 端口** | 网络通信的端点 / 一台机器上区分不同服务的编号 |
| **namespace / cgroup** | 容器隔离视野 / 限制资源的两大内核机制 |
| **Podman / Docker** | 容器工具；Podman 是 RHEL 系默认（无守护进程、可 rootless） |
| **chrony** | RHEL 系的时间同步服务（Debian 常用 systemd-timesyncd） |
| **UTC / RTC** | 世界统一时间 / 主板硬件时钟；Windows 存本地时间、Linux 存 UTC |

## 12. 最后对照一遍，以及接下来学什么

### 12.1 从上一篇搬过来的知识，在 Linux 里叫什么

**如果你看过[上一篇 C 语言环境搭建](/posts/vscode-mingw-c-setup/)，这张表会让你觉得"其实没换多少东西"：**

| Windows 上（上一篇） | Linux 上（这一篇） |
| --- | --- |
| `C:\` 盘符、`\` 分隔 | `/` 根目录、`/` 分隔 |
| `C:\mingw64\bin` 加进 PATH | 一样有 PATH；命令装在 `/usr/bin`、`/usr/local/bin` |
| `gcc.exe`、`g++`、`gdb.exe` | `gcc`、`g++`、`gdb`（同一个 GCC 家族，参数一样） |
| `.exe` 可执行文件 | ELF 文件（可执行位 `chmod +x`） |
| `.dll` 动态库 | `.so` 共享库 |
| 任务管理器看进程 | `top` / `htop` / `ps` |
| 服务（services.msc） | `systemctl` + unit 文件 |
| 注册表 | 几乎一切都在 `/etc` 下的文本文件里 |
| `.zip` / Bandizip | `tar` / `gzip` / `xz`（Linux 世界的主流是 `.tar.gz`） |
| VS Code 三个 json | `/etc` 下的各种配置文件（格式不同，本质一样） |
| 环境变量图形界面 | `export`、`~/.bashrc`、`/etc/profile.d/` |
| 中文乱码（GBK vs UTF-8） | 现代 Linux 一律 UTF-8，**反而更省心** |
| `where.exe gcc` | `which gcc`、`type -a gcc` |
| PowerShell / cmd | `bash`（还有 zsh、fish） |

**一句话：你在上一篇学到的那些概念（PATH、编译四阶段、动态库、配置文件），在 Linux 上一个都没浪费。**

### 12.3 接下来学什么（八周路线）

| 周 | 学什么 | 用虚拟机怎么练 |

### 12.4 三个小练习（检验你是不是真的会了）

1. **搭一个"两台机器才能完成"的服务**：在 Rocky 上装 Nginx 和 MariaDB，在 Debian 上用浏览器/`curl` 访问 Rocky 的网页，网页内容从数据库里读。**做完这一套，你就把包管理、服务、防火墙、SELinux、网络五块知识串起来了。**
2. **给 Rocky 加一块 20 GB 的虚拟硬盘并挂到 `/data`**：分区 → 格式化（XFS）→ 写进 `/etc/fstab`（用 **UUID**，不是设备名）→ `mount -a` 验证 → 重启确认自动挂载。**注意：写 fstab 前先拍快照，写错了会进 emergency mode（[10.3 ②](#103-登录与系统阶段的报错)）。**
3. **克隆一台机器并"去重"**：从 Rocky 的干净基线克隆一台 `rocky-node2`，改主机名、重建 `machine-id` 和 SSH 主机密钥，然后让两台机器互相 `ping`、互相 `ssh`。**这个练习做完，你就有了一个可以随便折腾的多机环境。**

**写在最后。**

上一篇结束时，你手里多了一套"编辑器 + 编译器 + 调试器"的通用认知。这一篇结束时，你手里多的是**两台可以随便搞坏的 Linux 机器**——而这恰恰是最值钱的部分：**学 Linux 最大的障碍从来不是难度，而是"不敢动"**。怕删错文件、怕配坏网络、怕把公司的服务器搞挂。

虚拟机把这个恐惧直接拿掉了。你可以把 `/etc` 删掉、可以把网卡配成砖、可以让内核 OOM 杀掉所有进程，代价只是"回滚一个快照，或者重装二十分钟"。

**所以别只读，去把它弄坏。** 记住那三句话：

- **报错要读最后几行、读第一处 error**——报错不是骂你，是线索；
- **一次只改一个地方**——这样你永远知道是谁的锅；
- **动手之前先拍快照**——然后你就可以放心大胆地试。

等你哪天在真服务器上敲下第一条命令、并且发现"和我虚拟机里做的一模一样"的时候，这一篇的目的就达到了。
