# maimaiDX HDD 启动研究笔记

> 研究快照时间：2026-09-18（Asia/Shanghai）
> 目标：把 `fragrance.moe/intro` 的流程、Evilleaker 手册现有内容，以及上游项目源码、tag、release、issue/PR 中与 maimai DX、SDEZ、SDGB、segatools、AquaMai、Mercury 有关的信息合并成一套可执行、可核验的资料。

## 0. 先给结论

1. 原教程的核心技术路线是：**自备合法游戏包 → 解包 `.app`/`.opt` → 取出 `Package` → 放入 segatools、MelonLoader、AquaMai → 配置 `amfs`/`option`/`appdata`、网络、键位、读卡器、触摸和 VFD → 启动 `amdaemon.exe` 后再启动 `sinmai.exe`**。
2. SDEZ 和 SDGB 的主体启动流程相同，但**区服身份、DNS 域名、keychip 区域、游戏数据版本、AquaMai 兼容边界**不同。SDGB 不能照抄一份只面向最新 SDEZ 的 AquaMai 配置后期待全功能工作。
3. 截至本笔记日期，segatools 上游最新正式 release 是 `2026-04-06`；源码 `develop` 在 2026-09 还有未发布更新。原教程链接的是 `2025-11-04`，不是当前最新版。
4. AquaMai 当前仓库没有 GitHub Release，只有 tag 和 MuNET 构建分发。公开版本配置在本次观测中同时列出了 `v1.5.4` release、`1.9.4-gb68f85f` slow 和 `1.9.5-g381a498` CI；没有一个“SDGB 专用”官方通道。
5. 上游 AquaMai 的构建参考包长期只针对 SDEZ，且当前构建使用新版 SDEZ 的 `Assembly-CSharp.dll` / `AMDaemon.NET.dll`。因此，“SDGB 只能用旧版 AquaMai”的可靠工程化表述应当是：**SDGB 应使用曾经针对旧版本验证过的 AquaMai 线，不要默认把最新 SDEZ CI 构建当作全功能 SDGB 构建**。
6. 最保守的官方稳定点曾是 `v1.5.4`（2025-08-26 发布配置）。目前能查到的、明确包含 SDGB 实测记录的较新历史点是 `v1.7.5`：PR #99 的合并提交包含在 `v1.7.5` 中，PR 正文明确写了“测试于 SDGB151+EZ156+160”。但这只是模块级测试，**不等于 v1.7.5 的全功能兼容承诺**。
7. `v1.8.0` 引入了名为 Evergreen 的 MuMod 自动更新器；它会从网络拉取 AquaMai 并按 `slow`/`ci` 通道安装。SDGB 若需要冻结旧版，必须避免让自动更新器把已验证的旧 DLL 覆盖成最新 CI 构建。
8. `v1.9.x` 及当前源码已包含面向 SDEZ 1.65/1.70 的阈值、字段和协议处理。SDGB 1.51 使用这些功能时，至少会和 `[EnableGameVersion]` 门槛、缺失类型/字段、旧 Unity/Mono、旧 MelonLoader 四类问题发生冲突。
9. `Mercury` 和 maimaiDX 的启动链路没有直接关系。segatools 里的 `mercuryhook`/`mercuryio` 是 WACCA 的 hook 和 IO，不是 maimai DX 的启动器或 Mercury 服务器。不要把 `dist/mercury/` 当作 maimai 配置模板。
10. 本笔记不提供 HDD、`.app`、`.opt`、ICF、密钥、泄露 keychip/PCB、服务器凭据或绕授权的下载/步骤。第三方工具的开源许可证只覆盖工具代码，不覆盖 SEGA/Wahlap 的游戏程序、数据、密钥或在线服务。

## 2. 术语和组件边界

| 名称 | 作用 | 一手来源 |
| --- | --- | --- |
| `SDEZ` | maimai DX 日服/SEGA 国际体系使用的 title/game ID | segatools `mai2hook` 默认 game ID；AquaMai `ConstParameter.GameIDStr` |
| `SDGB` | 中国服/舞萌 DX 使用的 title/game ID | AquaMai PR #99 使用 `SDGB151` 表述；服务器和 keychip 配置必须与目标区服一致 |
| `.app` | SEGA fscrypt/APP 容器，通常是完整游戏版或增量版 | `fsdecrypt`、`unsegaREBORN` README |
| `.opt` | Option/追加数据容器，通常包含 `Axxx` 等数据目录 | 同上 |
| `amdaemon.exe` | AM Daemon：启动、网络、板卡、认证、I/O 的守护进程 | segatools `launch.bat`、AquaMai 相关说明 |
| `Sinmai.exe` | Unity 游戏主程序 | segatools `launch.bat` |
| `mai2hook.dll` | segatools 的 maimai DX hook | segatools `games/mai2hook` |
| `mai2io.dll` | 自定义 maimai DX 按钮、触摸、LED IO 接口 | segatools `games/mai2io/mai2io.h` |
| `segatools.ini` | 加载路径、DNS、网络虚拟化、keychip、PCID、I/O、触摸、VFD、LED 配置 | segatools `dist/mai2/segatools.ini`、`doc/config/common.md` |
| `config_common.json` | AM Daemon 的通用设备/启动配置，通常由匹配版本的合法游戏包提供 | segatools `dist/mai2/launch.bat` 的参数列表 |
| `config_server.json` | 分发/服务器角色配置之一 | 同上 |
| `config_client.json` | 分发/服务器角色配置之一 | 同上 |
| `config_hook.json` | segatools 用于注入的 hook 配置；官方 maimai 示例只有 allnet auth 类型 | segatools `dist/mai2/config_hook.json` |
| `MelonLoader` | 运行 Harmony/AquaMai 的 Unity mod loader | AquaMai README；MelonLoader README |
| `AquaMai` | Sinmai 的 Harmony mod 套件 | MuNET-OSS/AquaMai |
| `Mercury` | segatools 中对应 WACCA 的 hook/IO，不是 maimai 启动器 | segatools `dist/mercury` |

## 3. Fragrance 教程逐项拆解

### 3.1 适用前提

- Windows x64。
- 自己合法拥有并有权运行对应的游戏基础包和可选增量包。
- 有足够的临时磁盘空间：原 `.app`、解密中间文件、VHD、`Package` 解包目录会同时占空间。
- `fsdecrypt` 需要读写权限；旧方法中的 ImDisk/Hyper-V 需要管理员或虚拟磁盘权限。
- 目标版本必须和 segatools、AquaMai、MelonLoader、服务器兼容。
- 路径尽量短、可写，避免空格和中文；`appdata` 需要持续可写。
- 原始教程不是脱壳、授权或线上服务接入说明。

### 3.2 章节一：APP → VHD

教程给出三种方法：

**方法一：fsdecrypt，教程推荐**

1. 把 `fsdecrypt` 放到可读写目录。
2. 对基础 `.app` 执行：

   ```powershell
   fsdecrypt <path/to/base.app>
   ```

3. 使用 7-Zip 打开生成的 `.vhd`。
4. 只复制其中的 `Package` 目录，作为游戏根目录的来源。

**方法二：unsegaREBORN**

1. 对 `.app`/`.opt` 执行：

   ```powershell
   unsegareborn <path/to/app-or-opt>
   ```

2. 只复制 `Package` 目录。
3. 教程警告该方法处理 `opt` 有旧 bug；在 2026 年应改为核对该项目当前 README 和 release，而不是照抄旧结论。

**方法三：旧 decrypt tools + ImDisk**

1. 将对应游戏 ID 的 key bin 放入工具目录。
2. 运行旧式 `fsdecrypt` 命令生成 `.vhd`。
3. 用 ImDisk 挂载，复制 `internal_0.vhd`。
4. 再用 7-Zip 或文件资源管理器打开 `internal_0.vhd`，复制 `Package`。

**增量包处理**

- 旧流程会把基础包产生的 `internal_0.vhd` 和增量包的 `internal_1.vhd` 放在同一目录。
- 用 `Set-VHD -ParentPath internal_0.vhd internal_1.vhd` 建立 differencing VHD 关系。
- 打开最上层 VHD，再复制 `Package`。
- 当前 `fsdecrypt v0.1.8+` README 已经写明会自动查找同目录 base 并合并 delta；`unsegaREBORN` 也支持 base + delta 堆叠。新流程通常不需要手工做 Hyper-V 父子 VHD，但必须确认工具版本和 delta 顺序。

### 3.3 章节二：VHD → EXE 环境

教程列出的依赖：

- 游戏 ICF 文件。
- VC++ Runtime 11.0 x64。
- 最新 VC++ x64 redistributable。
- segatools；教程示例为 `2025-11-04`。
- MelonLoader x64。
- AquaMai.dll。
- `odd` 文件。
- 示例 `segatools.ini`、`AquaMai.toml`、`launch.bat`。

环境中的关键步骤：

1. 解压 segatools 的 `mai2.zip`，将内容放到 `Package` 根目录。
2. 将 MelonLoader 和 `AquaMai.toml` 放到 `Package` 根目录。
3. 建立 `option`、`appdata`、`amfs`、`Mods`。
4. 将 `AquaMai.dll` 放入 `Mods`。
5. 将 ICF 文件命名为 `ICF1` 后放入 `amfs`。
6. 用示例替换 `segatools.ini` 和 `launch.bat`。
7. 教程要求把 `amdaemon.exe` 放入其提供的 Crackproof 解密流程，得到可注入的 `amdaemon.exe`。
8. 以管理员身份运行 `odd-loader.bat`。
9. 再运行 `launch.bat`。

这里必须加一个边界说明：

- `odd-loader.bat`、Crackproof 解密工具和对应 payload 不是 segatools 上游的一部分，许可证和完整性无法从公开源码确认。
- 如果某一步的实质是解除游戏防篡改/授权检查，本笔记不再展开具体命令或提供工具。应只处理自己有权处理的合法副本，并遵守服务器和当地法律。

## 4. 可直接落成教程的完整步骤

以下流程以 2026-09-18 的工具状态为准，并区分“上游稳定”与“教程旧流程”。

### 步骤 0：做合法性和版本清单

先记录：

```text
game_id:                  SDEZ 或 SDGB
game_data_version:       从 ConstParameter.NowGameVersion 读取，例如 25100
game_id_string:          从 ConstParameter.GameIDStr 读取
Sinmai.exe SHA-256:
amdaemon.exe SHA-256:
Assembly-CSharp.dll SHA-256:
AMDaemon.NET.dll SHA-256:
app/opt 原始文件名:
app/opt SHA-256:
segatools tag:
AquaMai tag:
MelonLoader version:
server host:
```

推荐的读取方式：

- 用 dnSpy/ILSpy 打开 `Assembly-CSharp.dll`，查找 `MAI2System.ConstParameter.NowGameVersion` 和 `GameIDStr`。
- 如果目标 AquaMai 构建能启动，检查其日志中 `GameInfo.GameVersion` / `GameInfo.GameId` 的间接输出，或在测试分支里临时打印这两个值。
- `NowGameVersion` 的数值格式可结合 AquaMai 源码判断：`25500` 对应 1.55，`26500` 对应 1.65。不要把社区简称 `SDGB151` 直接等同于某个补丁位，必须实测。

### 步骤 1：优先使用当前解包工具

当前更推荐 `beerpsi/fsdecrypt`：

- `v0.1.8` 已支持在纯 Rust 中直接提取 NTFS/APP 内容，并自动检测、合并 delta `.app`。
- `v0.1.9` 修复了 exFAT OPTION 容器中零字节文件导致失败的问题。
- README 明确说明 APPs 和 OPTION/DLC 都使用同一入口，`--no-extract` 才只是解密。

基础包：

```powershell
fsdecrypt <base.app>
```

增量包：

```powershell
fsdecrypt <update.app>
```

或者显式传入 base 和 update：

```powershell
fsdecrypt <base.app> <update.app>
```

Option：

```powershell
fsdecrypt <option.opt>
```

如果必须使用教程里的旧 VHD 方法：

- 只把最终 `Package` 复制到游戏目录；
- 增量包一定要以正确顺序叠加；
- 任何 `覆盖包` 都可能修改游戏二进制或数据，不能视为上游发布物；
- 建立自己的哈希清单，之后不要覆盖到无法回退。

### 步骤 2：建立最小游戏目录

建议结构：

```text
maimai/
  Package/
    Sinmai.exe
    amdaemon.exe
    Assembly-CSharp.dll
    AMDaemon.NET.dll
    config_common.json
    config_server.json
    config_client.json
    config_hook.json
    segatools.ini
    launch.bat
    amfs/
      ICF1
    option/
      Axxx/
    appdata/
    Mods/
      AquaMai.dll
      AquaMai.toml
    MelonLoader/
    UserData/
    version.dll
```

说明：

- `appdata` 指 SEGA 的 `Y:` 盘语义，不是 Windows 的 `%APPDATA%`。
- `amfs` 对应 `E:` 盘语义；segatools 注释明确说其中应有 ICF1 和 ICF2。
- `option` 指向包含 `Axxx` 子目录的目录。
- 不要把 `option` 写成文件；segatools 会检查它是否存在且是目录。
- 如果游戏版本不需要 option 数据，仍建议建立空 `option` 目录并配置路径，避免路径配置漂移。

### 步骤 3：安装 segatools

推荐版本策略：

| 目标 | 建议 |
| --- | --- |
| 只追求当前稳定、匹配最新 SDEZ | 上游 release `2026-04-06` |
| 完全复刻 Fragrance 教程 | `2025-11-04`，但要知道它不是最新 |
| 需要 maimai LED、触摸、VFD 新特性 | 至少 `2025-07-27`；优先 `2026-04-06` |
| SDGB 旧版 | 使用已验证的旧配置和 hook；不要因为“版本号更大”就盲目替换 |
| 需要 `allowAmfsDownloads`、`nextProcessFilePath` 等 develop 新项 | 必须自行从源码构建并回归测试；这些不是 `2026-04-06` release 的保证 |

操作：

1. 解压 segatools release。
2. 将 `dist/mai2` 下的内容复制到游戏根目录。
3. 保留 release 自带 `launch.bat`、`config_hook.json`、`segatools.ini` 作为基线。
4. 修改配置前先备份原文件。

### 步骤 4：安装 MelonLoader

AquaMai 当前 README 的安装方式是：

1. 下载 MelonLoader x64。
2. 将 MelonLoader 内容解压到 `Sinmai.exe` 所在目录。
3. 建立 `Mods`，把 AquaMai.dll 放入。
4. 启动游戏。

兼容原则：

- AquaMai 当前 README 固定链接 `MelonLoader 0.7.0`，但这不是对所有历史游戏版本都成立的版本声明。
- AquaMai 1.5.4 时代源码说明支持“旧版 MelonLoader”和 `0.6.4`。
- SDEZ 1.65/1.70 与 SDGB 1.51 的 Unity/Mono ABI 不同，不能仅凭 MelonLoader 能加载就认定 AquaMai 能工作。
- 如果同时让 segatools `[unity] targetAssembly` 和 MelonLoader 的 `version.dll` 注入，可能造成重复加载。一次只保留一种注入路径，先验证日志再叠加。

### 步骤 5：选择 AquaMai 构建

推荐按以下优先级：

1. **SDGB 稳定优先**：MuNET 公开版本配置里的 release `v1.5.4`，或者服务器/作者明确验证过的旧构建。
2. **SDGB 需要较新功能**：从 `v1.7.5` tag 源码建立测试构建。PR #99 的合并提交包含在 `v1.7.5`，并且 PR 明确写了 SDGB151 的测试记录。
3. **当前 SDEZ**：使用当前最新 tag/构建，但仍要匹配实际 game data 版本。
4. **不推荐**：把 `1.9.x` CI/slow 构建直接复制到 SDGB 后声称全功能可用；上游没有提供这种兼容矩阵。

另外：

- AquaMai 当前没有标准 GitHub Releases。tag 不等于有可下载二进制。
- `v1.8.0` 后出现 MuMod 自动更新器。需要用旧版时，应删除 MuMod 或禁止自动覆盖，至少不要使用 `fast`/`ci` 通道去替换已冻结的 DLL。
- 使用旧版 AquaMai 时，必须使用该版本随附的 `AquaMai.toml`。当前源码的配置迁移链已经到 2.6，旧版无法理解所有新栏目。

### 步骤 6：配置 `segatools.ini`

下面是结构性示例，不是可直接带到公网服务器的秘密配置：

```ini
[vfs]
amfs=D:\maimai\Package\amfs
option=D:\maimai\Package\option
appdata=D:\maimai\Package\appdata

[aime]
enable=1
aimePath=DEVICE\aime.txt
scan=0x0D

[vfd]
enable=1

[dns]
default=<server-host-or-ip>
replaceHost=0

[netenv]
enable=1
addrSuffix=11

[keychip]
id=<authorized-keychip-id>
gameId=SDEZ
platformId=ACA1
region=1
subnet=192.168.172.0

[pcbid]
serialNo=<authorized-ALLS-MAIN-ID-without-hyphen>

[system]
enable=1
freeplay=0
dipsw1=1

[led15070]
enable=1

[unity]
enable=1
targetAssembly=

[aimeio]
path=

[mai2io]
path=

[io4]
test=0x70
service=0x71
coin=0x72

[button]
enable=1

[touch]
p1Enable=1
p2Enable=1
```

字段解释：

- `vfs.amfs`: ICF1/ICF2 所在目录；缺失会导致启动失败。
- `vfs.option`: `Axxx` Option 目录；如果配置了但路径不存在，segatools 会报 fatal。
- `vfs.appdata`: 保存游戏运行数据；不是 Windows 用户目录。
- `dns.default`: 服务器域名或 IP。`127.0.0.1`、`localhost` 会被专门拒绝。
- `netenv`: 虚拟化 LAN 环境，IP 由 `keychip.subnet` 和 `addrSuffix` 推导，不需要把真实网卡 IP 填进游戏配置。
- `keychip.id`: 只能填合法授权给该机台/测试实例的 ID；不要使用公网泄露值。
- `keychip.gameId`: SDEZ 写 `SDEZ`，SDGB 的目标配置应写 `SDGB`；最终以目标服务器要求为准。
- `keychip.platformId`: `ACA1` 是 ALLS 平台默认形式；不要随意改平台类型。
- `keychip.region`: 文档明确：`1` 日本，`4` Export，`8` China。
- `pcbid.serialNo`: ALLS MAIN ID 去掉连字符，作为 Windows hostname 虚拟化值；LAN 内必须唯一。
- `system.dipsw1`: 单机通常为 `1`；同一 LAN 多机时只有一台设为 Server。
- `unity.enable`: segatools 的 Unity hook。如果使用 MelonLoader proxy，先确认是否与 `targetAssembly` 冲突。
- `led15070`: 对应 837-15070-04 灯板；旧灯板需要额外兼容选项或 AquaMai 模块。
- `touch`: 同名 section 同时承载两套概念：鼠标 WinTouch 的 `enable/remap/cursor`，以及 maimai 触摸串口模拟的 `p1Enable/p2Enable` 和 `p1DebugInput/p2DebugInput`。

务必保留 segatools 自带配置中的完整注释，不要把示例里的占位符直接用于线上服务。

### 步骤 7：检查 common/config 文件

上游 `launch.bat` 的调用形式是：

```bat
@echo off
pushd %~dp0

start "AM Daemon" /min inject -d -k mai2hook.dll amdaemon.exe -f -c config_common.json config_server.json config_client.json config_hook.json
inject -d -k mai2hook.dll sinmai -screen-fullscreen 0 -popupwindow -screen-width 2160 -screen-height 1920 -silent-crashes

taskkill /f /im amdaemon.exe > nul 2>&1
```

这说明：

- `config_common.json`、`config_server.json`、`config_client.json` 一起传给 AM Daemon。
- `config_server.json` / `config_client.json` 不是 segatools 配置；它们是游戏/服务端角色配置。
- 上游 `config_hook.json` 的示例内容极小，只有 anynet auth 类型：

  ```json
  {
    "allnet_auth": {
      "type": "1.0"
    }
  }
  ```

- `screen-width` / `screen-height` 是示例值，不是兼容性要求。应按实际显示布局修改。调试时 `-popupwindow` 便于查看异常；实机运行时不要盲目复制 2160×1920。
- 不要从网络上抓一段来路不明的 `config_common.json` 覆盖合法包中的文件。优先使用与游戏版本一致的原始文件。

### 步骤 8：配置 I/O、触摸、读卡器、VFD、LED

#### 按键和 IO4

- `[io4] test/service/coin` 是操作按钮。
- `[button] p1Btn1..p1Btn9`、`p2Btn1..p2Btn9` 映射 8 个环形按钮和 Select。
- 默认 1P 是 `WEDCXZAQ`，2P 是小键盘 `89632147`，Select 分别为 `3` 和 `*`。
- 使用自定义 IO 时，在 `[mai2io] path=` 填 DLL；路径解析顺序为 INI → `SEGATOOLS_MAI2IO_PATH` → `SEGATOOLS_IO_ROOT\mai2io.dll`。

#### 触摸

- `p1Enable=1` / `p2Enable=1` 打开 maimai 触摸串口模拟。
- `p1DebugInput` / `p2DebugInput` 控制键盘输入是否映射成触摸点。
- 触摸键名从 `p1TouchA1` 到 `p1TouchE8`，2P 对应 `p2TouchA1` 到 `p2TouchE8`。
- WinTouch 鼠标模拟使用 `[touch] enable/remap/cursor`，和上面的 maimai 串口触摸是不同层。
- 使用真实触摸屏时，关闭对应的 WinTouch 或调试键盘输入，避免双重输入。

#### 读卡器

- 内置读卡器模拟：`[aime] enable=1`、`aimePath=DEVICE\aime.txt`、`scan=0x0D`。
- `aimeGen` 控制文件不存在时是否生成随机 ID。
- 真实 SEGA 读卡器：关闭内置模拟，设置正确 COM port。
- 自定义读卡器：`[aimeio] path=` 或 `SEGATOOLS_AIMEIO_PATH`。
- 某些 e-money/Thinca 功能要求读卡器代际达到 3；不是所有模拟读卡器都支持。

#### VFD

- `[vfd] enable=1` 启用 VFD 模拟。
- `portNo=2` 是 maimai hook 使用的默认 VFD 端口。
- `utfConversion=1` 只影响日志/终端编码显示，不改变游戏逻辑。
- 2026-04-06 release 增加了 VFD 文本转发和状态回调，使用真实 VFD 或自定义 aimeio 时需要检查这一层。

#### LED

- `[led15070] enable=1` 对应 837-15070-04 灯板。
- 可设置 `portNo1`、`portNo2`、`boardNumber`、`fwVer`、`fwSum`。
- 旧 837-15070-02 灯板与新灯板行为不同；AquaMai 有单独的旧灯板支持模块，但必须和 segatools/hook 版本匹配。
- `mai2io` API 当前为 `0x0102`，支持按钮、触摸和 LED，包括 billboard/camera light；自定义 IO DLL 要声明自己的 API 版本并在初始化时返回正确值。

### 步骤 9：启动顺序

标准顺序：

1. 确认没有旧的 `amdaemon.exe` / `Sinmai.exe` 残留。
2. 先启动 AM Daemon，确认窗口出现并打印 VFS/DNS/keychip 等信息。
3. 再启动 `Sinmai.exe`。
4. 退出后确认 `amdaemon.exe` 被结束。

如果教程要求 `odd-loader.bat`：

- 它应在 AM Daemon 启动前运行，且只按教程指定来源使用。
- 运行后检查是否真的替换/准备了一个可启动的 `amdaemon.exe`。
- 不要把 `odd-loader` 当作通用启动器；它不是 segatools 上游命令。

### 步骤 10：验证清单

至少验证：

- AM Daemon 控制台没有 `Vfs: FATAL`。
- VFS 日志中的 `amfs`、`option`、`appdata` 指向预期目录。
- DNS 日志中的服务域名被重写到目标服务器。
- keychip 的 game ID、region、platform ID 与本机/服务器一致。
- 读卡器能读卡；键盘 scan 键按住时有响应。
- 按键、触摸、VFD、LED 都通过 Test Mode 或游戏内自检。
- `MelonLoader/Latest.log` 中有加载 AquaMai 的记录。
- AquaMai 若跳过补丁，能在日志中看到 `EnableGameVersion`/兼容性警告。
- 首局登录、游玩、保存、退出、再次登录均成功。
- 退出后没有残留进程。

## 5. SDEZ 日服配置

SDEZ 基线：

- 游戏 ID：`SDEZ`
- keychip region：日本用 `1`
- 默认 `mai2hook` 传入 `game_id="SDEZ"`、`platform_id="ACA1"`
- DNS：SEGA/All.Net 常见域名为 `*.sys-all.net`、`naominet.jp`、`ib.naominet.jp`、`aime.naominet.jp` 等
- `[netenv]` 通常保持开启，除非要处理特殊 LAN/head-to-head 场景
- 单机确认 `[system] dipsw1=1`；LAN 多机只有一台 Server

SDEZ 的 `segatools.ini` 核心段：

```ini
[vfs]
amfs=<...>\amfs
option=<...>\option
appdata=<...>\appdata

[dns]
default=<server-host-or-ip>

[keychip]
id=<authorized-keychip-id>
gameId=SDEZ
platformId=ACA1
region=1

[pcbid]
serialNo=<authorized-ACA-style-main-id-without-hyphen>

[system]
enable=1
dipsw1=1
```

日服注意点：

- 不要把 `region=8` 用于纯日服配置，除非服务器明确要求。
- SDEZ 版本可能高于 Evilleaker 2025 年快照中的 1.60；AquaMai 已包含 1.65/1.70 相关条件代码，实际版本以 `ConstParameter.NowGameVersion` 为准。
- 如果要使用最新 AquaMai，只应使用与游戏本体 `Assembly-CSharp.dll` 和 `AMDaemon.NET.dll` 匹配的构建。
- `config_common.json` 中的设备路径与 `segatools.ini` 的 VFS 路径要一致；不要同时维护两套互相冲突的配置。

## 6. SDGB 中国服配置

### 6.1 已确认的结构差异

segatools 的 DNS hook 同时注册了：

- SEGA/日本：`naominet.jp`
- ALL.Net：`*.sys-all.net`
- WAHLAP PowerOn：`at.sys-all.cn`、`at.sys-allnet.cn`
- WAHLAP AimeDB：`ai.sys-all.cn`、`ai.sys-allnet.cn`
- WAHLAP Billing：`bl.sys-all.cn`、`bl.sys-allnet.cn`

所以当前 segatools 二进制本身包含通往中国服域名族的重定向入口，但这也意味着：

- 只改 `[dns] default` 并不等于完成 SDGB 配置；
- 还要检查 `gameId`、`region`、游戏数据版本、服务器期待值和 config 文件；
- 旧 segatools 可能没有完整支持某些新的 WAHLAP URL 或端口行为。

### 6.2 推荐 SDGB 基线

```ini
[vfs]
amfs=<...>\amfs
option=<...>\option
appdata=<...>\appdata

[dns]
default=<sdgb-server-host-or-ip>

[netenv]
enable=1
addrSuffix=11

[keychip]
id=<authorized-keychip-id>
gameId=SDGB
platformId=ACA1
region=8
subnet=192.168.172.0

[pcbid]
serialNo=<authorized-unique-main-id-without-hyphen>

[system]
enable=1
freeplay=<按运营规则>
dipsw1=1
```

注意：

- `gameId=SDGB` 和 `region=8` 是最重要的中国服差异，但最终应以目标服务器配置为准。
- `mai2hook` 内部某些 VFS 路径仍使用 `SDEZ` 字符串作为内部目录名。不要因为看到了 `SDEZ` 就直接改成 `SDGB` 或重命名 `appdata` 目录；先对照原始 `Package` 和日志。
- `config_common.json`、`config_server.json`、`config_client.json` 的格式通常不因国服而完全不同，差别在网络、区域和服务器配置。不要从日服覆盖包直接覆盖国服包。

### 6.3 SDGB 的启动要点

1. 使用原始基础包和合法增量包，保留原始 `Package` 结构。
2. 选用能正确处理 `.app`/`.opt` 的当前解包工具，先验证 base 单独可解，再验证 delta 叠加。
3. 使用与目标旧版本兼容的 segatools 配置。至少 `2025-07-27` 后才有一套较完整的 maimai LED/触摸实现；但旧 SDGB 游戏版本并不要求盲目升级 hook。
4. 安装 AquaMai 时优先选择 `v1.5.4` 稳定线或从 `v1.7.5` tag 构建的测试线。
5. 如果使用当前 MuMod 包，确认 `Channel`、缓存和自动更新逻辑不会把旧版 DLL 覆盖掉。
6. 用 `GameInfo.GameId == "SDGB"`、`GameInfo.GameVersion` 的实际值确认构建确实识别到中国服。
7. 用 Test Mode 依次验证 I/O、触摸、读卡器、VFD、LED，再测试登录和保存。

### 6.4 SDGB 为什么通常停留在旧 AquaMai

这里要把“确认事实”和“合理推断”分开。

**确认事实**

1. AquaMai 公开源码用 `ConstParameter.NowGameVersion` 和 `GameIDStr` 判断运行环境。
2. `EnableGameVersionAttribute` 会在运行时按 min/max 门槛跳过类或方法。
3. 当前源码中大量模块最低要求为 `23000`，部分为 `23500`、`24000`、`25000`、`25500`、`26000`、`26500`、`27000`。
4. 2025-11-10 的 commit `3cfcab0` 专门加入 legacy version support，并用类级 version gate 避免旧版本加载新补丁。
5. PR #114 明确记录 1.55 以上 `MovieController._moviePlayers` 的类型变化；PR #126 明确提到 1.65；当前源码还有 1.70 阈值。说明新功能不是简单的 UI 选项，而是依赖不同游戏程序集结构。
6. AquaMai CI 从历史到现在都以 SDEZ 参考程序集构建，当前 `v1.7.5` workflow 也直接复制 `build-assets\SDEZ\* Libs`。没有看到 SDGB 构建矩阵。
7. `v1.7.5` 包含 PR #99；PR #99 正文明确写“测试于 SDGB151+EZ156+160”。
8. `v1.8.0` 的 Evergreen/MuMod 会在启动早期从网络读取版本配置，下载签名后的 AquaMai 并加载。
9. 本次观测的公开版本配置没有 SDGB 专属版本项，只有通用 release/slow/ci 构建。

**合理推断**

- 对 SDGB 最稳妥的历史线是 `v1.5.4` 官方稳定构建，或 `v1.7.5` 这一条包含 SDGB151 实测的 legacy 线。
- `1.8.x`/`1.9.x` 的新功能、协议和 MuMod 更新逻辑并不天然适配 SDGB 1.51。即使某些模块因版本门槛被跳过，当前 CI 二进制是否整体可启动，也没有官方全量保证。
- 因此“只能用老版本”更准确的说法是：**SDGB 需要一个经 SDGB 数据版本验证的构建，而不是只追版本号最高的 SDEZ 构建**。

**尚不确定**

- PR #99 的 SDGB151 测试是否覆盖全部 AquaMai 模块，还是只覆盖该 PR 新增的模块。公开 PR 没有给出完整回归矩阵。
- 2026 年 9 月的实际 SDGB 数据版本是否仍为 1.51.x。必须以目标游戏的 `ConstParameter` 实测。
- 某个 `1.9.x` 构建在关闭所有不兼容模块后能否稳定启动，缺少上游 SDGB CI 证据。
- 某些社区 fork 是否真的从上游同步，是否存在未公开改动，不能仅凭 README 判断。

### 7.2 `EnableGameVersion` 门槛表

这部分只说明“某模块会不会被显式跳过”，不代表跳过之外没有二进制兼容问题。

| 最低版本 | 代表模块/行为 | SDGB 1.51（25100） |
| --- | --- | --- |
| `23000` | 大多数新版补丁、Debug 保护、资源加载、部分 Unlock/UX 功能 | 可通过门槛，但仍需实测 |
| `23500` | SelectionDetail 等 | 可通过门槛 |
| `24000` | 若干 Unlock 子功能 | 可通过门槛 |
| `25000` | FixLevelDisplay、部分 KALEIDX/KaleiDX 逻辑 | 可通过门槛，但功能语义必须核对 |
| `25500` | DontRuinMyAccount、FixTrackNumDisplay、Hide1879、GrantFinalGateKey、CustomIntroCinematic、FixLongMusicRestart 等 | 会被跳过 |
| `26000` | FestaControl、部分 fade/Festa 逻辑 | 会被跳过 |
| `26500` | 新 packet 兼容、部分选曲排序字段、部分新 UI 子功能 | 会被跳过 |
| `27000` | 面向 1.70 的设置项/新字段 | 会被跳过 |

另外有几个反向边界，例如非 C 区 Touch Hold 修复只适用于 `23000..25699`，在 SDGB 1.51 上反而属于可用范围。

### 7.3 SDGB 上优先避免的“新功能”

以下不是“打开开关就能安全运行”的清单，而是适合作为兼容性怀疑点：

- 1.60 新增 UI、资源和字段相关功能。
- Festa 模式及其设置。
- 1.65/1.70 新增 packet、字段、排序和 fade 逻辑。
- KaleiDX 1.55+ 专有路径。
- `DontRuinMyAccount`、`FixTrackNumDisplay`、`Hide1879`、`GrantFinalGateKey` 等 `25500+` 模块。
- 自动下载/自动更新 MuMod；它会把已验证的冻结版本替换掉。
- 依赖新版 `MovieController` 布局的功能。
- 依赖新版本 `Assembly-CSharp.dll` 类型/方法但缺少版本门槛的社区补丁。

### 7.4 如何找到并核对一个兼容旧版

推荐流程：

1. **先找游戏版本，不先找 DLL**。读取 `ConstParameter.NowGameVersion` 和 `GameIDStr`。
2. 在 AquaMai tag 列表里找接近目标版本的 tag，优先查看 `v1.5.4`、`v1.7.5`。
3. 检查 tag 对应的 `GameInfo.cs`、`EnableGameVersionAttribute.cs`、`EnableConditionHelper.cs` 和 `build.ps1`。
4. 在目标 tag 中搜索 `[EnableGameVersion]`，建立启用/跳过清单。
5. 用目标游戏的 `Assembly-CSharp.dll` 和 `AMDaemon.NET.dll` 建立独立 `Libs` 目录后自行构建：

   ```powershell
   New-Item -ItemType Directory -Force Libs
   Copy-Item <合法游戏目录>\Assembly-CSharp.dll Libs\
   Copy-Item <合法游戏目录>\AMDaemon.NET.dll Libs\
   .\build.ps1
   ```

6. 对比构建前后的哈希，记录 `AquaMai.dll` 版本、配置版本、构建时间和 commit。
7. 在测试副本上启动，检查 `MelonLoader/Latest.log` 和 AquaMai 错误提示。
8. 逐项开启功能；一次只改变一个配置，避免无法判断是哪一个补丁导致崩溃。
9. 如果旧构建本身无法加载，停止堆叠新功能，先回到能启动的最小配置。

不要通过“最新 DLL + 旧游戏”的组合来猜兼容性。最可靠的验证是：**同数据版本的游戏程序集 + 对应 tag 的源码 + 该版本自己的配置模板 + 本地实测日志**。

## 8. Mercury 的明确说明

segatools upstream 中的 Mercury：

- `dist/mercury/segatools.ini` 注释明确写 `mercuryio` 是 “custom WACCA IO DLL”。
- `dist/mercury/launch.bat` 启动 `amdaemon.exe` 后注入 `../WindowsNoEditor/Mercury/Binaries/Win64/Mercury-Win64-Shipping.exe`。
- `games/mercuryhook` 与 `games/mercuryio` 是 WACCA 的 hook/IO。

所以：

- Mercury 不是 maimai 的第二个启动器。
- 不要把 `mercuryhook.dll` 配到 `sinmai.exe`。
- 不要把 `dist/mercury` 的配置拿来当 maimai 示例。
- 如果某教程把 Mercury 描述成 maimai 必需组件，先检查它是否混淆了 WACCA 和 maimai。

| DNS | `*.sys-all.net`、`naominet.jp` 等 | `*.sys-all.cn`、`*.sys-allnet.cn` 等 | segatools `dns.c` |
| keychip game ID | `SDEZ` | `SDGB` | `nusec` 可变配置 |
| 默认平台 | `ACA1` | 通常同为 ALLS `ACA1` | 目标服务器可覆盖 |
| 数据版本 | 更新快，可能到 1.65/1.70 线 | 通常停留在旧数据线 | 不得混用覆盖包 |
| AquaMai | 当前 tag/CI 主要面向最新 SDEZ | 旧稳定线或 SDGB 实测线 | 上游无 SDGB 构建矩阵 |
| MelonLoader | 以 AquaMai README/构建 tag 为准 | 可能需旧版 MelonLoader/Mono | 1.5.4 历史说明含 0.6.4 |
| 新功能 | 可随 SDEZ 版本增加 | 多个 25500+ 模块被跳过或不适用 | 以日志和实测为准 |
| Mercury | 无关 | 无关 | Mercury 是 WACCA |
| 合法包 | 自备合法 `.app`/`.opt`/ICF | 自备合法 `.app`/`.opt`/ICF | 不提供下载或密钥 |

## 10. 启动参数和常见配置关系

### 10.1 `launch.bat`

当前 upstream 的职责：

- 先启动 `amdaemon.exe`。
- 传入 4 个 JSON 配置。
- 再启动 `sinmai.exe`。
- 结束后杀掉 AM Daemon。

常见参数：

| 参数 | 用途 | 建议 |
| --- | --- | --- |
| `inject -d -k mai2hook.dll` | 注入 maimai hook | 保持和 segatools 版本一致 |
| `amdaemon.exe -f` | 前台/可见方式调试 daemon | 排障时保留 |
| `-c ...` | 指定 JSON 配置集 | 不要丢文件 |
| `sinmai -screen-fullscreen 0 -popupwindow` | 窗口化排障 | 仅排障/录屏时使用 |
| `-screen-width/-screen-height` | 屏幕分辨率 | 按实际显示器改 |
| `-silent-crashes` | 抑制崩溃窗口 | 调试时建议关闭，便于看错误 |

### 10.2 `config_common.json`

- 不是 segatools.ini 的替代品。
- 保存 AM Daemon 通用配置。
- 修改前保存原文件。
- 只使用与目标游戏版本匹配的配置模板。
- 出错时先比较原始文件哈希，再检查是否被覆盖包替换。

### 10.3 `config_server.json` / `config_client.json`

- 用于服务器/客户端角色。
- `[system] dipsw1` 与角色必须一致。
- LAN 多机时，只能有一台 Server。
- 单机不要同时模拟多台 Server。

### 10.4 `config_hook.json`

- 上游 maimai 示例只包含：

  ```json
  {
    "allnet_auth": {
      "type": "1.0"
    }
  }
  ```

- 不要往这个文件里放账号密码、keychip ID 或来源不明的证书。
- 需要更改认证/网络行为时，先看目标服务器的配置规范。

## 11. 常见问题排查树

### A. `amdaemon.exe` 立刻退出

1. 检查工作目录是否是 `Package` 根目录。
2. 检查 `config_common.json`、`config_server.json`、`config_client.json`、`config_hook.json` 是否都存在。
3. 检查 `segatools.ini` 的 `[vfs] amfs/appdata/option` 是否都存在。
4. 检查 `package/amdaemon.exe` 是否需要先按合法流程完成打包/完整性准备。
5. 检查 VC++ runtime 是否完整。
6. 检查是否错误地把 `mercuryhook.dll` 或 WACCA 配置用于 maimai。

### B. 黑屏，但 AM Daemon 存在

1. 看 AM Daemon 窗口是否有 VFS fatal。
2. 检查 ICF 是否命名为 `ICF1` 并位于 `amfs`。
3. 检查 `option` 是否指向目录而不是文件。
4. 检查游戏程序集和 AquaMai/MelonLoader 版本是否匹配。
5. 临时使用窗口模式和 `-silent-crashes` 关闭，获取崩溃堆栈。

### C. `amSysFileInitEx(). ErrCode -5`

- 这是早期 segatools 在没有真实 `E:` 盘时的已知问题，2024-02-27 release 已专门修复。
- 如果仍出现，说明使用了过旧 hook 或 VFS 未正确初始化。

### D. 网络/登录失败

1. 确认 `[dns] default` 不是 `127.0.0.1`、`localhost`。
2. 确认服务器域名/IP 可被主机解析和访问。
3. SDEZ 检查 `*.sys-all.net`、`naominet.jp`。
4. SDGB 检查 WAHLAP `*.sys-all.cn`、`*.sys-allnet.cn` 是否被 hook 到同一个目标。
5. 只有明确需要时才设置 `replaceHost=1`；它不是万能网络修复。
6. 检查 keychip game ID、region、PCID 是否与服务器一致。

### E. 多机 LAN/对战失败

1. 确认所有机台使用唯一 `pcbid.serialNo`。
2. 确认 `dipsw1` 只有一台 Server。
3. 了解 `[netenv]` 会虚拟化 LAN；文档说明它可能干扰 head-to-head。
4. 必要时按 segatools 文档使用 `redirectBroadcast` / `broadcast`；先记录实际网段。

### F. 读卡器没反应

1. `[aime] enable` 是否符合“模拟/真实读卡器”选择。
2. `aimePath` 是否可写；`aimeGen=1` 时才自动生成。
3. `scan` 键是否按住。
4. 自定义 `aimeio.dll` 是否存在、位数是否正确、API 是否匹配。
5. e-money 功能需要读卡器代际和额外数据，不是普通 Aime 模拟就足够。

### G. 触摸错位/双触

1. 明确是 WinTouch 鼠标模拟还是 maimai 串口触摸。
2. 检查 `p1Enable`/`p2Enable` 以及 `p1DebugInput`/`p2DebugInput`。
3. 检查 `p1TouchA1..E8` / `p2TouchA1..E8`。
4. 检查自定义 `mai2io.dll` 是否同时上报触摸。
5. 窗口移动后错位时再测试 `remap`；不要在不理解坐标系时乱开。

### H. 按键错误

1. 检查 `[io4] test/service/coin`。
2. 检查 `[button] p1Btn1..9`、`p2Btn1..9`。
3. 确认虚拟键码是十进制或 `0x` 十六进制。
4. 自定义 IO 与内置 IO 不要同时启用以致重复输入。

### I. VFD 无输出

1. 确认 `[vfd] enable=1`。
2. 真实 VFD 检查 `portNo` 和串口占用。
3. 终端乱码先试 `utfConversion=1`。
4. 自定义 aimeio 要提供 VFD 状态/文本回调。

### J. LED 不亮或旧框报错

1. 检查 `[led15070] enable=1`。
2. 检查 `portNo1`/`portNo2`、`boardNumber`、固件版本/校验。
3. 旧 837-15070-02 灯板不要冒充新板；使用对应的旧灯板兼容模块。
4. 确认 `mai2io` API 版本至少支持请求的 LED 功能。

### K. AquaMai 未加载

1. 检查 `Mods/AquaMai.dll` 是否在 `Sinmai.exe` 同级目录。
2. 检查 MelonLoader 日志。
3. 检查 `AquaMai.toml` 是否与 DLL/AquaMai 版本匹配。
4. 检查是否漏了 MelonLoader 的 `version.dll`/依赖。
5. 如果日志显示模块被 `EnableGameVersion` 跳过，这不是加载失败，而是预期剔除。
6. 如果启用新模块后崩溃，回退到旧稳定线或关闭所有 1.55+ 功能再测试。

### L. 旧版 AquaMai 被自动更新覆盖

1. 找出 MuMod `Channel`、`CachePath`。
2. 当前 `slow`/`ci` 都可能拉到比 `v1.5.4` 更新的构建；不要让自动更新器管理 SDGB 旧版。
3. 冻结旧 DLL 时应同时记录哈希，并在每次启动前校验。
4. 不要只替换配置而不替换 DLL，否则配置版本会不匹配。

## 14. 推荐的最终目录和启动顺序

如果目标是“先让 SDGB 稳定启动，再逐个加功能”，推荐：

```text
1. 合法原始 .app / .opt
2. 当前 fsdecrypt 解包并核对 delta 后的 Package
3. 备份 Package
4. 放入旧版 AquaMai 和匹配的 MelonLoader
5. 用 segatools 的 mai2 示例作为唯一配置基线
6. 配置 VFS / DNS / region / gameId / PCID
7. 先不开自定义 IO、LED、MuMod、进阶 AquaMai 模块
8. 启动 AM Daemon，确认 VFS/DNS/keychip
9. 启动 Sinmai，确认登录/读卡/触摸/按键
10. 逐项打开 AquaMai 功能
11. 记录每个版本、哈希和日志
12. 只把已验证的组合留作生产副本
```

不要做：

```text
最新 SDEZ AquaMai + SDGB 1.51
最新 MelonLoader + 未验证旧 AquaMai
自动更新器 + 冻结旧版
日服覆盖包 + 国服数据
来源不明 keychip/PCB/服务器凭据
伪造成绩上传
```

## 15. 待现场确认的开放问题

以下问题不能让二手教程替你回答：

1. 目标 SDGB 的 `ConstParameter.NowGameVersion` 精确值。
2. 目标 SDGB 的 `GameIDStr` 是否严格为 `SDGB`。
3. 目标服务器是否要求 `[keychip] gameId=SDGB`、`region=8`，以及是否接受其他 platform ID。
4. 目标包是完整 `.app` 还是 base+delta，`.opt` 是否必须。
5. 目标 SDGB 使用的 MelonLoader/Mono 版本，以及 AquaMai `v1.5.4`/`v1.7.5` 哪一个实际能加载。
6. SDGB 1.51 是否支持目标服务器要求的所有登录、卡片、保存和网络协议。
7. 目标网络能否访问服务器；是否需要 `replaceHost`。
8. 旧灯板/触摸/读卡器是否需要自定义 `mai2io.dll` 或 `aimeio.dll`。
9. 当前官网/服务端的版本是否已经超出 `SDGB151`，以及对应数据是否变化。

只要这些问题没有现场验证，就不应把“能用”写成全功能兼容。
